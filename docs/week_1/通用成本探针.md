# 通用成本探针 —— 把 Day-0 那一刀,变成能砍任意路径的刀

> Week 1 交付物 ②　|　脚本:[cost_probe.py](../../cost_probe.py)　|　Day-0 原版保留在 [li_fi_cost_probe.py](../../li_fi_cost_probe.py)

Day-0 的探针只能回答一个问题:**ARB→BAS 的 USDC 要多大价差才回本?**(答案:25 bps)
这一版要回答的是:**任意路径要多大价差才回本?**

从"一条路"到"任意路径",中间隔着四个必须想清楚的坑。这篇笔记就是这四个坑。

---

## 坑 1:decimals 写死 = 只能跑稳定币

Day-0 里有一行 `DECIMALS = 6`。

USDC 是 6 位,WETH 是 18 位。这行常量意味着你一旦换成 WETH,所有金额会错 **10¹²倍**,而脚本不会报错 —— 它会心平气和地打印出一个完全离谱的 bps。

**没有报错的错误,比报错的错误危险得多。**

解法:用 `/token` 端点查。

```
GET https://li.quest/v1/token?chain=ARB&token=USDC
→ {"address":"0xaf88...","symbol":"USDC","decimals":6,"priceUSD":"1.0001705156"}
```

目标资产的 decimals 更省事 —— `/quote` 的响应里 `action.toToken.decimals` 直接就有,不用额外请求。

> **通用规则**:凡是"依赖资产属性"的常量,都不该写死。写死的那一刻,脚本就退回成一次性的。

---

## 坑 2:`feeCosts` 里的 `included` 字段 —— 重复计算陷阱

跑 `/quote`,费用长这样:

```json
"feeCosts": [
  {"name": "LIFI Fixed Fee",      "amountUSD": "25.0043", "included": true},
  {"name": "LayerZero native fee","amountUSD": "0.0659",  "included": false}
]
```

这个 `included` 是整个 API 里最容易踩的字段:

| `included` | 含义 | 该怎么算 |
|---|---|---|
| `true` | 已经从 `toAmount` 里扣掉了 | **不能再加**,加了就是重复计算 |
| `false` | 你要另外掏钱(通常用原生币付) | **必须加**,不加就是漏算 |

那笔 `LIFI Fixed Fee` 是 25 美元。如果你把 `feeCosts` 无脑求和加到成本上,你会在一笔 10000 USDC 的交易上**凭空多算 25 bps** —— 正好把真实门槛翻一倍。

gas 同理:gas 用原生币 ETH 付,**从来不在 `toAmount` 里**,永远要另外加。

---

## 坑 3(核心):跨资产路径,token 口径根本无法定义

铁律 1 说"同种资产转移用 token 数量算"。Day-0 能这么干,是因为两头都是 USDC:

```
成本 = 发出 10000 USDC − 到手 9975 USDC = 25 USDC = 25 bps   ← 零价格假设
```

但换成 `USDC → WETH`,这个减法**没有意义**:10000 USDC 减 5.34 WETH 等于什么?

这时候大多数人会滑回美元口径:`fromAmountUSD - toAmountUSD`。**这正是 Day-0 已经证伪过的陷阱。** 用实测数据说话:

```
fromAmountUSD  1000.1705      ← ARB 上的 USDC 标价 1.0001705
toAmountUSD    1001.4184      ← BAS 上的 USDC 标价更高
→ 美元口径结论:"赚了 12 bps!"
→ token 口径事实:1000 USDC 发出,997.5 USDC 到手,亏 25 bps
```

**连正负号都反。** 因为两条链上同一个 USDC 的标价有细微差异,这点差异被规模放大后,直接吃掉了整个 25 bps 的桥费。

### 解法:往返闭环(roundtrip)

既然"起点和终点是同种资产"才能做减法,那就**让它变成同种资产** —— 把路径闭合回起点:

```
10000 USDC (ARB) ──→ 5.34 WETH (BAS) ──→ 9957.78 USDC (ARB)
                                          └─ 和起点同种资产,可以直接相减!

闭环成本 = 10000 − 9957.78 = 42.22 USDC = 42.2 bps   ← 依然零价格假设
```

这就是**铁律 1 在任意资产对上的推广**:单程做不到零假设,闭环可以。

而且这在套利上是天然合理的 —— **套利本来就是环**。三角套利是环,跨链搬砖回本是环,清算(借币→清算→卖抵押物→还币)也是环。闭环成本就是这个环本身的摩擦,毛价差必须先跨过它。

脚本里的对应实现:去程 `/quote` 拿到 `toAmount`,把这个数**原样**作为回程的 `fromAmount` 再报一次价。

---

## 坑 4:诚实分账 —— 哪部分零假设,哪部分是估算

闭环解决了被搬运资产的口径问题,但 **gas 仍然是另一种资产**(原生 ETH)。要把 gas 折进 USDC 口径,只能用价格 —— 无法避免。

那就**别假装它零假设**。脚本把成本分成两栏,永远不合并:

```
· 硬成本 25.00 bps —— 同种资产数量相减,零价格假设,可信。
· 账外  0.02 bps —— gas/未含费用原生币付,折算用了标价,是估算。
```

对稳定币,`priceUSD ≈ 1`,折算几乎无损。对波动资产,这就是个估计值。分开列,你才知道**自己的结论有多硬**。

> 这条思路可以直接搬到 Sonic 清算上:清算奖励是 token 口径的硬事实,抵押物变现滑点也是硬事实(卖出前后同种资产相减),但抢跑竞争的 gas 成本是另一种资产 —— 同样要分栏记。

---

## 用法

```bash
# 单程同资产 —— 经典稳定币搬砖,扫多个规模
python3 cost_probe.py --from-chain ARB --to-chain BAS --token USDC \
    --amounts 100,1000,10000,100000

# 跨资产 —— 脚本会拒绝给门槛,并提示你上 roundtrip
python3 cost_probe.py --from-chain ARB --to-chain BAS \
    --from-token USDC --to-token WETH --amounts 10000

# 往返闭环 —— 跨资产路径唯一诚实的算法
python3 cost_probe.py --from-chain ARB --to-chain BAS \
    --from-token USDC --to-token WETH --amounts 1000,10000,100000 --roundtrip

# 同链 DEX / 三角(from-chain == to-chain)
python3 cost_probe.py --from-chain ARB --to-chain ARB \
    --from-token USDC --to-token WETH --amounts 10000 --roundtrip

# 导出成第 4 节《证据记录表》,Week 2 接着填
python3 cost_probe.py --from-chain ARB --to-chain BAS --token USDC \
    --amounts 1000,10000 --csv evidence.csv
```

## 实测结论(2026-08-01)

### ① ARB→BAS USDC 单程 —— Day-0 结论复现并加固

```
       规模          到手      硬成本   账外bps   真实门槛    耗时  路径
     100.00      99.7500     25.00     2.33     27.33      7   eco
   1,000.00     997.5000     25.00     0.23     25.23      7   eco
  10,000.00   9,975.0000     25.00     0.02     25.02      7   eco
 100,000.00  99,750.0000     25.00     0.00     25.00  1,080   polymerStandard
```

- 25 bps 是**纯比例费**,规模再大也降不下去 —— 这是门槛的**地板**。
- gas 只在 ~100 USDC 以下才咬人(93 USDC 以上就摊薄到可忽略)。
- **10 万规模时路由从 `eco` 换成 `polymerStandard`,耗时从 7 秒暴涨到 1080 秒。** 门槛数字没变,但延迟风险涨了 150 倍 —— 18 分钟里价差还在不在,是另一个问题。**成本没变不等于风险没变。**

### ② ARB.USDC ⇄ BAS.WETH 往返闭环 —— 深度是真正的杀手

```
       规模          回到      硬成本   账外bps   真实门槛    耗时  路径
   1,000.00     997.1912     28.09     1.33     29.41     26   stargateV2 → across
  10,000.00   9,964.0622     35.94     0.18     36.11     26   stargateV2 → across
 100,000.00  98,466.7829    153.32     0.02    153.34  1,859   stargateV2 → near
```

门槛**随规模上升**,和稳定币完全相反的形态。脚本把这两种形态分开命名:

- **摊薄型**:门槛随规模下降,固定成本(gas)被摊薄 → 规模越大越划算,直到撞上比例费地板。
- **冲击型**:门槛随规模上升,深度不够,滑点和路由降级越吃越狠 → **最优规模在小端**。

> 🔴 **2026-08-05 重要更正 —— 上面这张表只是 3 个采样点,不代表这条路的常态。**
>
> 当时我据此说「跨资产门槛 ~29–43 bps」。连续监控 48.5 小时、**98 次观测**之后:
>
> ```
> 规模 1,000    中位 60.45 bps   区间 [51.90, 73.31]   标准差 2.94
> 规模 10,000   中位 60.84 bps   区间 [44.89, 70.52]   标准差 3.54
> ```
>
> **真实中位数是 60 bps,不是 29–43。** 上表那个 29.41 是真实测量,但它落在分布的**极低端**,
> 拿它当代表值就把门槛低估了一半。
>
> 表里的原始数字保留不动 —— 它们是当时真实的观测,删掉就是篡改证据。
> 错的不是测量,是**从 3 个点推出"这条路是 30 bps 量级"这个概括**。
>
> 这条教训和下面那条(负固定成本)是同一类:**数据不够时,错的往往不是数字,是你从数字里读出的那句话。**

> ⚠️ 这里我第一版写错了:用最小/最大两点做线性拟合去拆"固定成本 + 比例成本",在冲击型上解出了 **−12.5 USDC 的固定成本**。负的固定成本没有物理意义 —— 它是在告诉你**模型选错了**:成本对规模是凸的,直线拟合会把截距压到负数。
> 现在脚本会检测这个信号(拟合出负固定成本 或 门槛随规模上升),自动切换成冲击型解释,不再输出那个假的"地板"。
> **教训:一个数字算出来没有物理意义时,别去调参数,要去质疑模型。**

### ③ 数据本身也会骗你

跨资产路径上,脚本报出:

```
⚠ 数据异常: toAmountMin(5.372858) > toAmount(5.345994),该路径的保底值不可信
```

`toAmountMin` 是**最坏情况保底**,理论上永远 ≤ `toAmount`。stargateV2 的报价违反了这个不变量。

如果你拿它算"滑点缓冲 = toAmount − toAmountMin",会得到**负的滑点缓冲**,并且悄无声息地混进结论里。所以脚本对每条腿都做不变量检查。

> **新铁律候选:对上游数据做不变量检查。** API 返回 200 不代表数据自洽。你有安全背景 —— 这就是把"输入永远不可信"的习惯用在数据管道上。

---

## 沉淀下来的三条

1. **零假设的部分和有假设的部分,永远分开记。** 混在一起的那一刻,你就不知道自己的结论有多硬。
2. **套利是环,所以成本也该按环算。** 单程跨资产没有诚实的 token 口径,闭环有。
3. **算出没有物理意义的数字时,质疑模型,不要质疑参数。** 负的固定成本、负的滑点缓冲,都是模型或数据在报警。
