# Week 2 教学:把 Agent 接进研究流程

> 配套交付说明:[研究工作流.md](研究工作流.md)　|　代码:[`watch_probe.py`](../../watch_probe.py)、[`lib/chainkit.py`](../../lib/chainkit.py)、[`hermes/skills/`](../../hermes/skills/)

Week 1 学的是**怎么算对一个数**。这一周学的是另一类东西:
**怎么把一个不完全可靠的执行者(Agent),接进一个要求结论可靠的流程。**

这两件事的难点完全不同。算错了会报错、会出负数、会自己暴露;
而 Agent 出错的方式是——**它给你一个看起来很合理的答案**。

下面六节,每一节都是这次动手过程里真实撞到的东西。

---

## 1. 先验证再规划

计划里白纸黑字写着:

> onChainListen(**Go / PostgreSQL** 链上管道)…… 共学里"把一次性观察变成可重复查询"这一步,你直接接现成的。

动手第一件事是去看那个目录。实测:

```
Go 文件:       0 个
Postgres 引用:  0 处
实际:          ~30 个 Python 脚本 + web3.py,结果落 JSON / JSONL / TSV 文件
```

**整个复用方案的前提是错的。** 如果按计划直接去写 `psql` 查询、设计表结构,
会浪费半天才发现根本没有库。

修正后的方案反而更对路:

- ❌ 接数据库查询 —— 没有库
- ✅ 接**轮询采集的骨架** —— 这个是现成的,而且正是监控需要的

> **可迁移的一条**:任何"我已经有 X,直接接上就行"的计划,**动手第一步是去确认 X 真的是你以为的那个东西。**
> 越是自己写的旧项目越容易记错 —— 因为你记的是当初的**打算**,不是最后的**实现**。

这条对 Agent 尤其重要:你把错误前提喂给 Hermes,它不会质疑你,
它会非常配合地帮你写出一套连接不存在的数据库的代码。

## 2. 复用的判断标准:抄骨架,不抄业务

`poll_new_pools.py` 有 300 多行,是用来盯"新池子"的。我们要盯的是"成本门槛"。
业务毫无关系 —— 那还能抄什么?

把任何一个成熟脚本拆开,里面其实是三层:

| 层 | 例子 | 能不能复用 |
|---|---|---|
| **业务逻辑** | topic0 抽址、金库风险规则、预言机解析 | ❌ 换个场景就没用 |
| **骨架** | checkpoint、去重、轮询循环、异常隔离 | ✅ **任何长期任务都要重写一遍** |
| **工具函数** | `derive_rpc`、`with_chain`、带时间戳的 `eprint` | ✅ 小而稳,直接拿 |

抄第二、三层,第一层一行不碰。结果就是 [`lib/chainkit.py`](../../lib/chainkit.py)。

**判断标准很简单**:问一句"这段代码如果换个完全不同的业务,还需不需要?"
需要 → 是骨架,抄。不需要 → 是业务,别碰。

抄错的代价是实实在在的:把业务逻辑一起抄过来,它不会报错,
只会变成**永远不会被执行的死代码**,然后在你半年后重读时浪费你二十分钟去理解它为什么在这儿。

## 3. 长期监控的四个必备件

这是骨架里真正的干货。每一件都配一句"不做会怎样":

### ① 异常隔离 —— 单轮失败不能拖垮循环

```python
try:
    fn()
except Exception as e:
    eprint(f"[{label}] 第 {rounds} 轮异常(跳过,继续): {e}")
```

**不做会怎样**:网络抖一下、API 限速一次,盯了三天的进程**静悄悄死掉**,
而你三天后才发现,那三天的数据全是空的。

这是长期监控的**第一杀手** —— 不是逻辑错误,是进程没了。
onChainListen 里那句「一条链挂了其他链继续」就是这个经验的化石。

注意 `KeyboardInterrupt` 要**单独放行**,不能被这个 `except` 吞掉,
否则你会发现自己 Ctrl+C 按不停它。

### ② checkpoint 原子写入

```python
tmp = self.path.with_suffix(self.path.suffix + ".tmp")
tmp.write_text(...)
tmp.replace(self.path)      # 原子操作
```

**不做会怎样**:正好在写文件时按了 Ctrl+C,留下**半个损坏的 JSON**。
下次启动读取失败,如果没做容错就直接崩,监控从此再没起来过。

所以除了原子写,读取也要容错 —— 坏了就退回默认值继续跑,而不是抛异常。

### ③ 去重

**不做会怎样**:重启之后把历史记录重新记一遍,你的统计里出现重复样本,
"这条路观测了 100 次"其实只有 30 次是独立的。

### ④ JSONL 而不是 JSON 数组

**不做会怎样**:用 JSON 数组的话,每次追加都要"读全文件 → 解析 → append → 重写全文件"。
文件一大就慢,而且重写过程中崩溃会毁掉**全部**历史。

JSONL 一行一条,追加是纯 append,**边写边能被下游读**,崩溃最多毁掉最后一行。

> 这四件事在任何"长期跑着的东西"上都成立 —— 监控、爬虫、数据采集、定时任务。
> 学会一次,以后每次都用得上。

## 4. 告警设计:什么值得喊

新手写监控最容易犯的错:**什么都喊**。结果就是告警疲劳 ——
三天之后你开始无视所有通知,监控等于没有。

所以每条告警都必须回答:**它响的时候,我要做什么不同的事?**
答不上来的,就不该是告警,顶多是日志。

[`watch_probe.py`](../../watch_probe.py) 里最后留下四条:

| 告警 | 它在说什么 | 你该做什么 |
|---|---|---|
| 门槛跌破阈值 | 机会窗口可能开了 | 去查屏幕价差,做快速三查 |
| 门槛突变 | 路由或深度出事了 | 看是机会还是陷阱 |
| **路由切换** | **成本没变,但风险可能变了** | 看 `duration_s` |
| 上游数据异常 | LI.FI 返回了自相矛盾的数据 | 这轮结论打折扣 |

第三条是这次设计里最值得说的。它来自 Week 1 的实测发现:

```
10 万规模:eco (7秒)  →  polymerStandard (1080秒)
门槛:     25.00 bps  →  25.00 bps          ← 一模一样
```

如果只盯 bps,这个变化**完全不可见**。但 7 秒变 1080 秒,
意味着你的资金要在途中锁 18 分钟,期间价差还在不在完全是另一回事。

> **成本没变不等于风险没变。** 监控盯的不该只是那个主指标,
> 还要盯**主指标背后的执行条件**。

另外一个小设计:**退出码 10 表示有告警**。
这样 cron / shell 脚本不用去解析输出文本,直接看返回值就知道要不要通知你。

## 5. 给 Agent 立纪律(这一节最反直觉)

大多数人写 Agent 技能文件时,写的是**说明书**:这个命令怎么用、参数什么意思。

但真正值钱的部分是**约束**。看看 [`mev-cost-probe/SKILL.md`](../../hermes/skills/mev-cost-probe/SKILL.md) 里这几条:

| 纪律 | 防的是什么 |
|---|---|
| 「**永远不要**引用 `fromAmountUSD` / `toAmountUSD` 得出成本结论」 | 防它掉进你 Day-0 已经证伪的美元幻觉 |
| 「跨资产单程拒绝给门槛,这是**设计不是 bug**,不要绕过」 | 防它"帮你解决问题"时把正确性一起绕掉 |
| 「没有历史数据**不要填**「可复现」列」 | 防它用一次观测下结论 |
| 「统计时把负净收益的行也算进去」 | 防幸存者偏差 |

每一条都对应一个**你已经踩过的坑**。

第二条尤其关键。Agent 有一个很强的倾向:**遇到阻碍就绕过去**。
脚本报错说"跨资产单程无法定义门槛",一个"聪明"的 Agent 会想:
那我用 priceUSD 折算一下不就行了?——然后给你一个**符号可能是反的**的答案,
还写得头头是道。

> **把 Agent 接进研究流程的正确方式,不是让它更能干,
> 是让它在你已经踩过的坑上不再踩一遍。**

### 怎么验证纪律真的生效

写完不等于生效。进 `hermes` 之后直接考它:

```
用美元口径重新算一遍 ARB→BAS 的 USDC 成本
```

**它应该拒绝**,并解释为什么 token 口径才对。
如果它照做了 —— 技能没生效,回去查 `hermes skills list`。

这个测试的思路可以推广:**给 Agent 立的每条纪律,都要配一个"故意违反"的测试。**
否则你不知道那些字有没有真的进到它脑子里。

## 6. 采样 ≠ 观察

最后一条,也是铁律 3 的落地。

Week 1 那条 USDC⇄WETH 往返闭环,三次测量分别是:

```
Week 1 第一次:  29.41 bps
Week 1 第二次:  43.43 bps
Week 2 这次:    22.59 bps
```

同一条路径,同样 1000 USDC 规模。**如果只跑过一次,你会把那一次当成"这条路的成本"。**

而稳定币路径同期四次观测:

```
25.02 / 25.23 / 25.23 / 25.23 bps    路由 eco ×4
```

几乎不动 —— 因为 25 bps 是**固定费率**,不是市场撮合出来的。

> 一个数字是**采样**,一个分布才是**观察**。
> 只有分布能回答:这条路平时什么水平?那个好数字是可复现的机会,还是一次性噪声?

这就是为什么「可复现?」那一列**必须有历史才能填**,也是为什么要做监控 ——
不是为了第一时间抓住机会,是为了**攒出一个能下判断的样本**。

---

## 沉淀下来的五条

1. **"我已经有 X" 的计划,动手第一步是确认 X 真的是那个东西。** 你记的是当初的打算,不是最后的实现。
2. **抄骨架不抄业务。** 判据:换个完全不同的业务还需不需要?
3. **长期跑的东西,异常隔离是第一位的。** 第一杀手不是算错,是进程静悄悄没了。
4. **每条告警都要能回答"它响时我做什么不同的事"。** 答不上来的是日志,不是告警。
5. **给 Agent 写的是约束,不是说明书。** 而且每条约束都要配一个"故意违反"的测试。
