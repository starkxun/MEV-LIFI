# LI.FI 跨链可执行价差实测:数据分析教学

> 参考文件:[`LI.FI 跨链可执行价差实测.pdf`](../../LI.FI%20跨链可执行价差实测.pdf)  
> 本项目数据:[`watch/*.jsonl`](../../watch/) / [`price_history.csv`](../../price_history.csv) / [`evidence.csv`](../../evidence.csv)  
> 目标读者:刚开始做链上套利数据分析的新手

## 先给结论

这份 PDF 最值得学的不是某个具体资产有没有机会,而是它的数据分析方法。

它做了四件关键的事:

```text
1. 不只看屏幕价格,而是尽量用可执行报价算 edge。
2. 同一批数据按不同口径重算,看结论是否稳定。
3. 发现异常好看的机会后,先做自洽性诊断,找污染源。
4. 最后把结论写成"适用范围 + 局限",不把报价当成交。
```

套到本项目这次数据,结论是:

```text
ARB→BAS USDC→USDC:
  成本约 25 bps,屏幕价差最高不到 10 bps。
  结论:可复现地不成立。

ARB→BAS USDC→WETH 往返:
  成本约 60 bps,72 小时历史最大可成交中间价差只有 +26.49 bps。
  结论:可复现地不成立。
```

这不是"没找到机会所以没收获"。

真正的收获是:

> 我们知道了这两条路径为什么不成立,并且知道这个判断来自哪些数据、哪些公式、哪些局限。

## 1. PDF 在测什么

PDF 测的是 LI.FI 跨链路径里的"可执行价差"。

它不是只问:

```text
两个地方标价差多少?
```

而是问:

```text
如果我真的通过 LI.FI 报价买一腿、卖一腿,扣掉双边报价内含成本后,还剩多少?
```

PDF 里的核心公式可以理解成:

```text
edge = 卖价 / 买价 - 1
edge_bps = edge * 10000
```

如果:

```text
edge_bps > 0
```

表示双边报价扣完后还有正空间。

如果:

```text
edge_bps < 0
```

表示交易还没算 gas 就已经亏。

PDF 本轮采样规模:

| 指标 | 数值 |
|---|---:|
| 采样轮次 | 120 |
| 报价条数 | 2880 |
| 可用机会 | 0 |
| 组内时间跨度 | 9-31 ms |
| 隔离报价 | 546 条 |

新手要注意这里的"组内时间跨度"。

跨市场价差很容易变化。如果买腿和卖腿不是同时取,价差可能已经变了。

所以 PDF 里强调:

```text
一轮内全部腿并发发出,组内跨度 9-31 ms。
```

这是一条很重要的数据质量要求。

## 2. 同一批数据为什么要分多个口径

PDF 最有价值的一点是:它没有只跑一个结论。

它把同一批数据拆成三个口径。

### 口径一:默认费率

默认 integrator 费率下,双边大约有 50 bps 的费率压力。

结果:

| 资产 | min bps | 中位 bps | max bps | 正收益 |
|---|---:|---:|---:|---:|
| WETH | -57.2 | -51.1 | -42.7 | 0/120 |
| wstETH | -57.6 | -51.6 | -45.0 | 0/120 |
| USDT | -50.0 | -43.5 | -40.6 | 0/120 |
| LINK | -131.0 | -97.3 | -42.0 | 0/120 |

这个口径下,全部为负。

### 口径二:零费率

然后 PDF 把费率谈到 0 的情况拿出来看。

注意这不是简单常量假设,而是逐腿从报价里的 `feeCosts` 读取真实费用再扣回。

结果:

| 资产 | min bps | 中位 bps | max bps | 正收益 | >= +10 bps |
|---|---:|---:|---:|---:|---:|
| WETH | -7.3 | -1.2 | +7.2 | 33/120 | 0 |
| wstETH | -7.7 | -1.7 | +4.9 | 25/120 | 0 |
| USDT | -0.1 | +6.4 | +9.4 | 109/120 | 0 |
| LINK | -81.4 | -47.6 | +8.0 | 1/120 | 0 |

这个口径比默认费率好很多,但依然没有任何资产达到 `+10 bps`。

也就是说:

```text
即使费率为零,可执行价差也不足以构成稳定机会。
```

### 口径三:含污染报价

如果不剔除污染报价,报告会看起来很漂亮:

| 资产 | 中位 bps | 正收益 | >= +10 bps |
|---|---:|---:|---:|
| WETH | +32.5 | 118/120 | 118 |
| wstETH | +28.1 | 99/120 | 80 |
| USDT | +20.5 | 120/120 | 83 |
| LINK | +0.1 | 60/120 | 18 |

如果只看到这张表,新手很容易写:

```text
WETH 跨链套利机会明显存在。
```

但 PDF 最重要的地方就在这里:

> 好看的数字先不要信,先检查它是不是自洽。

## 3. PDF 是怎么证伪假信号的

PDF 用了一个很简单但很有效的检查:

```text
同一条链上买入后立刻卖出。
```

这件事理论上应该亏。

因为你要付:

```text
买入 DEX 成本
卖出 DEX 成本
滑点
报价误差
```

所以同链买卖往返如果出现稳定正收益,那不是套利,而是报价系统自相矛盾。

PDF 的诊断结果里,Base 侧出现了明显倒挂:

| 资产 | Arbitrum | Optimism | Base |
|---|---:|---:|---:|
| WETH | -1.7 | -7.2 | +36.3 |
| wstETH | -3.3 | -8.5 | +29.3 |
| USDT | +0.6 | -0.2 | +26.8 |
| LINK | -21.3 | -144.4 | -34.1 |

其中 Base 上 WETH、wstETH、USDT 的正值非常异常。

然后再按路由拆:

| 买腿路由 → 卖腿路由 | 资产 | 样本 | 中位 bps |
|---|---|---:|---:|
| fly → fly | WETH | 60 | +44.5 |
| kyberswap → fly | WETH | 22 | +35.5 |
| fly → fly | wstETH | 36 | +35.0 |
| okx → fly | wstETH | 38 | +30.2 |
| okx → kyberswap | wstETH | 6 | +1.8 |
| okx → okx | wstETH | 13 | +0.4 |
| kyberswap → kyberswap | USDT | 6 | +0.1 |
| kyberswap → okx | USDT | 6 | -0.1 |
| okx → okx | LINK | 5 | -62.6 |

结论很清楚:

```text
凡是牵涉 fly 的配对,数值明显异常。
不牵涉 fly 的配对,基本落在 0 附近或为负。
```

这说明:

```text
fly 报价源可能系统性高估 toAmount。
```

所以 PDF 做了隔离:

```text
QUARANTINED_TOOLS = fly
```

并且报告里显式打印隔离数量,不是静默删除。

这对本项目很有启发:

> 如果一个机会只在某个报价源出现,先怀疑报价源,不要先幻想套利机会。

## 4. PDF 给本项目的分析模板

从 PDF 可以提炼出一个通用模板。

| 步骤 | 要问的问题 | 对应检查 |
|---|---|---|
| 1. 定义口径 | 我算的是标价、报价,还是成交? | 写清数据源 |
| 2. 计算 edge | 扣完双边成本还剩多少? | `edge = sell / buy - 1` |
| 3. 测成本地板 | 错位至少多大才回本? | 同链/闭环成本 |
| 4. 查污染源 | 好机会是否来自单一工具? | 按 tool 分组 |
| 5. 做自洽性检查 | 同链往返是否反常为正? | 买后立刻卖 |
| 6. 写局限 | 这是报价还是成交?行情是否平静? | 明确适用范围 |

下面把这个模板套到 `MEV-LIFI` 本次数据。

## 5. 本项目这次的数据口径

本项目这次用了两类数据。

### A. 成本门槛

来自:

```text
watch/ARB.USDC-BAS.USDC.jsonl
watch/ARB.USDC-BAS.WETH-rt.jsonl
```

核心问题:

```text
这条路径至少要多少价差才可能不亏?
```

跨资产路径用往返闭环:

```text
ARB USDC → BAS WETH → ARB USDC
```

公式:

```text
硬成本 = 起点 USDC - 回到起点链后的 USDC
真实成本bps = 总成本 / 起点规模 * 10000
```

### B. 屏幕价差

来自:

```text
price_history.csv
```

核心问题:

```text
市场历史上有没有给过足够价差?
```

每小时公式:

```text
spread_bps = (BAS_price - ARB_price) / ARB_price * 10000
```

其中:

```text
ARB_price = Arbitrum 上 1 WETH 的 USDC 价格
BAS_price = Base 上 1 WETH 的 USDC 价格
```

## 6. 本项目成本地板分析

正式统计时切掉了调试数据:

```bash
python3 make_evidence.py --since 2026-08-03T08:34:00Z
```

成本结果:

| 路径 | 规模 | 观测数 | 成本中位 | 成本区间 | 极差 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| USDC→USDC | 1000 | 142 | 25.23 | 25.23~25.34 | 0.11 | 极稳 |
| USDC→USDC | 10000 | 142 | 25.02 | 25.02~25.03 | 0.01 | 极稳 |
| USDC→WETH 往返 | 1000 | 142 | 60.64 | 49.24~73.31 | 24.07 | 波动大 |
| USDC→WETH 往返 | 10000 | 142 | 60.65 | 43.92~71.71 | 27.79 | 波动大 |

读法:

```text
USDC→USDC 的门槛约 25 bps。
USDC→WETH 往返的门槛约 60 bps。
```

所以套利成立的第一道门槛是:

```text
稳定币路径:屏幕价差要超过约 25 bps
跨资产路径:屏幕价差要超过约 60 bps
```

## 7. 本项目屏幕价差分析

`price_history.csv` 统计结果:

| 指标 | 数值 |
|---|---:|
| 小时数 | 72 |
| 最小价差 | -26.31 bps |
| 严格中位价差 | +3.51 bps |
| 脚本打印中位 | +3.77 bps |
| 最大价差 | +26.49 bps |
| 为正小时数 | 42/72 |
| 为正比例 | 58% |
| Base 链内离散度中位 | 14.76 bps |
| 价差绝对值超过同期 Base 链内离散度 | 21/72 |
| 超过比例 | 29% |

手算一行:

```text
ARB_price = 1838.028775
BAS_price = 1833.479067
```

```text
spread_bps = (1833.479067 - 1838.028775) / 1838.028775 * 10000
           = -24.753 bps
```

含义:

```text
这一小时 Base 上 WETH 比 Arbitrum 便宜约 24.75 bps。
```

关键观察:

```text
72 小时里最大价差只有 +26.49 bps。
```

而跨资产往返成本门槛约:

```text
60.64 / 60.65 bps
```

价差没有穿过门槛。

## 8. 本项目净收益分析

净收益公式:

```text
净收益bps = 屏幕价差bps - 真实成本bps
```

为了避免把不同时间的两个极值拼成一个不存在的最好情况,表格用:

```text
净收益区间 = 屏幕价差区间 - 成本中位数
```

### 跨资产 1000 USDC

数据:

```text
屏幕价差 = -26.31 ~ +26.49 bps
成本中位 = 60.64 bps
```

计算:

```text
最差净收益 = -26.31 - 60.64 = -86.95 bps
最好净收益 = +26.49 - 60.64 = -34.15 bps
```

结果:

```text
净收益 = -86.95 ~ -34.15 bps
```

### 跨资产 10000 USDC

数据:

```text
屏幕价差 = -26.31 ~ +26.49 bps
成本中位 = 60.65 bps
```

计算:

```text
最差净收益 = -26.31 - 60.65 = -86.96 bps
最好净收益 = +26.49 - 60.65 = -34.16 bps
```

结果:

```text
净收益 = -86.96 ~ -34.16 bps
```

两个规模的最好净收益都小于 0。

所以:

```text
跨资产路径可复现地不成立。
```

### 极限乐观检查

即使使用最乐观拼法:

```text
最大价差 - 最低成本
```

也还是负。

| 规模 | 最大价差 | 最低成本 | 极限乐观净收益 |
|---:|---:|---:|---:|
| 1000 | +26.49 | 49.24 | -22.75 |
| 10000 | +26.49 | 43.92 | -17.43 |

这说明结论很硬:

```text
不是中位数不行,而是历史最好价差也不够。
```

## 9. 本项目异常源分析

PDF 里有 `fly` 报价污染。

本项目也有上游异常,但表现不同。

本项目异常是:

```text
toAmountMin > toAmount
```

也就是:

```text
最低保证到手 > 预期到手
```

这在逻辑上不可能,说明上游报价字段自相矛盾。

跨资产往返路径中:

```text
82/142 轮有该异常。
```

按工具拆:

| 工具 | 异常/出现 | 异常率 |
|---|---:|---:|
| stargateV2 | 82/82 | 100% |
| relaydepository | 45/83 | 54% |
| layerswap | 31/51 | 61% |
| mayan | 6/9 | 67% |
| mayanFastMCTP | 0/57 | 0% |
| across | 0/1 | 0% |
| symbiosis | 0/1 | 0% |

按完整路由看更清楚:

| 路由 | 样本 | 异常 | 异常率 |
|---|---:|---:|---:|
| stargateV2 → relaydepository | 45 | 45 | 100% |
| stargateV2 → layerswap | 31 | 31 | 100% |
| stargateV2 → mayan | 6 | 6 | 100% |
| mayanFastMCTP → relaydepository | 35 | 0 | 0% |
| mayanFastMCTP → layerswap | 19 | 0 | 0% |
| mayanFastMCTP → mayan | 2 | 0 | 0% |

结论:

```text
本次 toAmountMin > toAmount 异常与 stargateV2 完全重合。
```

这和 PDF 的 `fly` 事件很像:

```text
看起来是某个具体上游工具造成的数据自相矛盾。
```

区别是:

```text
PDF 的 fly 问题会制造假正收益。
本项目的 stargateV2 问题主要污染保底字段,当前成本结论仍然为负。
```

但后续如果要做实盘或自动监控,应该考虑:

```text
把 stargateV2 路由单独标记
或在结论里降低可信度
或加入隔离/分组报告
```

## 10. PDF 和本项目的共同结论

两份分析虽然数据不同,但方法上得出同一类结论:

| 维度 | PDF | 本项目 |
|---|---|---|
| 数据来源 | LI.FI 可执行报价 | LI.FI 成本报价 + 链上历史中间价 |
| 核心公式 | `edge = sell / buy - 1` | `净收益 = 屏幕价差 - 真实成本` |
| 主要风险 | fly 报价污染 | stargateV2 保底字段异常 |
| 机会判断 | 120 轮无可用机会 | 142 成本观测 + 72 小时价差无正净收益 |
| 方法亮点 | 多口径 + 污染源隔离 | 成本门槛 + 历史价差对齐 |
| 局限 | 报价不是成交,平静时段,2 小时 | 中间价不是实际成交,72 小时,ARB 离散度缺失 |

共同教训:

```text
好看的价差先别信。
先问它有没有扣成本,有没有成交深度,有没有污染源,有没有跨过成本地板。
```

## 11. 数据分析的最终写法

一条合格的数据分析结论应该包含四件事。

### 1. 数据范围

```text
成本:142 次 LI.FI 报价观测,2026-08-03 08:34 ~ 2026-08-06 07:05 UTC。
价差:72 小时 WETH/USDC 链上池历史价格。
```

### 2. 计算口径

```text
成本:往返闭环回到 USDC 后计算 bps。
价差:(BAS_price - ARB_price) / ARB_price * 10000。
净收益:屏幕价差 - 成本中位数。
```

### 3. 结果

```text
跨资产路径成本中位约 60.6 bps。
72 小时最大屏幕价差只有 +26.49 bps。
净收益区间始终为负。
```

### 4. 局限

```text
price_history.csv 使用的是链上池中间价,不是指定规模真实成交后的滑点价格。
ARB 备选池在该时段没有成交,链内离散度主要来自 Base 侧。
LI.FI 报价中 stargateV2 相关记录存在 toAmountMin > toAmount 异常。
```

## 12. 下一步该怎么做

如果继续沿 LI.FI 跨链价差方向推进,不要先扩大资金规模。

先补三个能力:

| 下一步 | 为什么 |
|---|---|
| 把报价和真实成交做小额对比 | PDF 最大局限就是报价不是成交 |
| 对异常工具做隔离报告 | 防止 fly/stargateV2 这类源污染结论 |
| 按事件而不是中位数监控 | 平静时段没有机会,真正机会可能只在错位事件里 |

一个更严格的后续判定标准可以写成:

```text
如果 24 小时内,扣除真实成本后没有任何 >= +10 bps 的可执行事件,
则该资产/链组合暂时失败。
```

这和 PDF 的第二轮标准一致:

```text
不要因为中位数接近 0 就继续幻想机会。
要看有没有足够大的、可重复的正事件。
```

## 一句话总结

参考 PDF 后,本项目这次数据分析可以总结为:

> 成本门槛约 60 bps,历史最大可成交中间价差约 26 bps,且价差信号多数时间弱于链内场所离散度;因此 ARB→BAS 的 USDC→WETH 跨资产往返在本窗口内可复现地不成立。  
> 同时,stargateV2 相关报价存在字段自相矛盾,后续应像 PDF 隔离 fly 一样,把异常工具显式标记或隔离。

最终要记住的不是某个数,而是这个分析顺序:

```text
先定义口径
再算成本地板
再看价差是否穿过地板
再查异常报价源
最后才写结论和局限
```
