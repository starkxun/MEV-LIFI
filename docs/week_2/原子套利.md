> 起因:共学群分享的 Solana 地址 [`J7GR6XoJ…Tx6Nf`](https://solscan.io/account/J7GR6XoJfCPwZumW9xZ1nbWkyaq1oYSQuSVmCdBTx6Nf)

## 先给结论

那个地址是一个**正在运行的原子套利机器人**。61.7 小时里打了 **6000 笔交易**,
其中 **5656 笔失败(94.3%)**,靠剩下的 344 笔赚钱。

```
成功率     5.73%
频率       ≈ 97 笔 / 小时
10 笔成功交易合计  +0.094 SOL
```

**94% 的失败率不是问题,而是这个策略的设计前提。** 下面解释为什么。

---

## 一、「原子」是什么意思

### 对比你已经测过的跨链搬砖

```
跨链搬砖(你 Week 1-2 测的):
  ① 在 A 链买  →  ② 等桥(7 ~ 1080 秒)  →  ③ 在 B 链卖
  中间有真实的时间间隔。价差可能跑掉,资金可能卡在半路。

原子套利:
  [ ① 买 + ② 卖 ] 打包进同一笔交易
  → 成功:两步都成,赚差价
  → 失败:整笔回滚,像没发生过
```

**「原子」(atomic)就是不可分割 —— 没有"买完了但还没卖"这种中间状态。**

### 这带来的最大改变:失败成本≈0

回顾你的成本模型:

```
净收益 = 屏幕价差 − 桥费 − 滑点 − gas − 延迟风险
        − 失败交易成本(失败概率 × 已花 gas + 占用资金)   ← 这一项
        − 资金占用
```

原子套利把**失败交易成本压到只剩手续费**。资金没有被占用过,
因为那笔交易根本没执行成功。

**所以它能承受 94% 的失败率。** 试错是免费的,那就疯狂试 ——
每小时 97 笔就是这么来的。

## 二、拆一笔真实交易

签名 `5rpAyf7XYLVZSaiSEEeipPbmw4hjMRQr…`,一笔交易里同时做了两件事:

```
① 从池子 Fex8CSk 买入:  付出 5.6259 WSOL  →  得到 81,172 个 memecoin
② 卖给池子 2TD1fMP:     付出 81,154 个币  →  得到 5.6887 WSOL
─────────────────────────────────────────────────────────
                          差价 +0.0628 WSOL,外加剩下 18.25 个币
```

**同一个币在两个池子里价格不一样,低买高卖,一笔搞定。**

### 它的技术构造

```
签名钱包 J7GR6Xo…(普通钱包,持有 46.4 SOL)
   └─ 调用 BaMpent4Np6pYZ7JLDmtZNFJ8o3VBnHdy6A9mGDyZRW8   ← 它自己部署的程序
        └─ CPI → LBUZKhRxPF3XUpBCjp4YzTKgLccjZhTSDM9YuVaPwxo   ← Meteora DLMM
        └─ CPI → pAMMBa…(Pump AMM)等其它 DEX
```

**注意中间那层:它部署了自己的 Solana 程序。** 因为 Solana 的一笔交易里
要把多个 DEX 的 swap 串起来、并且让第二步用上第一步的结果,
需要一个合约来编排。(**这一点在 Sui 上不一样,见第五节。**)

### 失败长什么样

```
AnchorError caused by account: bin_array
Error Code: AccountNotEnoughKeys. Error Number: 3005
```

Meteora DLMM 是"分箱"做市 —— 流动性按价格区间(bin)存放。
机器人**发交易前要先算好会用到哪些 bin,把这些账户列进交易里**。

交易上链时价格已经走出那个范围 → 需要的 bin 账户没列进来 → 整笔失败。

**这就是 94% 失败的主因:预测账户时的价格,和上链时的价格不一样了。**

## 三、我在分析过程中读错了一次

第一遍我只看**原生 SOL 余额变化**:

```
交易           原生SOL净变化
5rpAyf7XYL     -0.014629     ← 看起来在亏钱
2PrEykHmoQ     -0.013635     ← 也在亏
10 笔合计:     -0.040895 SOL  ← "这机器人一直在亏"
```

**结论是反的。** 因为:

- **利润以 WSOL(包装 SOL)到账** —— 那是个 token,不算在原生 SOL 余额里
- **小费用原生 SOL 付** —— 所以原生余额在减少

两个一起算才对:

```
交易           原生SOL      WSOL       合计       小费
5rpAyf7XYL   -0.014629  +0.031686  +0.017057   0.014624
2hNaDLCWja   -0.000603  +0.030704  +0.030101   0.000000
4qQQhnPoaM   -0.001071  +0.017480  +0.016409   0.001000
2PrEykHmoQ   -0.013635  +0.025645  +0.012010   0.013630
…
10 笔合计:                          +0.094360 SOL
```

> **这是铁律 1 的翻版:只认一种计价口径,就会得出符号相反的结论。**
> 你 Day-0 栽在"美元 vs token",我这次栽在"原生 SOL vs WSOL"。
> 同一个坑,换了张皮。
>
> **通用判据:分析任何链上账户前,先问"钱可能以几种形式存在"。**
> 原生币、包装币、各种 token —— 漏掉一种,结论就可能翻。

另外注意那个**小费**:0.0146 SOL 是付给验证者/区块构建者买优先权的。
在总利润 0.0317 里占了 46% —— **速度是明码标价的**。

## 四、和你测过的东西对比

| | 跨链搬砖(你测的) | 原子套利(这个) |
|---|---|---|
| 失败成本 | **高** —— 桥费已付、资金在途 | **≈0** —— 交易回滚 |
| 能承受的失败率 | 几乎不能失败 | **94% 都在失败** |
| 延迟 | 7 ~ 1080 秒 | 同一区块内 |
| 门槛 | 25 ~ 60 bps | 覆盖手续费 + 小费即可 |
| 谁在竞争 | 慢,人也能参与 | **纯拼速度,机器人战场** |
| 需要的工程 | 会调 API 就行 | 部署合约 + 账户预测 + 延迟优化 |

**最本质的差异是"失败成本"。** 这一项从"高"变成"≈0",整个策略的形态就变了:
从"必须算准才敢做",变成"算不准就多试几次"。

## 五、Sui:哪些已经验了,哪些还没

### ✅ 已确证(我实测的)

**Sui 公共 fullnode 的 JSON-RPC 已经废弃了。** 直接访问返回:

```
Method not found. JSON-RPC on public fullnodes has been deprecated.
Please migrate to gRPC or GraphQL endpoints.
See https://docs.sui.io/develop/access-sui-data
```

`suix_getReferenceGasPrice`、`sui_getChainIdentifier` 这类方法**全部失效**。

**这是你一上手就会撞到的第一堵墙。** 网上大部分 Sui 教程和 SDK 示例还在用
JSON-RPC,照抄会直接跑不通。先去官方文档确认当前该用哪个端点。

> 我在这个环境里连不上 Sui 的 GraphQL 端点(HTTP 000),
> 所以**没能实测 gas 价格、DEX 包地址这些具体数字** —— 下面凡是涉及
> 具体数值的,一律标成"要你自己验",我不编。

### ✅ 已验证:PTB 真的不用部署合约(2026-08-06 补)

拿到 [`fuzzland/sui-mev`](https://github.com/fuzzland/sui-mev) 实测过了,
**待办第 ② 条可以打勾**:

```
.move 文件数: 0        ← 全仓库没有一个 Move 合约
```

它用 `ProgrammableTransactionBuilder` 直接在**交易层**串联多个 DEX 的 swap:

```rust
coin_out: Argument::NestedResult(last_idx, 0),   // 上一步的输出
receipt:  Argument::NestedResult(last_idx, 1),   // 直接喂给下一步
```

`NestedResult` = "取第 N 条命令的第 M 个返回值"。**这就是 PTB 组合。**

对比 Solana 那个机器人必须部署 `BaMpent…` 才能编排多步 swap ——
**Sui 上的启动成本确实低一个数量级。**

### ✅ 另一个发现:它用闪电贷,零本金

```rust
// 1. flashloan(第一个 DEX 支持就用它,否则走 Navi 借贷)
// 2. swaps
// 3. repay flashloan
```

**不用自己出本金** —— 交易内借出来、套完、还回去、留下差价,全程原子。

> **这条可以直接搬到你的清算主业**:借币 → 清算 → 卖抵押物 → 还款,打包一笔。
> 抢不到就整笔回滚,只亏 gas。不会出现"钱花了但没抢到"这种最难受的情况。

### ⚠️ 但「跑起来」的门槛在别处:要自建全节点

它的两个模拟器都不是普通 RPC 能满足的:

| 模拟器 | 需要什么 |
|---|---|
| `HttpSimulator` | `dry_run_transaction_block_override` —— **魔改过的 RPC**,标准节点没有。作者自己标了 deprecated |
| `DBSimulator` | 直读节点的 **RocksDB**(`/home/ubuntu/sui/db/live/store`)+ socket 实时推送 |

**所以"只读跑一遍看看有多少机会"这条路,前提是先建节点。**
这就是为什么下面那个探测脚本不依赖它 —— 花钱之前先量数据。

### 🔧 探测脚本:先量数据,别先建节点

既然"跑机器人"要先建全节点,那就**先用零成本的方式量价差** ——
这是你在跨链上验证过的顺序:**先量成本地板,再看有没有机会。**

[`sui_pool_price.py`](../../sui_pool_price.py) 干这件事,
**不依赖 sui-mev 仓库、不需要 Rust、不需要节点**:

- 池子清单已从 sui-mev 复制到 [`data/sui_pools/`](../../data/sui_pools/)(8 个文本文件,11MB)
- 只调 `sui_multiGetObjects` 读链上池子状态
- 直接扔服务器就能跑

#### RPC 说明

`SUI_RPC` 从环境变量读,**不写死在代码里** —— Ankr 那类 URL 自带 API key,
写进文件就等于提交到 git。

实测 Ankr 会偶发失败(连打 8 次,2 次 HTTP 000),所以脚本的端点顺序是
**自有付费端点 → 公共端点兜底**,配合重试和轮换。
少一个数据点,不如慢一点但拿到。

> ⚠️ **30 分钟这个间隔的局限要说清楚。**
> 你测跨链时门槛是固定费率(很稳),半小时够。但 Sui 这个价差是
> **市场撮合出来的**,而原子套利的机会窗口可能只有几秒。
>
> **半小时一轮只能回答「价差的典型水平是多少」,回答不了「有没有短暂的窗口」。**
>
> 但作为第一步这样是对的:先看典型水平离地板差多远。
> **现在差 38~45 bps —— 如果几天下来一直是这个量级,那连窗口都不用找了。**

### ⚠️ 还没验的两件事

**1. 共享对象的竞争模型**

Sui 的 AMM 池是**共享对象(shared object)**,访问它的交易要走共识排序。
这和 Solana 的账户锁定模型不同。

要搞清楚:**两笔交易同时想动同一个池会怎样?** 排队、其中一笔失败、还是别的?
这直接决定你的失败模式和重试策略。

**2. 失败到底花多少钱**

原子套利的全部前提是"失败几乎免费"。在 Sui 上:

- 交易 abort 时 gas 怎么收?全收、部分收、还是不收?
- 有没有类似 Jito 小费的优先权机制?怎么定价?

**这一项如果和 Solana 不同,整个策略的经济学就要重算。**

> 代码里 `GAS_BUDGET = 10_000_000_000`(10 SUI)只是**上限**不是实际花费,
> 回答不了这个问题。要么读 Sui 文档,要么发一笔必然失败的交易实测。

### 一个方法论迁移

你已有的工具里,这两个思路直接搬到了 Sui:

- **成本地板优先** —— `sui_pool_price.py` 先算双边手续费地板,再看价差够不够
- **持续监控 + 分布而非单点** —— `--interval` / `--history` 复用了
  [`lib/chainkit.py`](../../lib/chainkit.py) 的循环骨架(单轮异常不拖垮整个循环)

## 六、关于 Sonic

你说"整条链半死不活,清算脚本还挂着"。这个观察本身有信息量:

**链安静对套利是双刃的** —— 竞争少,但机会也少。对**清算**尤其明显:
清算机会来自借贷市场的头寸变化,链上活动少 = 借贷规模小 = 清算事件稀疏。

建议不要凭感觉判断,**用你现成的方法量一下再决定去留**:

- 过去 30 天 Sonic 上发生了多少次清算?(链上事件可回溯,一次查询的事)
- 其中你的脚本抢到几次、被抢走几次?
- 抢到的那几次,**扣掉抵押物变现滑点之后**真实到手多少 bps?

**如果清算事件本身就稀疏,那不是你脚本的问题,是市场的问题** ——
那就该迁移。但如果事件不少而你抢不到,那是速度问题,换条链一样会遇到。

> 脚本挂着不花钱,可以先留着当数据采集器 —— 它记录的"错过的机会"
> 本身就是判断该不该走的证据。

## 七、诚实的风险提醒

1. **这是机器人战场,拼的是延迟。** 那个 Solana 机器人每小时打 97 笔、
   付 46% 的利润当小费买优先权。你的优势在合约安全和清算逻辑,**不在延迟竞争**。
2. **94% 失败率意味着大量试错。** 即使单次失败便宜,**规模化之后的
   总成本不可忽略** —— 记得把它算进成本模型。
3. **本文的 Solana 数据、Sui 的 PTB/闪电贷/价差都是实测的**;
   但**共享对象竞争模型和失败成本还没验** —— 那两条是整个策略经济学的地基。
4. **不构成投资建议。** 真上手前先小额、先只读、先量成本地板。

## 沉淀

1. **「原子」的价值不在于快,在于把失败成本压到接近零。**
   这一项从"高"变"≈0",策略形态就从"算准才做"变成"算不准就多试"。
2. **分析链上账户前,先问"钱可能以几种形式存在"。**
   我这次漏了 WSOL,得出了符号相反的结论 —— 铁律 1 换了张皮。
3. **速度是明码标价的。** 那 46% 的小费占比,就是延迟的市场价。
4. **换链之前先量数据,别凭"感觉这条链不行"。**
5. **"能不能做"和"值不值得做"是两个问题,而且答案可以相反。**
   Sui 上 PTB 免部署 + 闪电贷零本金,技术门槛比 Solana 低一个数量级 ——
   但实测价差只有成本地板的四分之一。**技术可行 ≠ 经济可行。**
6. **动手建基础设施之前,先花零成本量一次数据。**
   跑那个机器人要先建全节点;而一个不依赖它的探测脚本,当天就能告诉你
   价差离地板差多远。
