## 先给结论

这两个东西**不是一类**,放一起是因为它们在同一条链路的两端:

```
Backpack     = 场地(一家 CEX,你在这里持仓、付手续费)
Taoli Tools  = 手(一个下单器,替你在两个场地同时反向开仓)
```

**最关键的认知纠正**:Taoli Tools **不负责找机会**。

它的官方定义是"半自动化的 U 本位对冲套利工具,核心功能是一键双边下对冲单"✅。
你输入「价差到 0.3% 就下单」,它盯着、到了就下。
**价差从哪来、够不够覆盖成本、这个价差是不是假的 —— 全是你自己的事。**

用你 Week 1-2 的成本模型对照,它只占其中一格:

```
净收益 = 屏幕价差 − 手续费 − 滑点 − 资金费 − 延迟风险 − 单腿风险
         ↑                                      ↑
      你要自己判断                        Taoli Tools 干的是这里:
      (它不管)                          把「两条腿的时间差」压到最小
```

这个定位很诚实,文档里明写了三个"不是"✅:
> 不是无风险摇钱树 / 不能全自动赚钱 / 不能自动化执行策略

## 一、Taoli Tools

### 1.1 它到底解决什么问题

对冲套利的操作难点不在「知道有价差」,在**两条腿必须几乎同时成交**。

手动操作的失败模式:你在 A 所点了买,切到 B 所准备卖,这 3 秒里价格动了 ——
现在你不是套利,是**单边裸多**。这就是文档里反复提的「单腿」(single-leg)问题✅。

Taoli Tools 就是把这 3 秒压掉:一次点击,两个所同时反向下单。

> 这跟你在 [原子套利.md](原子套利.md) 里分析的 Solana 机器人是**同一个问题的两种解法**:
> 原子套利用「打包进一笔交易」实现零时间差(失败就整体回滚);
> Taoli Tools 是跨 CEX,做不到原子性,只能**尽量缩短**时间差 ——
> 所以**单腿风险消不掉,只能减小**。这是它和原子套利的本质差距。

### 1.2 架构与信任模型(这块设计得不错)

✅ 官方说明:

| 项 | 说明 |
|---|---|
| 运行位置 | **浏览器本地运行**,网页版直接跑,无需部署 |
| 密钥存储 | 全部存在你本机浏览器,做了基本加密 |
| 服务端收集 | User Agent、IP、交易所 UID/钱包地址的 **Hash**、资金额度 |
| 为什么收 | 检测多开滥用(按总资金卡 VIP 等级),Hash 不可逆推 |
| DEX 签名 | 有独立的开源自托管签名服务 [Taoli Tools Signer](https://github.com/peddlerfans/taoli-tools-signer) |

作者自己的说法⚠️(2025-06 推文):"从今以后,无需信任。"—— 指的是助记词签名这块开源了。

**部署方式**✅:
- 本地浏览器跑(推荐新手,但电脑得一直开着)
- Windows 服务器 + 远程桌面(文档标注"推荐大多数用户")
- Linux 服务器 + Docker + VNC(资源占用少)

> 注意最后一条:**它本质是个浏览器应用,服务器部署也是在服务器上开个浏览器**。
> 这跟你跑 `watch_probe.py` 那种无头脚本不是一回事,延迟和稳定性天花板不同。

### 1.4 怎么用

**上手流程**✅(官方 quick-start 六步):

1. 访问 [taoli.tools/trade](https://taoli.tools/trade),**用 Telegram 登录**
2. 右上角进设置页
3. (可选)把左上角 UID 发给作者,付款开通 VIP —— VIP0 免费不用这步
4. 在设置页填各交易所的 API Key / Secret,点 Save 测试连通
5. 交易页下方「Symbol, CA」搜索,选定 A、B 两个交易对,点「Add Pair」
6. 小额试跑

**下单参数**(这是核心,✅ 原文提取):

| 参数 | 含义 |
|---|---|
| **Once** | 当前差价 ≥ 预设差价时,按当前差价下一次单 |
| **Loop** | 持续等待,每次差价达标就下单,循环到出错为止 |
| **单边下单** | 按住 Shift,忽略差价设置,手工补腿用 |
| **Sequence** | 下单顺序:Parallel / A then B / B then A |
| **Size** | 单次下单数量(币) |
| **MinA / MaxA** | A 腿持仓上下限(币);`$MinA/$MaxA` 是美元版 |
| **VA / VB** | 价距 —— 委托价与买一卖一的差距(%),限价单用 |
| **MaxO** | 单边未成交最大挂单数 |
| **Flat** | 勾选后每次双边下单前检查持仓是否平衡 |

**交易页面显示的东西**✅:Position(持仓,A/B 一致 = 平衡)、Fee(永续显示下次资金费收取时间和费率;
现货杠杆显示每小时利息)、Best Bid/Ask(**颜色变化指示数据新鲜度**)、Available、Risks(风险指数)、
P&L(**含手续费**,平台币抵扣和链上 gas 也计入)。

> 「颜色指示数据新鲜度」这个设计值得注意 —— 说明作者踩过**报价过期**的坑。
> 文档 FAQ 里确实写了:**报价超过 3 秒触发失败**✅。这跟你 `cost_probe.py` 里
> 记 `duration_s` 是同一种警觉。

### 1.6 风险(✅ 官方风险页,值得逐条读)

**安全侧**:
- 数据存本机浏览器 → **恶意插件、木马、供应链攻击都能偷 key**
- 原文警告:即使设了 IP 白名单、关了提现权限,**黑客仍可通过小币种对敲把钱转走**
- 建议:API key 只给「读 + 交易」最小权限

> 最后这条很关键,而且是**多数人的盲区**:关提现 ≠ 安全。
> 对敲(wash trade 到一个自己控制的对手方)能绕过提现限制把钱挪走。

**资金侧**:
- 网络抖动导致**单腿成交**,要手动去交易所补
- 永续爆仓、**ADL 自动减仓**
- **稳定币脱锚** → 整个 U 本位假设失效
- 极端行情可能损失全部本金

界面上有三个风险指标:**ADL**(减仓优先级)、**MR**(保证金率)、**Liq Price**(爆仓价),
红→黄→绿→灰四色。

**FAQ 里的常见亏损原因**✅ —— 这部分信息密度最高:

| 亏损原因 | 机制 |
|---|---|
| 资金费方向反了 | 持仓方向和资金费符号一致时,你是**付钱**的那方 |
| 现货数量缩水 | CEX 买入用币扣手续费、卖出用 USDT 扣,导致两边数量对不齐 |
| DEX 滑点 | 实际到手数量取决于池深度 |
| 单腿 | 一边失败(尤其 A-then-B 的市价单),要手动补平 |
| 时间戳错误 | 系统时钟漂移 > 5 秒直接被拒 |

FAQ 的盈利判据原文⚠️(转述):**两个价差之和 > 2 倍总手续费,理论上就赚**。

> ⚠️ 这句话要打个问号。它算的是**开仓价差 + 平仓价差 vs 双边手续费×2**,
> **没有包含资金费、滑点、单腿概率**。
> 用你的框架说:这是**成本地板的下界**,不是完整成本。
> 你 `sui_pool_price.py` 里那句"名义为正,但还没扣价格冲击、gas、被抢先的概率"
> 是同一个提醒。**这条是明天可以跟作者对齐的技术点,不是挑刺 —— 我猜他自己清楚,
> 只是文档为了好懂做了简化。**

## 二、Backpack

### 2.1 是什么

一家 2023 年 11 月上线的 CEX⚠️,创始团队背景比较特殊:
- **Armani Ferrante** —— Solana 生态开发者(Anchor 框架、Backpack 钱包)
- **Can Sun** —— FTX 前法律总顾问
- Backpack US 总裁是**前 CFTC 代理主席 Mark Wetjen**

牌照:杜拜 VARA⚠️;欧盟另设 Backpack EU(MiFID II)。

**产品线**⚠️:现货、永续合约、**美股与 ETF(1000+ 档,真股非代币化)**、借贷质押、活期理财。

### 2.2 费率(✅ 官方文档实测抓取,2026-08-06)

这是你最该关心的部分 —— **它直接就是成本地板的输入**。
下面是官方 [VIP Program 费率表](https://support.backpack.exchange/exchange/programs/backpack-vip-program.md)
的完整档位,单位换成 bps:

| 档位 | 现货 Maker | 现货 Taker | 永续 Maker | 永续 Taker |
|---|---|---|---|---|
| **Tier 1(默认)** | **8** | **10** | **2** | **5** |
| Tier 2 | 7 | 9 | 1.9 | 4.5 |
| Tier 3 | 6 | 8 | 1.8 | 4 |
| Tier 4 | 5 | 7 | 1.6 | 3.5 |
| Tier 5 | 4 | 6 | 1.3 | 3 |
| Tier 6 | 3 | 5 | 1.0 | 2.8 |
| VIP 1 | 2 | 4.5 | 1.0 | 2.6 |
| VIP 2 | **0** | 4 | **0** | 2.4 |
| VIP 3 | 0 | 3.5 | 0 | 2.2 |
| VIP 4 | 0 | 3 | 0 | 2.0 |
| VIP 5 | 0 | 2.5 | 0 | 1.8 |

**换算成你的地板语言**(以默认 Tier 1 计):

```
现货跨所搬砖,双边 taker:  10 + 10 = 20 bps   ← 光手续费
永续对冲,双边 taker:       5 +  5 = 10 bps
永续对冲,双边 maker:       2 +  2 =  4 bps   ← 这就是为什么文档推荐限价单
```

> **这解释了 Taoli Tools 为什么给 VA/VB 参数(挂在买一卖一之外)**:
> maker 和 taker 差 2.5 倍,不挂限价单,地板直接翻倍。
> 但挂限价 = **可能不成交** = 单腿风险上升。**这是明确的取舍,不是免费午餐。**
>
> 注意档位是**渐进**的,不存在"冲一档省一半"的跳变。
> 起步 20 bps 这个数才是你该用的地板 —— 别拿 VIP5 的数字做规划。

### 2.3 ⚠️⚠️ 最重要的一条:Taker 有 100ms 减速带

✅ 这是这次调研**信息价值最高的发现**,来自官方
[Taker Speed Bump](https://support.backpack.exchange/technical-docs/trading/taker-speed-bump.md),
中文资料里几乎没人提:

> Backpack 对**现货和期货所有市场的 taker 订单统一施加 100ms 减速带**。
> - 任何**没带 `postOnly` 标志**的订单都受影响 —— 包括市价单、限价单、**以及 IOC 单**
> - 带 `postOnly` 的订单**不受影响**
> - **撤单不受影响**,立即处理
> - 对所有参与者一视同仁
> - **试图绕过减速带违反服务条款**

官方给的理由是保护挂单方免受延迟套利(latency-driven adverse selection),换取更深的盘口。

**这对你意味着什么 —— 三条,每条都是硬约束**:

```
① 吃单套利在 Backpack 上被结构性地削弱了。
   100ms 内价格可能已经变了,你按屏幕价差算的收益是拿不到的。
   这是交易所**故意设计的**,不是网络抖动,加钱、换机房、离得近都没用。

② 双边对冲时,如果 Backpack 这条腿是 taker,它必然比另一条腿晚 100ms。
   → 单腿暴露窗口从"网络抖动的随机量"变成"至少 100ms 的确定量"。
   这直接抬高了 Taoli Tools 文档里那个「单腿风险」。

③ 唯一的解法是走 postOnly(纯挂单)。
   但 postOnly = 只做 maker = 可能不成交 = 又回到单腿问题。
```

> **这三条串起来看,就明白 Taoli Tools 的 Backpack 配置页为什么写「建议用限价单模式」了**✅ ——
> 表面理由是"很多交易对不支持市价单",但**更深的理由是减速带**。
> 不过要注意:Taoli Tools 的 VA/VB 是"挂在买一卖一之外多少",
> **这不等于 `postOnly`** —— 一个限价单如果价格穿过盘口仍会成为 taker 并吃到减速带。
> **这两者是不是等价,是明天必须问清楚的一个具体问题。**(见 Q7')

**用你自己的框架说**:你 Week 1-2 一直在量的是「屏幕价差 vs 可成交价差」的差。
减速带是一个**新的、可量化的、被官方明确公布的**差值来源 ——
它让 Backpack 的 taker 侧屏幕价差**系统性地不可成交**。这跟你在 LI.FI 上
发现的报价失真是同一类问题,只是这次原因写在文档里。

出金⚠️:每 30 天首次免费(质押 BP 可提额度),超出每笔 $50;VIP 全免。稳定币入金 15+ 条链免费。

### 2.4 BP Token 与积分⚠️

- 2026 年 3 月发行,总量 10 亿
- **25% 空投给积分计划参与者和 Mad Lads NFT 持有人**
- **无内部人分配**(如属实,在行业里确实罕见)
- 质押可降手续费、增加免费出金次数、长期质押可转公司实际股权

> 这一条对套利者有实际影响:**如果刷量能换积分/空投,那"亏一点手续费"可能是划算的**。
> Taoli Tools 文档也明说了它的一个用途是「**刷交易量撸空投或返佣**」✅ ——
> **注意这跟套利是两回事**:那种情况下你不是在赚价差,是在**买积分**,
> 手续费是成本不是障碍。想清楚自己在做哪一件。

### 2.5 地区限制⚠️

不服务:朝鲜、伊朗、古巴、叙利亚、乌克兰特定地区。
暂不提供:加拿大、日本、英国、新加坡、新西兰、多数欧盟国(欧盟走 Backpack EU)。

### 2.6 ⚠️ Backpack + Taoli Tools 的三个具体坑(✅ 官方 backpack 配置页原文)

这两条很实在,**是我这次调研最有操作价值的发现**:

1. **API Key 不能选只读** —— 必须给完整权限
2. **必须解除浏览器跨域(CORS)限制才能用** —— 因为 Backpack API 的限制,
   文档专门有一章 [disable-browser-cors](https://docs.taoli.tools/disable-browser-cors/) 教怎么关
3. **建议用限价单模式** —— 因为**很多 Backpack 交易对不支持市价单**

> 第 2 条要警惕。**关掉浏览器 CORS 是一个真实的安全降级**:
> 那个浏览器实例里,任意网页都能向任意域发带凭证的请求。
> 配合上面「key 存在浏览器本地」的设计 —— **这两件事叠在一起,风险不是相加是相乘**。
> 务实做法:**专门开一个只跑 Taoli Tools 的浏览器实例/用户目录,不用它上任何别的网站**。
> (文档里的多开教程正好教了怎么用独立 user-data-dir 启动,可以复用。)
> **这是明天值得当面确认的一条。**

## 三、如果要自己验证,最小实验是什么

按你一贯的顺序 —— **先量地板,再看机会**:

```
第 0 步(零成本,今天就能做):
  打开 funding-rank.taoli.tools,记录一批币在各所的 8h 资金费率。
  这是免费的、公开的、不用注册的。

第 1 步(零成本):
  用 Backpack 官方费率(2.2 表)+ 第 0 步的资金费率,手算地板:
     地板 = 双边手续费 + 持仓期资金费
  然后问:观察到的价差分布有没有 30% 的时间超过这个地板?
  ——— 答案是"没有"的话,后面全都不用做。   ← 你在 Sui 上就是这么筛的

第 1.5 步(零成本,新增 —— 因为 100ms 减速带):
  Backpack 公开行情 API 不用 key:
     https://api.backpack.exchange/api/v1/markets
  按 60s 采样某个对的买一卖一,量「100ms 内盘口变动幅度」的分布。
  这个数就是减速带给你的**额外滑点**,要加进地板。
  ——— 如果它跟你的目标价差同一量级,吃单套利在 Backpack 上直接出局。

第 2 步(免费额度):
  VIP0 注册,$5,000 以内,单个交易对,Size 设到最小,只用 Once 不用 Loop。
  目的不是赚钱,是量三个数:实际成交价差 vs 屏幕价差的差、单腿发生率、端到端延迟。

第 3 步:
  上面三个数拿到之前,不要付费,不要 Loop,不要加规模。
```

**第 2 步量的那三个数,就是明天最该跟作者对的东西** —— 因为他有 2000+ 用户的样本,
而你只有你自己的。

## 四、明天的提问清单

> 排序原则:**先问只有他能答的,再问文档能查的**。文档里写着的别问,那是浪费两个人的时间。
> 下面每条都标了「**为什么问**」—— 会议上如果时间不够,按顺序砍尾巴。

### 🔴 第一梯队:只有他有数据的

**Q1. 你说过「稳赚的套利比如 Sui MEV,我不会拿出来卖,只能我一个人赚」——
能展开讲讲 Sui 上那类机会现在是什么状态吗?**

> **为什么问**:这是全场对你价值最高的一个问题,而且是**他自己公开说过的话**⚠️
> (2025 年 4 月推文,来源见文末)。你手上正好有 `sui_pool_price.py` 在量 Sui 多 DEX 价差。
> **拿你的实测结果去问,而不是空问** —— 比如"我量了 Cetus/Turbos/FlowX 的中间价差,
> 双边手续费地板算下来是 X bps,价差大部分时间压在地板下面。你说的那类机会,
> 是不是根本不在这种中间价价差里,而在别的地方(比如清算、大单冲击后的回归)?"
> **想听到的**:机会的**类型**,不是具体参数。他不会给参数,但会给方向 —— 而方向才是你缺的。

**Q2. 2000+ 用户跑下来,亏钱的人最主要栽在哪一项?
是资金费方向、单腿、还是滑点?有没有大致的比例感?**

> **为什么问**:文档列了五种亏损原因,但**没有权重**。
> 权重才是决策信息 —— 知道 80% 的亏损来自单腿,和知道 80% 来自资金费,
> 你的防护重点完全不同。**这个数只有他有。**

**Q3. 单腿实际发生率大概是什么量级?千分之几还是百分之几?
Parallel 和 A-then-B 两种 Sequence 差多少?**

> **为什么问**:这是**能不能上规模的唯一硬约束**。单腿率决定了你每笔的隐含成本
> (单腿概率 × 平均补腿损失),这一项如果是 50 bps,那所有 20 bps 的机会都是假的。
> 文档完全没提这个数。

**Q4. 从上线到现在一年半,哪一类机会是明显衰减的?哪一类还活着?**

> **为什么问**:套利机会有生命周期。他有跨越一年半的观测,你没有。
> **这个问题比问"现在什么赚钱"高级** —— 后者他多半不会答,前者是行业观察,他更愿意聊。

### 🟡 第二梯队:方法论

**Q5. 工具显示的是屏幕价差(买一卖一),但实际成交要吃深度。
你有没有考虑过在界面上直接显示「按当前 Size 算的可成交价差」?
还是说用户都自己心里有数?**

> **为什么问**:这正是你 Week 1-2 反复踩的点 —— 屏幕价差 ≠ 可成交价差。
> **这个问题会暴露你做过功课**,而且是产品讨论不是索取信息,他容易接话。

**Q6. FAQ 里那句「两个价差之和大于 2 倍总手续费理论上就赚」——
这里面没算资金费和滑点。是为了让文档好懂做的简化,还是实践中这两项确实可以忽略?**

> **为什么问**:**问法很重要**。给了他台阶(「是不是为了好懂」),
> 不是踢馆。真实答案大概率是"是简化",但**他补充的那部分才是你要的**。

**Q7. Backpack 要求关掉浏览器 CORS,而 API key 又存在浏览器本地。
这两件事叠加,你自己是怎么隔离的?有推荐的实践吗?**

> **为什么问**:这是我这次调研发现的最实在的安全问题(见 2.6)。
> 他一定想过这个,但文档没写。**答案对你有直接的操作价值。**

**Q7'. Backpack 对所有 taker 单有 100ms 减速带,只有 `postOnly` 免疫。
Taoli Tools 的 VA/VB 限价单,下的是普通限价单还是 `postOnly`?
如果是普通限价,那价格穿过盘口时还是会吃到那 100ms。**

> **为什么问**:🔴 **这条其实该算第一梯队 —— 如果时间只够问三个问题,把它换进去。**
> 它是一个**能当场给出是/否答案的具体技术问题**,而答案直接决定
> Backpack 这条腿的单腿暴露窗口是"网络抖动量"还是"至少 100ms"。
> 而且这个问题会立刻显示你不是来听介绍的(见 2.3 —— 中文圈基本没人讨论减速带)。
> **想听到的**:如果答案是"普通限价",顺势问「有没有考虑加个 postOnly 开关」——
> 这是一条具体的产品建议,比泛泛提问留下的印象深得多。

**Q8. 为什么是「半自动」?做成全自动的技术障碍是什么,还是刻意的产品决策?**

> **为什么问**:他的定位很克制,这不像是能力不足,更像是想清楚了。
> 答案可能涉及**责任边界**(全自动 = 你要为用户亏损负责)和
> **策略同质化**(全自动 = 所有人同时下单 = 机会瞬间消失)。
> 两个答案都很有信息量。

### 🟢 第三梯队:有时间再问

> **为什么问**:你手上有 142 轮监控数据,发现 **82 次异常全部来自 stargateV2**
> (见 [待办.md](待办.md))。**这是你能反过来提供信息的地方** ——

> **为什么问**:轻松话题,可以收尾用。也顺便了解他的产品节奏。

## 六、一句话总结

**Taoli Tools 是一把好用的手,Backpack 是一块场地,但「往哪伸手」这件事没人替你做。**

它的价值在于把你已经判断出来的机会**执行得更干净**(时间差更小、单腿更少);
它的边界在于**判断本身**——而判断恰好是你 Week 1-2 一直在建的东西
(成本地板、可成交价差、不变量检查)。

**这两件事是互补的,不是替代的。** 明天带着你的地板数据去谈,位置会比"来学怎么用工具"好很多。

而 Backpack 的 100ms 减速带是个提醒:**成本地板不只由手续费构成,还由交易所的规则设计构成**。
你之前量的是"市场给你的成本",这一条是"场地给你的成本" —— 它写在文档里,
不用猜,但也不会有人主动告诉你。
