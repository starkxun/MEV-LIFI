# 屏幕价差教学:它是什么,为什么没自动填,怎么获取

> 配套表格: [`evidence.csv`](../../evidence.csv)  
> 当前成本来源: [`watch/*.jsonl`](../../watch/)  
> 当前可成交价工具: [`pool_price.py`](../../pool_price.py)  
> 历史价差工具: [`price_history.py`](../../price_history.py)

## 先给结论

`evidence.csv` 里的「屏幕价差bps」指的是:

> 市场表面上给你的价差,还没有扣真实成本。

真正要判断套利是否成立,不能只看屏幕价差,而要看:

```text
净收益 = 屏幕价差 - 真实成本
```

例如:

```text
屏幕价差 = +40 bps
真实成本 = 25 bps
净收益 = +15 bps
```

这才有可能成立。

如果是:

```text
屏幕价差 = +10 bps
真实成本 = 25 bps
净收益 = -15 bps
```

那就是屏幕上看着有价差,但扣完桥费、gas、滑点以后不成立。

这里的 `bps` 还是老规矩:

```text
1 bps = 0.01%
25 bps = 0.25%
100 bps = 1%
```

---

## 真实成本和屏幕价差分别回答什么

你可以把一条套利路径拆成两个问题。

### 问题 1:这条路至少要多少价差才不亏

这是「真实成本」回答的。

例如 `watch_probe.py` 跑了三天后,表里得到:

```text
USDC→USDC 10000:
真实成本 25.02 [25.02~25.03] bps

USDC→WETH 往返 10000:
真实成本 60.65 [43.92~71.71] bps
```

意思是:

```text
USDC→USDC 这条路,屏幕价差至少要超过约 25 bps 才可能赚钱。
USDC→WETH 往返这条路,屏幕价差至少要超过约 60 bps 才可能赚钱。
```

### 问题 2:市场有没有真的给这么多价差

这是「屏幕价差」回答的。

如果市场只给:

```text
屏幕价差 +1 bps
```

那面对:

```text
真实成本 60 bps
```

就明显不够。

## 为什么 `make_evidence.py` 没有自动填跨资产屏幕价差

原因是:同资产和跨资产不是一回事。

### 同资产:USDC -> USDC

对于:

```text
ARB USDC -> BAS USDC
```

起点和终点都是 USDC。

脚本可以粗略抓:

```text
Arbitrum 上 USDC 的 priceUSD
Base 上 USDC 的 priceUSD
```

然后做:

```text
(Base USDC 标价 - Arbitrum USDC 标价) / Arbitrum USDC 标价
```

这就是一个粗略的「标价差」。

所以 `make_evidence.py --fetch-screen` 可以帮同资产路径填一个起步值。

但注意:它会标注 `(标价)`。

因为 LI.FI 的 `priceUSD` 是参考标价,不是你那笔交易真实能成交的价格。

### 跨资产:USDC -> WETH

对于:

```text
ARB USDC -> BAS WETH -> ARB USDC
```

不能拿:

```text
USDC 的 priceUSD
WETH 的 priceUSD
```

直接相减。

因为它们不是同一种资产。

真正要看的是:

```text
Arbitrum 上 1 WETH = 多少 USDC
Base 上 1 WETH = 多少 USDC
```

也就是两条链上的 `WETH/USDC` 可成交价格差。

这需要读链上 AMM 池,而不是简单读 LI.FI 的 token 标价。

所以跨资产那两行没自动填,不是脚本坏了,而是脚本没有替你乱猜。

## 怎么获取当前屏幕价差

当前项目里用 [`pool_price.py`](../../pool_price.py) 查链上 AMM 池的中间价。

命令:

```bash
python3 pool_price.py --chains ARB,BAS --base USDC --quote WETH --min-tvl 500000
```

这句话的意思是:

```text
查 Arbitrum 和 Base 两条链
用 USDC 计价
看 WETH 的价格
只保留 TVL 至少 500,000 USDC 的池子
```

输出里重点看最后这一段:

```text
>> 跨链价差 ARB→BAS(各取最深池)
   ARB Uniswap V3 fee500: 1,910.19
   BAS Uniswap V3 fee3000: 1,910.39
   价差 +1.05 bps
```

它的含义是:

```text
Arbitrum 最深池里,1 WETH 约等于 1910.19 USDC
Base 最深池里,1 WETH 约等于 1910.39 USDC
Base 比 Arbitrum 贵约 1.05 bps
```

这次观察下,屏幕价差就是:

```text
+1.05 bps
```

## 怎么用它判断净收益

假设 `evidence.csv` 里跨资产往返成本是:

```text
USDC→WETH 1000:
真实成本 60.64 [49.24~73.31] bps

USDC→WETH 10000:
真实成本 60.65 [43.92~71.71] bps
```

而 `pool_price.py` 当前查到:

```text
屏幕价差 +1.05 bps
```

那净收益粗算就是:

```text
1000 规模:
+1.05 - 60.64 = -59.59 bps

10000 规模:
+1.05 - 60.65 = -59.60 bps
```

这说明:

```text
当前这一刻不成立。
```

注意这里说的是"当前这一刻",不是说永远不成立。

要判断是否可复现,还要看历史上一段时间内屏幕价差有没有经常超过成本门槛。

---

## 为什么还要看链内离散度

`pool_price.py` 不只输出跨链价差,还会输出「场所间离散」。

例如:

```text
Base 存活 5 个池
价格 1,904.25 ~ 1,910.39
场所间离散 32.25 bps
```

这句话很重要。

它的意思是:

```text
在同一条 Base 链上,不同池子的 WETH/USDC 价格就已经差了 32.25 bps。
```

如果跨链价差只有:

```text
+1.05 bps
```

而同链不同池子的差都有:

```text
32.25 bps
```

那这个跨链价差就不是一个强信号。

你不能只说:

```text
Base 比 Arbitrum 贵 1 bps。
```

因为换一个 Base 池子比,结论可能就变了。

所以脚本会提醒:

```text
这个跨链价差小于链内场所间离散度。
```

新手可以先记住:

> 如果跨链价差还没有同链不同池子的价格差大,那这条信号很弱。

## 怎么获取历史屏幕价差

`pool_price.py` 只能看当前这一刻。

如果要补三天监控期间的历史价差,用 [`price_history.py`](../../price_history.py)。

命令:

```bash
python3 price_history.py --chains ARB,BAS --base USDC --quote WETH \
  --since 2026-08-03T08:34:00Z --csv price_history.csv
```

这句话的意思是:

```text
从 2026-08-03 08:34 UTC 开始
拉 Arbitrum 和 Base 上 WETH/USDC 的逐小时价格
算每个小时的跨链价差
导出到 price_history.csv
```

为什么起点用 `2026-08-03T08:34:00Z`?

因为这是正式服务器监控开始的时间。

前面本地调试的数据不应该混进正式样本。

---

## `price_history.py` 需要什么

`price_history.py` 用 The Graph 拉历史池子价格。

所以需要 `.env` 里有:

```text
THE_GRAPH_KEY=你的 key
```

如果没有 key,脚本会跑不起来。

当前项目里 `lib/graph.py` 就是封装 The Graph 查询用的。

## 获取后怎么填回 evidence.csv

### 只做当前一次观察

如果你只跑了一次:

```bash
python3 pool_price.py --chains ARB,BAS --base USDC --quote WETH --min-tvl 500000
```

得到:

```text
价差 +1.05 bps
```

可以先在 `evidence.csv` 的跨资产两行里手填:

```text
屏幕价差bps: +1.05(可成交中间价,单次)
净收益bps: -59.59
成败原因: 当前可成交中间价差只有约 +1.05 bps,远低于约 60 bps 的往返成本门槛;且链内场所离散度大于跨链价差,信号弱。
可复现: 当前单次观察不成立;需历史价差序列确认
```

但这只能说明"这一刻不成立"。

### 做完整历史判断

如果你跑了:

```bash
python3 price_history.py --chains ARB,BAS --base USDC --quote WETH \
  --since 2026-08-03T08:34:00Z --csv price_history.csv
```

然后看到输出类似:

```text
跨链价差 ARB→BAS 共 N 小时
最小 ...
中位 ...
最大 ... bps
为正 .../N 小时
跨链价差绝对值超过同期链内离散度的小时数 ...
```

这时可以把 `屏幕价差bps` 填成区间:

```text
最小 ~ 最大(可成交中间价,逐小时)
```

再和真实成本区间对比。

判断逻辑:

```text
如果屏幕价差大部分时间 < 真实成本:
  可复现地不成立

如果屏幕价差偶尔 > 真实成本:
  偶发窗口,需要更细粒度监控

如果屏幕价差经常 > 真实成本:
  可复现地成立,值得进入下一阶段验证
```

## 新手最容易犯的错

### 1. 把 `priceUSD` 当成可成交价格

`priceUSD` 是标价,不是你真能成交的价格。

表里如果写 `(标价)`,就代表这只是参考。

### 2. 只看价差,不扣成本

屏幕价差不是利润。

必须扣掉:

```text
桥费
gas
DEX 手续费
滑点
失败交易成本
资金占用
执行延迟风险
```

这个项目先把前几项压成了 `真实成本bps`。

### 3. 拿不同池子的价格乱比

同一条链上不同池子的价格可能差很多。

如果你用:

```text
Arbitrum 的一个深池
Base 的一个浅池
```

去比,可能会凭空造出一个假机会。

所以 `pool_price.py` 会用 `--min-tvl` 过滤僵尸池,并提醒链内场所离散度。

### 4. 用单点结论写成长期结论

一次 `pool_price.py` 只能说明当前这一刻。

要写「可复现」,应该用 `price_history.py` 拉历史序列,或者继续定时采样。

---

## 最小操作流程

新手可以按这个顺序来:

```bash
# 1. 先看当前 WETH/USDC 跨链可成交价差
python3 pool_price.py --chains ARB,BAS --base USDC --quote WETH --min-tvl 500000

# 2. 如果只是单次观察,把最后的「价差 xx bps」手填进 evidence.csv

# 3. 如果要判断可复现,拉历史价差
python3 price_history.py --chains ARB,BAS --base USDC --quote WETH \
  --since 2026-08-03T08:34:00Z --csv price_history.csv

# 4. 再把历史价差区间和 watch 得到的真实成本区间对比
```

## 一句话总结

真实成本回答:

```text
这条路至少需要多少价差才可能赚钱?
```

屏幕价差回答:

```text
市场现在或历史上有没有给过这么多价差?
```

只有当:

```text
屏幕价差 > 真实成本
```

并且这个现象能重复出现时,才有资格写成:

```text
可复现地成立
```

否则就只能写:

```text
可复现地不成立
```

或者:

```text
成本门槛可复现,套利是否成立未判定
```
