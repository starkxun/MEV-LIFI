> 打卡日期:2026-08-07
> 脚本:[`cost_model.py`](../../cost_model.py)、[`delay_risk.py`](../../delay_risk.py)

## 先给结论

共学文档说这是「整个共学最值钱的东西」。公式长这样:

```
净收益 = 屏幕价差 − 桥费 − 滑点 − gas − 延迟风险 − 失败交易成本 − 资金占用
```

七项。做完之后的状态:

```
桥费/协议费 + 滑点   [实测]   25.00 bps
gas + 未含费用       [实测]    0.02 bps
延迟风险             [实测]    0.61 bps  ← 之前是空的
资金占用             [公式]    0.00 bps  ← 之前是空的
失败交易成本         [待定]      —      ← 测不了,老实空着
────────────────────────────────────
合计(不含待定项)             25.64 bps
```

> 那个 `0.61` 一开始跑出来是 `0.00`,**而且是错的** —— 详见第四节坑 5。
> 一个"看起来很合理的零",查出来是采样分辨率的产物。

**这个脚本的核心不是把七项加起来,是给每一项标上证据等级。**

## 一、开工前先立一条规矩

大多数人写成本模型是这么干的:

```
桥费     实测 25 bps
滑点     实测 0.02 bps
失败概率 假设 5%
资金成本 假设年化 10%
延迟风险 假设 2 bps
─────────────────────
净收益   +3.47 bps      ← 精确到小数点后两位
```

**这是把猜测包装成计算。**

三个假设值里只要有一个偏了 50%,那个 `+3.47` 就可能变成负的。而**你看着那个精确的小数点,会以为自己算过了。**

> **参数测不出来的成本模型,没有价值。**
>
> 你整个项目的方法论都在反对这个 —— 25 bps 实测过、60 bps 采样 157 次、
> 日内周期做了置换检验。**不该在最后一步破功。**

所以正确的开工顺序不是「把七项都填上」,而是:

**先问每一项能不能测。不能测的就标「待定」,不填假设值。**

## 二、逐项过一遍:能测吗

### 已经有的三项(不用重做)

| 项 | 怎么来的 |
|---|---|
| 桥费/协议费 | `/quote` 的 `feeCosts`,实测 25.00 bps 且已定位是 LI.FI 服务费 |
| 交易滑点 | 规模扫描出来的成本曲线(摊薄型 vs 冲击型) |
| gas | `gasCosts`,而且和硬成本**分栏**不混算 |

**注意桥费和滑点在 LI.FI 的报价里是合在一起的** —— `toAmount` 已经把两者都扣掉了。所以脚本里它们是一行,不硬拆。硬拆需要额外假设,反而不诚实。

### ① 延迟风险 —— 能测,这是这次的主要工作

公式里写的是「执行期间价差消失的概率 × 损失」。听起来很抽象,但换个问法就具体了:

> **我这条路要跑 T 秒,这 T 秒里价差通常会跑多远?**

关键是找到**秒级精度的价格数据**。The Graph 的 `swaps` 实体正好有:

```
Swap 实体字段: id, transaction, timestamp, pool, ..., sqrtPriceX96, tick, ...
```

**每一笔成交都是一个精确到秒的价格快照。**

而且有个很好用的性质:

> **AMM 的价格只在有人成交时才变**,两笔成交之间价格恒定。

所以 swap 序列**就是完整的价格路径**,不需要插值 —— 只要取「t+T 时刻之前最后一笔成交的价格」。

跑出来的结果:

```
    延迟 │  不利侧(该进成本模型)              │ 绝对变动
   (秒)  │  中位    75%    90%    95%        │  中位    95%
      7  │  0.00   0.00   0.01   0.61        │  0.00   1.40
     30  │  0.00   0.00   1.19   2.56        │  0.00   4.03
    300  │  0.00   3.71   9.09  12.69        │  3.57  16.87
   1080  │  0.00   7.56  15.20  20.08        │  7.67  27.81
   1859  │  0.00   9.58  19.94  27.63        │  9.46  30.86
```

（24 小时窗口、12,325 个观测点。**这是修完坑 5 之后的数** —— 修之前 7s 那行全是 0.00。）

**从一句话变成了一张可查的表。**

#### 为什么量「价差」不量「单边价格」

第一版我量的是单个池子的价格漂移。**方向错了** —— 你赚的是**两条链之间的价差**,不是单边价格。

两条链的价格一起涨,你的套利不受影响;只有**价差收窄**才是损失。

所以默认模式改成:在两条链成交时刻的**公共时间网格**上算
`spread(t) = (P_bas − P_arb) / P_arb`,再看它 T 秒后跑多远。

#### 为什么用 95% 分位而不是中位数

看那张表的中位数那一列:**全是 0.00**。

因为大部分时候价差压根不动。**风险全在尾部。** 用中位数会得出「延迟风险 = 0」这种荒唐结论。

> **成本模型该用保守值。分布是长尾的时候,中位数没有意义。**

#### 为什么只取「不利侧」

价格朝有利方向跑不是风险,是运气。所以脚本把变动拆成两侧,只把**不利那一侧**放进成本模型。绝对变动那一列只作参考。

### ② 资金占用 —— 能算,但要找一个可观测的利率

```
资金占用成本 = 本金 × 年化机会成本 × (延迟 / 一年)
```

延迟有(`executionDuration`),本金你自己定,**只有「年化机会成本」需要外部输入**。

拍脑袋填「假设 10%」就前功尽弃了。**改成读链上真实数据**:

```
Aave V3 的 currentLiquidityRate(USDC 存款年化)
  ARB  2.37%
  BAS  3.37%
```

**理由**:那是你不做套利时,同一笔钱躺着能拿到的、**链上可查的真实收益**。

算出来:

```
1080 秒 × 2.37% = 0.01 bps
```

**小到可以忽略 —— 而这本身就是个结论。**

> 对秒级/分钟级的路径,资金占用根本不是问题。
> 它只在**资金锁几天**时才咬人 —— 比如有挑战期的桥(Optimism 原生桥 7 天)。
>
> **算出「可以忽略」和「没算」是两回事。** 前者是结论,后者是缺口。

### ③ 失败交易成本 —— 测不了,而且要说出来

```
失败交易成本 = 失败概率 × (已花 gas + 占用的资金)
```

**「失败概率」你现在拿不到**,因为你从来没真实执行过。

有个容易搞混的地方:157 轮监控里 **0 次报价失败**。但那是**报价成功率**,不是**执行成功率** —— 报价成功不代表交易能上链、能成交、桥不会卡。

可能的替代品和它们的局限:

| 替代 | 局限 |
|---|---|
| LI.FI `/status` 端点(`PENDING/DONE/FAILED`) | 要有真实交易才有状态可查 |
| 那个 Solana 原子套利机器人的 94.3% 失败率 | **不能套用** —— 原子套利失败成本≈0,跨链不是 |

**所以这一项明确标「待定」。** 脚本会在输出里反复提醒:

> 只要 失败概率 × 单次失败损失 > 你算出的净收益,就依然是负的。


**16 倍的性价比。** 之前只知道该快,现在知道快值多少钱。

## 四、写脚本时踩的五个坑

### 坑 1(最危险):主成本项缺失时还打印合计

跨资产单程模式下,桥费/滑点是**无法定义**的(10000 USDC 减 5.34 WETH 没意义)。第一版会这样输出:

```
桥费/协议费 + 滑点        —     [无法定义] 跨资产单程
gas + 未含费用          0.03
延迟风险                2.43
─────────────────────────────
合计(不含待定项)        2.46 bps      ← 危险
```

**一个漏掉大头的合计,比没有合计危险得多** —— 它看起来像个可用的数字。

现在改成拒绝给出:

```
合计:**拒绝给出** —— 主成本项(桥费/滑点)在跨资产单程下无法定义。
      加 --roundtrip 让路径闭合回起点,减法才重新成立。
```

> **可迁移的一条:宁可拒绝输出,也不要输出一个有缺口的汇总数字。**

### 坑 2:TVL 最高的池子 ≠ 价格发现最活跃

我先用 Base 的 fee3000 池(TVL 1.12 亿,最高)量延迟风险,结果:

```
04:46:33   1,900.1833   −0.0528 WETH  +100.64 USDC
04:45:07   1,900.1830   +0.1008 WETH  −190.96 USDC
04:43:23   1,900.1835   −0.1005 WETH  +191.54 USDC
```

**这个池子被一个 ~$190 的乒乓交易占满了**,价格在 `1900.1830 ↔ 1900.1835` 之间来回摆(0.003 bps)。

用它量出来的延迟风险**假得离谱地低**。

> **选数据源时,「大」和「有信息量」是两回事。**

### 坑 3:同一秒有多笔成交时保留错了那笔

实测 200 笔里有 **33 个时间戳有多笔成交**。降序拉取时,该保留的是「那一秒最后的价格」= 降序里**第一次遇到**的那笔。我原来的写法会被后面的旧价格覆盖。

### 坑 4:我又编了两个池子地址

`fee100` 和 `fee10000` 是我凭印象写的,查出来一个查询失败、一个 0 笔成交。

**这是这个项目里第二次犯同样的错**(上次是 Base 的 fee10000)。已改成从 factory 合约现取。

> **地址、ID 这类东西永远不要凭记忆写。** 现取一次的成本远低于事后 debug。

### 坑 5(事后才发现):采样分辨率粗于要测的尺度 → 伪零

上线跑了一天之后才发现的,而且**是从"感觉哪里不对"查出来的**,不是脚本报错。

现象:成本模型算 10k 那条路(7 秒),延迟风险显示 **0.00**。

```
     延迟      样本 │  不利侧  75%   90%   95%
      7    8631  │   0.00  0.00  0.00  0.00     ← 全零
     30    8631  │   0.00  0.00  0.94  2.15
```

看着像"7 秒太短所以没有风险",**其实是工具看不见**。

原因:价差序列建在 **10 秒网格**上,而你查的是 **7 秒**:

```
网格点: 1000, 1010, 1020, ...
查 t0=1000 的 7 秒后 → t0+7 = 1007
取"≤1007 的最后一个网格点" → 1000   ← 就是起点自己
差值恒等于 0
```

**所有 T < 网格步长的行,结构上必然是 0。**

最坑的地方:**它还报 `n=8631`** —— 一个大样本量,让人觉得这个 0.00 很可信。

> **可迁移的一条:采样分辨率必须细于你要测的尺度。**
> 拿 10 秒网格测 7 秒变化,答案必然是 0。那不是"没有风险",
> 是"这个工具看不见"。
>
> 而且注意它的伪装:**结构性产物 + 大样本量**。这和之前那几个坑是同一族——
> 未初始化的池报出 1.8e22 的价格、回测算出 100% 成功率,
> **都是"看起来合理但实际是产物"的数字**。

修法:网格自动收紧到最小 horizon;`T < 网格` 时明确标「不可测」而不是给 0。

修完之后 7 秒那行从 `0.00` 变成 `0.61`,连带证据表的完整成本也都变了:

```
                执行成本   完整成本(修前)  完整成本(修后)
稳定币 10k       25.02      25.02          25.63
跨资产往返 1k    60.69      63.87          63.68
```

## 六、evidence.csv 每一栏是什么意思

回头看表时最容易出问题的地方:**分不清哪一列是实测、哪一列是判断、哪一列是估计**。
逐栏说明。

### 完整表头

```
时间 | 链 | 资产 | 类型 | 规模 | 路径 | 观测次数 |
屏幕价差bps | 执行成本bps | 完整成本bps | 净收益bps | 延迟秒 | 成败原因 | 可复现
```

### 逐栏含义

| 栏位 | 含义 | 谁填 | 硬度 |
|---|---|---|---|
| **时间** | 观测窗口的起止(不是单个时刻) | 脚本 | 事实 |
| **链** | `源链→目标链` | 脚本 | 事实 |
| **资产** | `源资产→目标资产` | 脚本 | 事实 |
| **类型** | 跨链 / 同链 / 跨链·往返 / … | 脚本 | 事实 |
| **规模** | 测试本金 | 脚本 | 事实 |
| **路径** | 走过的桥/DEX **及各自次数**(如 `eco×130, polymerStandard×12`) | 脚本 | 事实 |
| **观测次数** | 这一行背后有几个采样点 | 脚本 | **读其它列前先看这个** |
| **屏幕价差bps** | 市场表面给你的价差,**还没扣成本** | **人工** | 看标注 |
| **执行成本bps** | 桥费 + 滑点 + gas。**你确定要付的钱** | 脚本 | 实测 |
| **完整成本bps** | 执行成本 + 延迟风险 + 资金占用 | 脚本 | 实测+估计 |
| **净收益bps** | 屏幕价差 − 成本(括号里标了用哪个口径) | 脚本 | 派生 |
| **延迟秒** | 这条路要跑多久 | 脚本 | 实测 |
| **成败原因** | 为什么成/不成。**写机制不写结果** | **人工** | 判断 |
| **可复现** | 是稳定机会还是一次性噪声 | **人工** | 判断 |

### 「执行成本」和「完整成本」为什么要分成两列

这是 2026-08-07 改的。原来只有一列叫「真实成本bps」,**那个名字在骗人** ——
它暗示"这就是全部成本",但实际只含三项。

```
执行成本 = 桥费 + 滑点 + gas          ← 你**确定要付**的钱
完整成本 = 执行成本 + 延迟风险 + 资金占用  ← 再加上**风险估计**
```

**两者口径不同,不是精度不同。** 分开列的理由:

- 执行成本是**硬的** —— 报价里写着,一分不会少
- 延迟风险是**估计** —— 基于历史分布的 95% 分位,而且只采到了平静行情

混在一列里,你就分不清自己的门槛有多少是确定的、多少是估出来的。

差距有多大取决于延迟:

```
              执行成本    完整成本    差值    延迟
稳定币 10k      25.02      25.02     0.00      7s   ← 快,几乎没差
跨资产往返      60.59      63.71    +3.12     36s
100k 走 polymer 25.00      41.36   +16.36   1080s   ← 差 65%
```

**延迟越长,两个数差得越多。** 这也是为什么「延迟秒」那一列必须和成本一起读。

### 三个读表时的注意事项

**① 先看「观测次数」再看别的。**

`n=1` 和 `n=157` 的同一个数字,含金量差着量级。表里那几行 `n=—` 的是
**孤儿行**(一次性手工观察 / Hermes 记的口径校准),不来自监控,保留但别当统计结果用。

**② 「净收益」括号里的口径标注要看。**

```
-38.44(完整口径)     ← 扣了延迟风险和资金占用
-15.32(仅执行成本)   ← 没扣,偏乐观
```

拿不到延迟风险数据时会退回执行成本口径,**并且明说**。
不标口径的话,两行的净收益不可比却看不出来。

**③ 成本填的是「中位数 [最小~最大]」,不是单点。**

```
25.02 [25.02~25.03]     ← 157 次观测,极稳
60.69 [43.21~73.31]     ← 157 次观测,波动大
```

中位数不用平均数 —— 偶尔一次路由降级会跑出 153 bps 这种极端值,平均数会被拖歪。

### 还有一栏没有:失败交易成本

**表里没有这一列,因为测不了。** 但它是真实存在的成本。

所以读任何一行的「净收益」时,心里都要加一句:

> 这还没扣失败交易成本。只要 失败概率 × 单次失败损失 > 这个净收益,就依然是负的。

## 七、怎么搬到你的清算主业

共学文档特别强调这条(「你今天在跨链上劈的这一刀,原样砍在你的主业上」)。对应关系:

| 跨链搬砖 | Sonic 清算 |
|---|---|
| 桥费 / 协议费 | 清算罚金分成 |
| 交易滑点 | **抵押物变现折价** ← 你的大头 |
| gas | 抢跑竞争的 gas |
| 延迟风险 | 从发现到成交期间价格再变 |
| 失败交易成本 | **被别人抢先** |
| 资金占用 | 垫资时间(**用闪电贷可压到 0**) |

**两条值得注意:**

1. **「抵押物变现折价」就是清算版的滑点。** 而且它可以用同一套方法测 —— 拿抵押物的池子,量「卖出 X 数量会滑多少」,就是 `pool_price.py` 那套。
2. **闪电贷把资金占用压到 0。** 这是 [原子套利那篇](原子套利.md) 里学到的:借币 → 清算 → 卖抵押物 → 还款,打包一笔。**抢不到就整笔回滚,只亏 gas。**

## 新手最容易犯的五个错

### 1. 把假设值和实测值混在一张表里

**最起码要标出来哪些是实测的。** 否则三个月后你自己都分不清。

### 2. 用中位数描述长尾分布

延迟风险的中位数**全是 0**。只看中位数会得出「没有延迟风险」。**长尾分布要看分位数。**

### 3. 算不出来就填一个「保守的假设值」

听起来很负责,实际上还是猜。**「待定」比「假设 5%」诚实,也更有用** —— 它告诉未来的你,这里有个真实的缺口需要补。

### 4. 给列起一个比它实际内容更大的名字

原来那列叫「真实成本」,只含三项。**名字暗示的范围比内容大,就是在误导** ——
包括误导三个月后的你自己。

改成「执行成本」+「完整成本」两列之后,口径自明,不用翻文档才知道含什么。

### 5. 相信一个「合理但没验证过」的零

`延迟风险 0.00 bps` 看起来完全合理 —— 才 7 秒嘛,能有多少变化。
**但合理不等于正确。** 那个 0 是网格分辨率的产物(见坑 5),不是测量结果。

> **判据:一个数字如果"恰好等于 0 / 恰好 100% / 恰好整数",
> 先怀疑它是结构性产物,而不是发现。**
>
> 这个项目里已经栽过三次:回测 100% 成功率、未初始化池的天文数字、
> 现在这个伪零。**三次都是"看起来合理 + 大样本量"的组合。**

## 一句话总结

```
成本模型的价值不在于那个合计数字,在于你知道每个数字有多硬。
```
