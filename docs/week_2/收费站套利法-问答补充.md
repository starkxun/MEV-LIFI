## 1. `lib/graph.py` 是干什么的?

[`lib/graph.py`](../../lib/graph.py) 是项目里的 The Graph 查询客户端。

它主要做三件事:

1. 读取 `THE_GRAPH_KEY`:优先读环境变量,其次读项目根目录 `.env`。
2. 统一发 GraphQL 请求:处理认证、超时、重试和 GraphQL 错误。
3. 管理已验证 subgraph:让其它脚本用 `ARB` / `BAS` / `ETH` 这样的链名查历史数据。

它被 [`price_history.py`](../../price_history.py) 和 [`lp_backtest.py`](../../lp_backtest.py) 复用。前者用它拉历史价格,后者用它回测 V3 LP 仓位。

## 2. 里面说的“注册表”是什么?

“注册表”指的是 `SUBGRAPHS` 这个本地字典,不是系统注册表,也不是链上合约。

它是一张“可信 subgraph ID 清单”:

```python
SUBGRAPHS = {
    "ARB": {"id": "...", "name": "uniswap-v3-arbitrum", "schema": "uniswap-v3"},
    "BAS": {"id": "...", "name": "Uniswap V3 Base", "schema": "uniswap-v3"},
    "ETH": {"id": "...", "name": "Uniswap-V3 (mainnet)", "schema": "uniswap-v3"},
}
```

为什么需要它:

- The Graph 上同名 subgraph 很多,ID 不能靠猜。
- 有的 Uniswap V3 subgraph 用 Messari schema,字段叫 `liquidityPool`,不是标准的 `pool`。
- 有的看起来有 `pool`,但缺 `poolHourDatas`,拉不了小时历史数据。
- 网关偶尔会瞬时失败,所以客户端要重试。

所以注册表里的 ID 需要确认:能查通、schema 匹配、同步健康、价格和 RPC 直读对得上。

## 3. “钱不是直接进池子了吗,怎么还分段?”

钱确实进了池子合约,但在 Uniswap V3 里,它不是“给整个价格轴无限使用”,而是变成一个有价格条件的 LP 仓位。

你提供 LP 时会指定区间,例如:

```text
ETH 价格在 $2,800 ~ $3,200 之间时,我的钱参与交易
超过这个范围,我的钱还在合约里,但不参与当前交易
```

所以:

```text
钱进池子 = 资产托管在合约里
分段 = 这笔资产只覆盖指定价格 tick 区间
活跃 = 当前价格在你的区间内,能赚手续费
不活跃 = 当前价格在区间外,不能赚手续费
```

V2 是默认覆盖 `0 到 ∞` 的整条价格轴。V3 是你自己选一段价格轴。范围越窄,同样本金在这段里的资金密度越高;但价格跑出去就不开张。

## 4. “集中流动性”到底想表达什么?

传统 AMM(Uniswap V2)里,LP 资金被摊在所有可能价格上:

```text
ETH = $1
ETH = $100
ETH = $3,000
ETH = $100,000
ETH = $1,000,000
```

但真实交易通常只发生在当前价格附近。价格在 $3,000 附近时,你摊在 $100,000 那里的资金基本用不到。

V3 让你只把资金放在某个区间:

```text
ETH = $2,800 ~ $3,200
```

结果是:

```text
V2 = 覆盖范围无限,资金效率低
V3 = 覆盖范围自选,资金效率高,但会出区间
```

放到“收费站套利法”里,就是把流动性放在你认为机器人会经过的价格路段上,经过时收手续费;不经过时没有手续费。

## 5. 四档费率 `fee100` / `fee500` / `fee3000` / `fee10000` 是什么?

它们是 Uniswap V3 同一交易对的不同手续费池。

例如同样是 `WETH/USDC`,可以同时有:

```text
WETH/USDC 0.01% 池
WETH/USDC 0.05% 池
WETH/USDC 0.30% 池
WETH/USDC 1.00% 池
```

合约里的 fee 单位是百万分之一:

```text
fee100    = 100 / 1,000,000   = 0.01%
fee500    = 500 / 1,000,000   = 0.05%
fee3000   = 3000 / 1,000,000  = 0.30%
fee10000  = 10000 / 1,000,000 = 1.00%
```

文档里的统计:

```text
fee100    (0.01%)   $3,030,371    35,727 笔
fee500    (0.05%)   $7,691,203    13,843 笔
fee3000   (0.30%)  $31,456,452    19,523 笔
fee10000  (1.0%)       $9,249        78 笔
```

后两列是成交额和交易笔数。它说明一件事:手续费率高不代表 LP 一定赚得多。

LP 手续费大致来自:

```text
手续费收入 = 成交量 × 手续费率 × 我的流动性占比
```

`fee10000` 单笔收 1%,但几乎没人走,所以“收费站很贵,但路上没车”。

## 6. 什么是“刷量”?

刷量就是成交额看起来很大,但可能不是正常用户真实需求,而是人为反复交易堆出来的 volume。

文档里的异常例子:

```text
BNB  1.00%  累计成交 $42,495,616,379  TVL $16,495  ⚠成交额/TVL 过高,疑似刷量
```

问题在于比例离谱:

```text
累计成交 424 亿美元
当前 TVL  1.6 万美元
```

一个只有 1.6 万美元流动性的池子,历史上显示 424 亿美元成交,不一定能 100% 证明造假,但足够说明这个数据不能直接当“真实流量”用。

常见刷量方式:

```text
A -> B
B -> A
A -> B
B -> A
```

同一个人或一组地址反复 swap,每次都会计入 `volumeUSD`,但这些交易未必代表外部真实需求。可能目的是做排名、做项目数据、拿激励、满足空投条件等。

对 LP 来说,不能只看累计成交额。要同时看 TVL、最近成交、交易笔数、价格行为,以及这些成交是否可复现。

## 8. `--range-lo -20 --range-hi -2` 是干什么的?

这两个参数是在模拟 Uniswap V3 LP 的价格区间,单位是“相对建仓价的百分比”。

```bash
--range-lo -20
--range-hi -2
```

意思是:

```text
区间下沿 = 建仓价下方 20%
区间上沿 = 建仓价下方 2%
```

如果建仓价是:

```text
0.33414492 USDT/COAI
```

那么:

```text
下沿 = 0.33414492 × (1 - 20%) = 0.26731593
上沿 = 0.33414492 × (1 - 2%)  = 0.32746202
```

所以输出:

```text
区间 [0.26731593, 0.32746202]
```

单位是:

```text
USDT/COAI
```

也就是:只有当 COAI 价格在 `0.2673 ~ 0.3275 USDT/COAI` 之间时,你的 LP 仓位才活跃并赚手续费。

## 9. “建仓价”是什么?是不是自己创建模拟池子?

不是创建模拟池子。

“建仓”在这里指:在回测开始时间点,假设你拿 `10,000 USDT` 到这个已经存在的 COAI/USDT 池里开一个 V3 LP 仓位。

```text
已有池子:COAI/USDT 1% 池
模拟动作:投入 10,000 USDT
建仓价:回测开始时池子的 COAI 价格
LP 区间:建仓价下方 -20% 到 -2%
```

文档里的命令:

```bash
python3 lp_backtest.py --chain BNB \
  --pool 0x4610464356ba6bba15eec558619d84b72fea260f \
  --capital 10000 --range-lo -20 --range-hi -2 \
  --since 2026-07-29T08:00:00Z --hours 168
```

这里 `--since 2026-07-29T08:00:00Z` 锁定回测开始时间。脚本取这个窗口的第一个小时价格作为建仓价。

## 10. 第 4 步输出怎么读?

输出:

```text
回测结果    COAI/USDT   费率 1.00%
建仓价 0.33414492 USDT/COAI    结束价 0.34299299  (+2.6%)
区间   [0.26731593, 0.32746202]   期间价格 0.317165 ~ 0.345327
时长   100 小时,其中 19 小时在区间内(19%),穿越 12 次
------------------------------------------------------------------------
投入             10,000.00 USDT(单边)
撤池拿回          10,000.00 USDT + 0 COAI  折合 10,000.00 USDT
------------------------------------------------------------------------
① 手续费收入            +4.29 USDT   (+4.3 bps)
② 存货盈亏              +0.00 USDT   (+0.0 bps)
③ gas                  -5.00 USDT
   净收益               -0.71 USDT   **-0.7 bps**
```

逐行解释:

```text
建仓价 0.33414492 USDT/COAI
结束价 0.34299299 (+2.6%)
```

回测开始时 COAI 价格是 `0.3341`,结束时是 `0.3430`,币价小涨 `2.6%`。

```text
区间 [0.26731593, 0.32746202]
期间价格 0.317165 ~ 0.345327
```

你的 LP 只覆盖 `0.2673 ~ 0.3275`。这段时间 COAI 最低到过 `0.3172`,最高到过 `0.3453`,所以价格确实短暂进入过你的区间。

```text
时长 100 小时,其中 19 小时在区间内(19%),穿越 12 次
```

有效小时数据有 100 个点。只有 19 个小时你的 LP 是活跃的。价格进出区间共发生 12 次切换。

```text
投入 10,000.00 USDT(单边)
撤池拿回 10,000.00 USDT + 0 COAI
```

因为区间在建仓价下方,开仓时你是全 USDT。价格中途跌进区间,后来又涨回区间上方,所以结束时又变回全 USDT,没有留下 COAI 存货。

```text
手续费收入 +4.29 USDT
存货盈亏 +0.00 USDT
gas -5.00 USDT
净收益 -0.71 USDT
```

这是一个比较友好的行情:没有被一路砸穿,没有接一堆下跌币。但手续费只有 `4.29 USDT`,还不够覆盖 `5 USDT` gas,最后净亏 `0.71 USDT`。

结论:

```text
良性场景 = 没出大事,但收益太薄
关键风险 = 一旦价格跌穿区间,你会从 USDT 变成 COAI 存货
```

## 11. “只有当 COAI 下跌到区间里,别人才会用 COAI 换走你的 USDT”是不是唯一赚钱方式?

不是。那只是“收费站套利法”这套设定里的赚钱方式。

这套策略的设定是:

```text
单边 USDT
区间放在现价下方
高费率池
等价格跌进区间后发生交易
```

它理想中的赚钱路径:

```text
COAI 当前 0.334
你的区间 0.267 ~ 0.327

价格跌进区间
交易发生,你收手续费
价格又涨回区间上方
你撤池,拿回 USDT
```

但 LP 还有很多其它方式:

- 区间放在现价附近,吃更多交易量。
- 区间放在现价上方,反过来卖币。
- 双边投入,让仓位一开始就在区间内。
- 做低费率深池,靠大成交量赚钱。
- 动态调整区间,主动管理。

真正决定是否赚钱的不是“价格必须跌下来”,而是:

```text
手续费收入 > 存货亏损 + gas + 资金占用 + 其它风险成本
```

在现价下方单边放 USDT,本质上更像:

```text
一串带手续费收入的限价买单
```

赚钱场景:

```text
价格短暂跌进区间 -> 成交并收手续费 -> 价格又涨回去
```

亏钱场景:

```text
价格跌进区间 -> 你逐渐买入 COAI -> 价格继续下跌或跌穿区间
```

所以文档要验证的核心不是“能不能收手续费”,而是“手续费能不能覆盖被动接盘的损失”。
