## 复制这段到服务器

```bash
cd ~/MEV-LIFI && mkdir -p logs

tmux new-session -d -s mev -n stable -c ~/MEV-LIFI \
  "python3 -u watch_probe.py --from-chain ARB --to-chain BAS --token USDC \
     --amounts 1000,10000 --interval 1800 --alert-below 20 2>&1 | tee -a logs/stable.log"

tmux new-window -t mev -n roundtrip -c ~/MEV-LIFI \
  "python3 -u watch_probe.py --from-chain ARB --to-chain BAS \

     --roundtrip --interval 1800 --alert-below 25 2>&1 | tee -a logs/roundtrip.log"

tmux ls
```

三天后每条路径每个规模约 **144 次观测**,足够下判断了。

## 每个参数为什么这么设

### `python3 -u` —— 关掉输出缓冲

输出一旦经过管道(`| tee`),Python 会切换成块缓冲,**日志可能几小时才刷一次**。
`-u` 强制不缓冲。

> 这个坑很隐蔽:你在终端里跑得好好的,一挂到后台就"没输出了",
> 以为程序挂了,其实只是没刷出来。

### `tee -a logs/` —— 日志文件是唯一的事后凭据

**实测过**:命令一旦退出,tmux 会连窗口带滚动历史一起销毁。
如果没写文件,进程为什么退出的、退出前报了什么,全都查不到。

用 `-a`(追加)不用覆盖,重启监控时不会洗掉之前的日志。

### `--interval 1800` —— 半小时一轮

限速完全不是瓶颈:每 30 分钟 2–4 次请求,而允许的是 **100 次 / 60 秒**。
间隔设更短也行,但半小时的采样密度对"这条路平时什么样"已经够用。

### `--alert-below` —— 阈值要设在"真信号"上

| 路径 | 阈值 | 为什么 |
|---|---|---|
| 稳定币 | 20 bps | 25 bps 是**固定费率地板**。跌破 20 意味着 LI.FI 改了费率结构 —— 那才是真信号 |
| 跨资产往返 | 25 bps | 实测区间 22–43 bps,25 能捞到偏好的那一侧 |

**稳定币那条如果设 25 会天天响,等于没设。** 告警设在"日常水平"上就是制造噪声,
三天后你会开始无视所有通知 —— 那时候监控就白做了。

## 三个限制

### 1. tmux 扛得住断线,扛不住重启

SSH 断了没事,服务器重启就没了,要手动拉起来。

真要长期无人值守,cron 更稳 —— `watch_probe.py` **省略 `--interval` 就是单次模式**,
每次独立进程,一次挂了下次照跑:

```cron
*/30 * * * * cd ~/MEV-LIFI && python3 watch_probe.py --from-chain ARB --to-chain BAS --token USDC --amounts 1000,10000 >> logs/stable.log 2>&1
```

跑几天用 tmux 完全够,不用折腾这个。

### 2. 两个进程不会打架

各写各的文件:`ARB.USDC-BAS.USDC.jsonl` 和 `ARB.USDC-BAS.WETH-rt.jsonl`,
checkpoint 也是分开的。

### 3. 单轮异常不会杀掉循环

网络抖动、限速会打一行日志然后继续跑 —— 这是 [`lib/chainkit.py`](../../lib/chainkit.py)
里 `run_loop` 的异常隔离在起作用。

但**如果日志里连续几十行都是异常**,那是真出问题了(比如 API 变更、网络持续不通),
值得去看一眼。偶尔几行正常,连续几十行不正常。

## 回来之后

```bash
cd ~/MEV-LIFI
python3 make_evidence.py --dry-run          # 先看,别直接覆盖
python3 make_evidence.py --fetch-screen
```

它会打印判定建议,那时候跨资产那行的「可复现」就有依据填了。

**重点看跨资产的方差比稳定币大多少** —— 这个对比本身就是一条结论:

- 稳定币的成本来自**固定费率**(不随市场变)→ 方差应该接近 0
- 跨资产的成本来自**市场撮合 + 实时路由**→ 方差应该明显大

如果三天后跨资产的方差**也很小**,那反而是个意外发现,值得追问为什么。
