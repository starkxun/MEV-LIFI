## 1. 本次到底拉了哪些数据

这次数据分两大类。

### A. 成本数据:watch/*.jsonl

成本数据来自 [`watch_probe.py`](../../watch_probe.py)。

它每半小时问一次 LI.FI:

```text
这条路径现在能不能走?
走什么桥/聚合器?
1000 和 10000 两个规模分别要多少成本?
预计多久?
有没有上游报价异常?
```

本次主要有两个文件:

| 文件 | 路径 | 含义 |
|---|---|---|
| `watch/ARB.USDC-BAS.USDC.jsonl` | ARB USDC → BAS USDC | 同资产跨链,稳定币对照组 |
| `watch/ARB.USDC-BAS.WETH-rt.jsonl` | ARB USDC → BAS WETH → ARB USDC | 跨资产往返闭环 |

`jsonl` 的意思是:

```text
一行 = 一次观测
```

### B. 价差数据:price_history.csv

价差数据来自 [`price_history.py`](../../price_history.py)。

它拉的是链上 AMM 池的历史价格:

```text
Arbitrum 上 1 WETH = 多少 USDC
Base 上 1 WETH = 多少 USDC
```

然后逐小时计算:

```text
Base 的 WETH/USDC 价格 相对 Arbitrum 贵/便宜多少
```

本次导出了:

```text
price_history.csv  共 72 行
```

也就是 72 个小时点。

## 2. 为什么要同时拉成本和价差

判断套利不能只看一个数字。

你需要同时知道两件事:

| 问题 | 对应数据 | 它回答什么 |
|---|---|---|
| 这条路要付出多少摩擦? | `watch/*.jsonl` | 真实成本门槛 |
| 市场有没有给出足够价差? | `price_history.csv` | 屏幕价差 |
| 扣完以后还剩不剩? | `evidence.csv` | 净收益和可复现结论 |

核心公式是:

```text
净收益bps = 屏幕价差bps - 真实成本bps
```

如果:

```text
屏幕价差 > 真实成本
```

才可能有正收益。

如果:

```text
屏幕价差 < 真实成本
```

那就是看起来有价差,但扣完成本不成立。

---

## 3. 为什么跨资产要用往返闭环

同资产路径很好算:

```text
ARB USDC → BAS USDC
```

投入和到手都是 USDC。

所以:

```text
真实成本 = 投入 USDC - 到手 USDC
```

跨资产路径不一样:

```text
ARB USDC → BAS WETH
```

投入是 USDC,到手是 WETH。

如果只看这一段,你会立刻遇到问题:

```text
我到底亏了多少 USDC?
```

这需要折算 WETH 价格,一旦价格口径错,成本就会错。

所以本项目用往返闭环:

```text
ARB USDC → BAS WETH → ARB USDC
```

这样终点又回到 USDC。

公式变成:

```text
硬成本 = 起点 USDC 数量 - 往返回来后的 USDC 数量
```

这就是"同一种资产口径"。

## 4. 本次成本观测结果

正式统计时切掉了本地调试数据:

```bash
python3 make_evidence.py --since 2026-08-03T08:34:00Z
```

原因是调试数据不是正式观测。

如果不切掉,一次调试时跑出的极端值会污染区间,让人误以为机会更好。

### 成本汇总表

| 路径 | 规模 | 观测数 | 真实成本bps | 成本极差 | 路由特点 | 上游异常 |
|---|---:|---:|---:|---:|---|---:|



```text
最高成本 - 最低成本
```


```text

```

这说明它主要是固定费率结构,不是市场撮合导致的波动。

跨资产往返路径:

```text

```

这说明它受实时路由、DEX 成交、桥选择影响更大。

## 5. 本次屏幕价差结果

`price_history.csv` 里的核心列是:

| 列 | 含义 |
|---|---|
| `ARB_price` | Arbitrum 上 1 WETH 等于多少 USDC |
| `BAS_price` | Base 上 1 WETH 等于多少 USDC |
| `spread_bps` | Base 相对 Arbitrum 的 WETH/USDC 价差 |
| `BAS_disp_bps` | Base 同链不同池子的价格离散度 |

每一小时的跨链价差公式:

```text
spread_bps = (BAS_price - ARB_price) / ARB_price * 10000
```

为什么乘以 `10000`?

因为:

```text
1 bps = 0.01%
10000 bps = 100%
```

### 手算一行

第一行数据:

```text
ARB_price = 1838.028775
BAS_price = 1833.479067
```

代入:

```text
(1833.479067 - 1838.028775) / 1838.028775 * 10000
= -24.753 bps
```

含义是:

```text
这一小时 Base 上的 WETH 比 Arbitrum 便宜约 24.75 bps。
```

### 72 小时价差汇总

| 指标 | 数值 | 含义 |
|---|---:|---|
| 小时数 | 72 | 共 72 个逐小时价格点 |
| 最小价差 | -26.31 bps | Base 最便宜的一小时 |
| 严格中位价差 | +3.51 bps | 72 个值排序后中间两个的平均 |
| 脚本打印中位 | +3.77 bps | 当前脚本取排序后第 37 个值 |
| 最大价差 | +26.49 bps | Base 最贵的一小时 |
| 为正小时数 | 42/72 | 58% 的小时 Base 更贵 |
| Base 链内离散度中位 | 14.76 bps | Base 同链不同池子的价格差中位数 |
| 超过同期链内离散度 | 21/72 | 只有 29% 小时价差强过同链噪声 |

这里有两个关键点。

第一:

```text
最大屏幕价差只有 +26.49 bps。
```

第二:

```text
跨资产往返成本中位数约 60.6 bps。
```

所以屏幕价差远远不够覆盖成本。

## 6. 链内离散度是什么意思

这是新手最容易忽略的一列。

跨链价差说的是:

```text
Arbitrum 和 Base 两条链之间价格差多少
```

链内离散度说的是:

```text
同一条链上,不同池子的价格自己就差多少
```

如果:

```text
跨链价差 = 5 bps
链内离散度 = 15 bps
```

那这个跨链价差就很弱。

因为同一条链内部换个池子,价格差都比跨链差大。

本次数据:

```text
只有 21/72 小时,跨链价差绝对值超过同期 Base 链内场所离散度。
```

这说明:

```text
多数时间里,所谓跨链价差还没有同链池子之间的价格差大。
```

所以不能把屏幕价差当成稳定信号。

注意一个局限:

```text
这次 ARB_disp_bps 为空,因为 Arbitrum 备选池在该时段没有足够小时成交数据。
所以这里主要是在和 Base 链内离散度比较。
```

这个局限不推翻结论。

如果 Arbitrum 也有可用离散度,取两条链的最大离散度,只会让"超过离散度"的小时更少或相同。

## 7. 怎么从成本和价差算净收益

净收益核心公式:

```text
净收益bps = 屏幕价差bps - 真实成本bps
```

但填表时要小心:不要拿两个极值拼一个不存在的最好情况。

例如:

```text
最大屏幕价差 = +26.49 bps
最低成本 = 43.92 bps
```

如果直接算:

```text
26.49 - 43.92 = -17.43 bps
```

这只是一个"极限乐观检查":

```text
即使用历史最大价差碰上历史最低成本,仍然是负的。
```

但它不一定真实发生在同一小时。

所以 `evidence.csv` 里净收益区间采用更稳的教学口径:

```text
净收益区间 = 屏幕价差区间 - 成本中位数
```

### 跨资产 1000 USDC

数据:

```text
屏幕价差: -26.31 ~ +26.49 bps
成本中位: 60.64 bps
```

计算:

```text
最差净收益 = -26.31 - 60.64 = -86.95 bps
最好净收益 = +26.49 - 60.64 = -34.15 bps
```

填表:

```text
净收益bps = -86.95 ~ -34.15
```

### 跨资产 10000 USDC

数据:

```text
屏幕价差: -26.31 ~ +26.49 bps
成本中位: 60.65 bps
```

计算:

```text
最差净收益 = -26.31 - 60.65 = -86.96 bps
最好净收益 = +26.49 - 60.65 = -34.16 bps
```

填表:

```text
净收益bps = -86.96 ~ -34.16
```

两个规模的最好净收益都小于 0。

所以:

```text
跨资产往返路径可复现地不成立。
```

## 9. 本次处理流程复盘

完整流程是:

```text
1. 服务器半小时拉一次 LI.FI 报价
2. watch_probe.py 写入 watch/*.jsonl
3. make_evidence.py 汇总成本分布
4. price_history.py 拉 72 小时 WETH/USDC 历史价格

8. 填 evidence.csv

```

对应命令:

```bash
# 成本汇总,切掉正式监控前的调试数据

# 历史屏幕价差
python3 price_history.py --chains ARB,BAS --base USDC --quote WETH \
  --since 2026-08-03T08:34:00Z --csv price_history.csv
```

## 10. 新手要记住的几条原则

### 1. 一次报价不是结论

一次报价只能叫采样。

三天半小时一次,得到 142 次观测,才有资格讨论:

```text
稳定不稳定
区间多宽
路由是否频繁切换
是否可复现
```

### 2. 成本和机会不是一回事

成本稳定只能说明:

```text
门槛稳定。
```

但机会是否成立要看:

```text
屏幕价差是否长期大于成本。
```

### 3. 不要把标价当成交价

LI.FI 的 `priceUSD` 是参考标价。

真正更硬的来源是链上池子的可成交中间价,也就是 `price_history.csv` 和 `pool_price.py` 使用的口径。

### 4. 不要用极值编故事

最大价差和最低成本不一定发生在同一时刻。

所以它们相减只能做极限检查,不能当常态收益。

### 5. 负结论也是成果

本次最重要的成果不是"找到机会",而是:

```text
排除了两条路径。
```

这能避免以后继续在明显不成立的路径上浪费时间。
