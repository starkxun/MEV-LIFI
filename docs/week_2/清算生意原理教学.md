<a name="第一部分"></a>
## 第一部分:一笔清算里到底发生了什么

### 1.1 清算的规则(为什么会有钱赚)

借贷协议(Aave / Spark / Morpho…)允许你抵押 A、借出 B。协议持续算一个**健康因子**:

```
健康因子 HF = Σ(抵押品价值 × 清算阈值) / Σ(债务价值)
```

`HF < 1` 时仓位可清算。这时**任何人**都可以:

1. 替借款人还掉一部分债务 B;
2. 从借款人的抵押品里拿走**等值的 A,外加一笔清算奖励**(通常 5~8%)。

这笔奖励就是全部利润的来源。**注意三件事:**

- **规则完全公开** —— HF、阈值、奖励比例全在链上,谁都能算;
- **机会完全确定** —— 不是"我猜价格会涨",是"这个仓位现在就能清";
- **谁先上链谁拿走** —— 同一个仓位只能被清算一次。

> 这三条合起来,决定了这门生意的一切。**第三部分会证明:它们必然导致利润被竞价拿走。**

### 1.2 一笔真实交易的完整流程

真实交易 `0x84cc7f25…f9a06a`(SparkLend,2026 年):

```
① Balancer 闪电贷借出 2,285.98 USDT           ← 零本金,手续费 0
② SparkLend 清算:还 USDT 债务
                → 拿走 0.04128684 cbBTC
③ 把 cbBTC 卖给 Wintermute(走 Bebop RFQ)
                → 收回 2,285.978 USDT + 0.098983 WETH
④ 还 Balancer 2,285.978 USDT                  ← 借多少还多少,USDT 净变化精确为 0
⑤ 付 0.005838 WETH 给做市商                    ← RFQ 报价里的费
⑥ 解包 0.09314553 WETH → 全额转给区块构建者      ← 关键的一步
```

**整笔交易是原子的:任何一步失败,全部回滚,只亏 gas。**

第 ⑥ 步是这个研究里最容易被漏掉的一步 —— 我第一版就漏了,后面第四部分会讲为什么它这么难看见。

### 1.3 五个角色,别搞混

| 角色 | 地址 | 干什么 |
|---|---|---|
| **签名者 EOA** | 17 个轮流用 | 只负责签名、发交易、付 gas,余额 0.1~0.6 ETH |
| **执行合约** | `0xf0570ec4…` | 闪贷 + 清算 + 换币 + 还款,全部原子完成 |
| **借款人** | 被清算的那位 | 抵押品被拿走 |
| **做市商** | Wintermute `0x51c72848…` | 通过 Bebop RFQ 接下抵押品,给出可原子执行的报价 |
| **区块构建者** | 每块不同 | 决定这笔交易能否进块、排在第几位 |

**为什么要 17 个 EOA?** 因为 nonce 是串行的:

```
1 个 EOA:  nonce 5 卡住 → 6、7、8 全堵在后面
17 个 EOA: 互相独立,一个卡住不影响其他 16 个
```

> ⚠️ **但别照抄这个理解:** 实测这 17 个 EOA 只有 **78%** 的交易发给这台清算机器人,
> 其余发给同一运营方的另外三台机器人。**它是一个共享签名池,不是这台机器人的专属钱包。**
> 我一开始写成"100% 专属",差点把别的机器人赚的钱记到清算头上。

### 1.4 合约里没有策略

反编译执行合约后最重要的发现:**合约里一行策略代码都没有。**

```solidity
function xd8f7ffd4(LenderCfg lcfg, ExecCfg ecfg, uint256 coinbaseTip) {
    lcfg.exchange   = 0..5    → 打哪个借贷协议
    lcfg.flashType  = 0..2    → 从哪借闪电贷
    ecfg.calls[]    = 任意调用 → 变现路径由链下算好传进来
    coinbaseTip               → 给构建者多少,也是链下算好传进来
}
```

**它是一个配置驱动的执行器。** 哪个仓位能清、借多少、怎么变现、出价多少 —— 全部在链下算好、当参数塞进来。

> **推论:清算没有秘密策略。** 规则、机会、奖励全部公开,
> **edge 不在"发现",在"执行"。** ——
> 但第三部分会说明,"执行"这个 edge 也值不了多少钱。

## 第二部分:毛机会从哪来,又进了谁的口袋

### 2.1 先定义清楚三个词

这三个词混用是我犯下所有错误的根源,**务必分清**:

| 词 | 定义 | 在 1.2 那笔里 |
|---|---|---|
| **毛机会** | 卖掉抵押品所得 − 还掉的债务 | 0.098983 WETH |
| **竞价** | 付给区块构建者换排序的钱 | 0.09314553 WETH |
| **落袋** | 真正归运营方的钱 | 0.005838 WETH |

**「毛机会」不是利润。「合约自留 0」也不等于没赚钱**(转发型合约会把利润转给别的地址)。

### 2.2 钱的四个去处(40 笔实测)

对 `0xf0570ec4` 的 40 笔交易逐笔用 `trace_transaction` 拆开:

```
毛机会合计               1,306.07 WETH   (100%)
├─ 闪电贷费                   0.00        0.00%
├─ gas(EOA 另付)             0.09 ETH    0.01%
├─ 付给区块构建者           656.22       50.2%
└─ payout → Wintermute      649.85       49.8%
   合约自留                    0.0028      0.00%
```

**闪电贷费 0.00%** —— 38 笔里 21 笔走 Balancer(免费),17 笔走 Aave V3(0.05%,收在借出的稳定币上,换到 WETH 口径两位小数都进不去)。

**这就是「用闪电贷不就覆盖成本了吗」的答案:它已经在用了,而且那根本不是主要成本。**

### 2.3 而 50/50 这个平均数掩盖了真相

按毛机会规模分档,**留存率(= payout / 毛机会)完全不同**:

```
毛机会   0~1  WETH   n=12   留存   2.8%
毛机会   1~5  WETH   n=11   留存   1.8%   ← 中位数 2.68 WETH 落在这一档
毛机会   5~20 WETH   n= 6   留存   2.6%
毛机会  20~100 WETH  n= 5   留存   9.0%
毛机会 100~∞  WETH   n= 4   留存  62.5%
```

翻译成人话:

- **做中位大小的清算,98% 的钱被竞价拿走** —— 一单赚约 $92,一天 1.24 单,约 **$114/天**;
- **38 笔里的 4 笔大单,贡献了 96.8% 的利润**(约 $120 万 / 39 天)。

> **整门生意就是那 4 笔。** 剩下 34 笔基本是白做。

### 2.4 竞价是「恒定比例」,不是「固定地板」

这个区别决定打法,必须分清。逐笔看竞价占毛机会的比例:

```
毛机会 0.0776 → 99.6%      毛机会  2.71 → 98.8%
毛机会 0.3552 → 99.5%      毛机会 14.29 → 97.8%
毛机会 1.4000 → 99.8%      毛机会 42.58 → 93.6%
                  <20 WETH 的 29 笔:中位 98.8%
```

从 0.08 到 84 WETH,**比例基本是常数 ~98%,与规模无关**。

如果是"固定地板"(比如每笔至少要付 0.5 ETH),形状应该是小单比例极高、大单被摊薄 —— **不是这个样子**。

断点在 100 WETH 附近,而且很陡:

```
 84.76 → 87.3%
105.82 → 84.1%
137.02 → 44.5%   ← 悬崖
294.86 → 37.6%
468.21 → 24.8%
```

**这不是"大单摊薄了固定成本",是"大单没人跟你抢"。**

## 第三部分:为什么是这个分法(这部分最值得理解)

### 3.1 一条经济学规律

> **当一项投入被商品化(所有人都能零成本获得),租金就会流向剩下的那个稀缺要素。**

套到清算上:

| 要素 | 稀缺吗 | 谁拿走租金 |
|---|---|---|
| 资本 | ❌ 闪电贷让它免费 | 无人 |
| 信息(哪个仓位能清) | ❌ 链上公开,规则确定 | 无人 |
| 代码能力 | ❌ 模板化,合约里没有策略 | 无人 |
| **区块排序权** | ✅ **一个区块只有一个第一位** | **区块构建者** |

所有人都能执行同一笔清算 → 唯一的差别只剩谁出价高 → 公开拍卖把价值拍到接近 100% 归拍卖人。

**这就是 98% 的来源。它不是某个环节效率低,是竞争均衡的必然结果。**

### 3.2 所以闪电贷是反向的

直觉是「闪电贷降低成本 → 利润变多」。实际相反:

```
闪电贷把入场资本门槛降到 0
      ↓
所有人都能参与同一个公开、确定的机会
      ↓
竞价把价值拍到接近 100% 归构建者
```

**闪电贷消除的是「失败成本」和「资本成本」,不是「竞争成本」。**
它甚至加剧竞争 —— 你能零成本参与,别人也能。

> **闪电贷是入场必备、但不产生任何优势的东西** —— 因为所有对手都有。
> 这类东西在商业分析里叫 **table stakes**,不是护城河。

### 3.3 那大单为什么能留住 62.5%?

**因为闪电贷解决入场,不解决出场。**

那笔留存 62.5% 的交易,抵押品是 **15,131 WETH(约 $2,900 万)**。要在同一笔原子交易里把它变现,你需要一个做市商肯给这个量的可执行 RFQ 报价。

- 入场(借 $2,900 万):闪电贷免费,人人可得;
- 出场(原子卖掉 $2,900 万):**只有少数几家做市商接得住**。

能执行的对手变少 → 拍卖的第二高价掉下来 → 竞价掉到 24.8%。

> **一句话:竞争发生在出场能力上,不在入场能力上。**

这也解释了为什么这台机器人的**利润收款地址就是 Wintermute 本身** ——
它不是"顺手赚一笔"的对手方,**它的报价能力本身就是入场券**。

### 3.4 全市场验证:凡是竞价为 0 的地方,要么没有价值,要么没有出口

横扫 30 天、5 类协议、717 条清算事件,竞价 ≈ 0 的情形只有四类:

| 场景 | 为什么没人抢 | 你能赚到吗 |
|---|---|---|
| **尘埃单** —— 有人在清 $1.08 的仓位 | 没有钱 | ❌ |
| **Euler v2 荷兰拍** —— 折扣从 0 往上爬 | 竞争在**折扣空间**,价值退回借款人 | ❌ 折扣被压掉 |
| **Morpho 长尾抵押品** —— `AVLT`、`PT-`、`ILLIQUID_PERPD` | **没有原子出口**,要接非流动库存 | ⚠️ 需自有资金 + 价格风险 |
| **Compound III `absorb`** | 那一步本就不产生利润 | ❌ |

最有说服力的一组对照,来自同一批 Morpho 大额清算:

```
$981,636  抵押品 AVLT(RWA)          竞价 0.00021 ETH
$151,917  抵押品 ILLIQUID_PERPD       竞价 0
$ 23,994  抵押品 cbBTC(可变现)       竞价 0.44454 ETH = 规模的 3.54%
```

**一到能原子变现的地方,竞争立刻回来。**

> ### 这一节的核心
>
> **凡是存在可原子变现出口的地方,竞价就会把价值吃掉;
> 凡是竞价为 0 的地方,要么没有价值,要么没有出口。**

### 3.5 构建者会退钱吗?会,但只有 1.1%

有人会想:报出去的钱,构建者不是会按边际贡献退一部分吗?

实测(方法见 4.5):

```
上一代机器人全生命周期  竞价支出 585.32 ETH / 299 笔
                        refund   6.37 ETH /  18 笔   → **1.1%**
当前这一代              551 天 refund = **0**
```

**refund 补不回来。** 三情景法里,"保守场景"就是实测场景。

<a name="第四部分"></a>
## 第四部分:怎么量它 —— 链上测量的五个陷阱

> 这部分的价值**超出清算本身**,任何链上资金流分析都会踩到。

### 陷阱 1:原生 ETH 转账不产生任何日志

给构建者的钱走的是:

```solidity
block.coinbase.call{value: coinbaseTip}("");
```

**这是原生 ETH 转账,不 emit 任何 event。** receipt 的 logs 里一个字都没有。

**只要你的工具建立在"扫日志"之上,它就有一整类看不见的资金流。**

> **修法:只能上 `trace_transaction`(或 `debug_traceTransaction`),没有别的路。**
> ```python
> tr = rpc(eth, "trace_transaction", [txhash])
> bid = sum(int(x["action"]["value"], 16) for x in tr
>           if x["type"] == "call" and x["action"]["to"] == block_miner)
> ```

### 陷阱 2:WETH9 的 deposit/withdraw 不发 `Transfer`

```solidity
// WETH9 实际实现
function withdraw(uint wad) public {
    balanceOf[msg.sender] -= wad;
    msg.sender.transfer(wad);
    Withdrawal(msg.sender, wad);      // ← 只有 Withdrawal,没有 Transfer!
}
```

所以「WETH 的 Transfer 净变化」**不等于** WETH 余额变化。正确公式:

```
WETH 余额变化 = Transfer 净额 + Deposit − Withdrawal
```

### 陷阱 3:两个盲点会合谋,把错误伪装成一个漂亮的数

这是本次最阴险的一个。把陷阱 1 和 2 叠在一起:

```
做市商 → 合约   +G       (Transfer,看得见)
合约 → 做市商   −f       (Transfer,看得见)
withdraw(T)              (Withdrawal,看不见)     T = 竞价
合约 → 收款地址 −(S−T)    (Transfer,看得见)      S = G−f
───────────────────────────────────────────────
Transfer 净变化 = G − f − (S−T) = **T**
```

**残差恰好等于竞价。** 于是脚本输出了一个"看起来完全合理的利润分布"
(中位 2.658 WETH、基尼 0.728、38/40 为正),还能通过所有 sanity check ——

**而它测的其实是「付给构建者的钱」,和利润正好是相反的东西。**

> 已在 tx `0xefe4f89f…` 上 wei 级验证:
> Transfer 净变化 `0.536620432662676339 WETH`,
> trace 实测付给 coinbase `0.536620432662676339 ETH`,**差值为 0**。

### 陷阱 4:同一个地址既是交易对手又是收款方 —— 按**位置**认,不按**地址**认

这台机器人的利润收款地址(存储槽读出来的)就是 Wintermute,
**而 Wintermute 同时是它的 RFQ 做市商**。所以"转给这个地址的 WETH"里混着两样东西:

- 抵押品**卖出腿**(可以有 15,131 WETH 那么大)
- 真正的利润 **payout**

三种口径,前两种都错:

| 口径 | 结果 | 错在哪 |
|---|---|---|
| 单向求和 | 27,466 WETH | 把卖出腿当利润 |
| 取净额 | 被换币方向带偏 | 抵押品是 WETH 时符号翻转 |
| **「解包之后」那笔** | **649.85 WETH ✅** | 对应合约里一行确定的执行顺序 |

合约的出账顺序是固定的:

```
…换币… → withdraw(coinbaseTip) → 打给构建者 → transfer(收款地址, payout)
```

**所以 `WETH.Withdrawal` 之后那笔转给收款地址的,才是 payout。** 两代机器人验证:

```
第三代 0xefe4f89f   解包  0.536620 → 之后 OUT  0.006600  = payout
第二代 0xcadcbc27   解包 29.188298 → 之后 OUT 23.286174  = payout
                    (解包**之前**那笔 817.251709 是卖出腿)
```

> **关键原则:口径要有物理依据。**
> 最后那个之所以对,是因为它对应合约里一行确定的执行顺序,
> **不是因为它的数看着舒服。没有机制依据的口径,选出来的都是你想要的答案。**

### 陷阱 5:给构建者的钱有**两条通道**

```
付给构建者 = block.coinbase 直接转账(trace,无日志)
           + 优先费 gasUsed × (effectiveGasPrice − baseFeePerGas)
```

这台机器人走前者,很多清算人走后者。**只算一条会把另一种打法的人误判成"不付钱"。**

### 附:两个非陷阱但很好用的技巧

**① 识别构建者 refund,不要用地址名单**

地址名单一定过期,新构建者一定会漏。用结构性特征:

> **一笔 builder refund,它的 `from` 就是包含它的那个区块的 fee recipient。**

构建者在自己出的块里给搜索者打钱 —— 这个签名几乎不可能伪造。
实测很干净:17 个 EOA 的 73 笔 ETH 入账里,只有 18 笔满足。

**② 反常样本先读 `symbol()` / `name()`**

那 21 笔"零竞价大额清算"的抵押品叫 `ILLIQUID_PERPD` ——
**名字直接说了它为什么没人抢。** 比任何推理都快。

<a name="第五部分"></a>
## 第五部分:我犯的错,和它们的共同模式

本次一共翻车三轮。按**错误类型**归类比按时间顺序更有用:

### 类型 A:测量口径错误(测了 X 却以为是 Y)

| 错误 | 后果 |
|---|---|
| 把「gas 成本」当"为速度付费" | 算出 ≈0%,分子分母是同一个东西 |
| 把「Transfer 净变化」当利润 | 实际测到的是竞价,**结论符号相反** |
| 把「转给收款地址的 WETH」当利润 | 27,466 vs 649.85,**差 40 倍** |

> **共同点:程序不报错,输出看起来完全正常。**
> 这个项目里最危险的 bug 从来不是崩溃,是**看起来正常的错误输出**。

### 类型 B:样本与口径的偏差

| 错误 | 后果 |
|---|---|
| 「17 个 EOA 100% 专属这台机器人」 | 实际 78%,差点把别人的 refund 记过来 |
| 「162 天做 1,456 笔 ≈ 9 笔/天」 | 162 天是**最近 200 笔**的跨度,1,456 是**生命周期**总数,两个数不能相除 |
| 「1.2 笔/小时」 | 是 1.2 笔/**天**,单位看错,差 24 倍 |
| 只按"竞价低"筛清算人 | 排在最前的是清 $1.08 仓位的尘埃机器人 |
| 按 emitter 分层取样 | AaveV2 拿到 172 个名额(全是尘埃),大额 Aave V3 只分到 9 个 |

> **共同点:分子和分母来自不同的总体。**
> **任何比例,先问一句:分子分母是不是同一批东西?**

### 类型 C:推理错误

**① 荒谬的中间结果是免费的报警器,别急着把它调顺**

`refund / 竞价 = 5907%` 这个数本身没用,但它逼我回头查 EOA 归属,
才发现"17 个 EOA 专属"是错的。
**如果当时随手换个分母让它"看起来合理",就会得出完全相反的结论。**

**② 漂亮的中间结果比荒谬的更危险 —— 因为它不报警**

上一代机器人跑出「自留 22.96 WETH、为速度付费 92.6%」,看着就像"上一代能赚钱",
差点写进结论。拆开发现 **22.96 全部来自单独一笔**,其余 39 笔是尘埃。

**③ 错误前提 + 正确直觉 = 最难自查的错误结论**

我从「竞价 100%」推出「利润一定在链下的 RFQ 定价里」——
前提错了(竞价其实 50.2%),方向却对了(利润确实归 Wintermute)。
**方向对会让人停止怀疑**,比纯粹的错更难发现。

> **验证结论时要单独验前提,不能因为结论看着对就放过。**

### 类型 D:下结论的边界

- **"不可观测"往往只是"没查够"。** 群友的 PDF 查了 1 个 EOA 就判定
  refund 链上测不到;查全 17 个就查到了 18 笔。
- **要下「不可行」的结论,得把最有利的样本也测了。** 当前这代 refund=0
  只能说明这一代;找到唯一有 refund 的上一代、实测 1.1% 之后才算有证据。
- **"没找到"要写清楚方法的盲区。** 私有订单流的定义就是链上不可见,
  所以本方法**先天**证明不了它不存在。结论只能写
  「这些清算人没有表现出私有优势」。

## 第六部分:结论

### 6.1 这门生意是什么样的

```
清算 = 用闪电贷零本金抢公开的固定折扣
     → 原子变现给做市商
     → 把大部分折扣竞价给区块构建者换排序

利润 = 毛机会 − 竞价
     小单:毛机会 2.68 WETH,留存 1.8%  ≈ $92/笔   → 不是生意
     大单:毛机会 468 WETH,留存 62.5%             → 生意全在这里
```

### 6.2 三条路,都验到底了

| 路 | 结论 |
|---|---|
| **更快发现机会** | ❌ 不是瓶颈。38 笔里 29 笔都被竞到 98%,**大家都发现得了** |
| **规模** | ✅ 真实存在,但入场券是单笔 **$250 万~$620 万**的原子变现能力 |
| **私有订单流** | ⬜ 30 天全市场数据里**没有出现**(方法有先天盲区,只能说"没表现出") |
| **接非流动抵押品** | ⚠️ 数据里浮出来的第四条,但**这不是套利** —— 是信贷/库存生意 |

### 6.3 最该记住的一句

> **闪电贷解决入场,不解决出场。而竞争发生在出场能力上。**

「抄它的实现蓝图」和「抄它的商业模式」是两回事:
**前者可抄(闪电贷 + RFQ + 原子回滚 + 多签名者池,都是工程),
后者需要你本身就是做市商。**

### 6.4 这条线的边界

- 30 天、单链、5 类协议、**平静行情** —— 实测约为三年均值的 **1/6**;
- 同一台机器人在 6 月单笔吃过 15,131 WETH 抵押品,而 7~8 月全市场最大只有 $182 万;
- **清算是波动的函数。上面所有数字都是下界:平静期 1/6,级联期 100 倍以上。**

> **2026-08-09 补:另一个必须撤回的结论。**
> 「主流市场清算竞争者只有 2~3 个」来自 Base 链 2 天样本,**是错的**。
> 三年数据:Aave V3 **183 个**、Compound V3 **184 个**、Morpho **159 个**独立清算人。
> 我们自己 30 天全市场扫描也数出 36 个清算合约,同一量级。

如果将来要重开这条线,唯一值得做的是:**找一段大跌窗口重跑
[`liquidator_scan.py`](../../liquidator_scan.py)**,看极端行情下这些比例会不会变。
但即使变了,3.1~3.3 那个经济学结构不会变 —— **它不依赖行情,依赖竞争结构。**
