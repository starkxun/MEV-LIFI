## 先给结论

追完一整条线,最有价值的产出是这一句:

> **清算没有秘密策略。规则、机会、奖励全部链上公开 —— edge 全在执行,不在发现。**

这句话的证据是一份**反编译出来的机器人源码**:合约里**一行策略代码都没有**,协议、金额、变现路径全部由链下算好、当参数传进来。

修正之后,还要补上更硬的第二句:

> **edge 在执行,而执行的钱一半买了排序、一半归了做市商。** 实测毛机会里 **50.2% 付给区块构建者、49.8% 转给 Wintermute**,合约自留 0。
> 而且这个分法**随机会规模剧变**:中位大小的清算 98% 被竞掉,100+ WETH 的大清算能留下 62.5%。**生意全在尾部。**(第十三节)

顺带得到:
- 一份**可抄的清算实现蓝图**(闪电贷 + RFQ 变现 + 原子回滚 + 多签名者池)
- ~~一个反直觉的实测:主流市场清算竞争者只有 2~3 个~~ —— **这条的支撑没了**,见第九节
- 一个已经落地的决策:**放弃 Sonic**(你自己查的数据 + Aave 官方提议关闭部署)

## 一、开工前:归因拆分需要「多笔」,不是「一笔」

任务写的是"还原**某笔**公开可验证交易",但真正目标是:

> 哪些能力来自**策略**,哪些来自**基础设施**,哪些只是某个**时间窗口的运气**。

**一笔交易分不出这三样。** 它们的签名是统计性的:

| | 怎么显形 |
|---|---|
| **运气** | 极少数交易贡献绝大部分利润(集中度高、基尼大) |
| **基础设施** | 每笔都稳定为速度付费、失败率有特征 |
| **策略** | 单笔经济学稳定(中位 ≈ 均值)、路径重复 |

所以顺序是:**先算分布,再挑代表性的单笔去还原。**

> **挑单笔时挑中位数附近的,不要挑最赚的那笔。**
> 最赚的那笔恰恰是运气,拿它还原会写出一篇好看但没有代表性的报告。

## 二、第一个发现:那份榜单不是「套利者名单」

Dune 那张表叫 `Highest priority fee spending addresses` —— **"谁最舍得为插队付钱"**,不是"谁最会套利"。

223 个地址,分类前 14 名之后:

```
14 个地址
├─ 5 个 三明治(jaredfromsubway×2, Wintermute, Kayle×2)   ← 是 MEV,但不是套利
├─ 5 个 路由/散户机器人(Banana Gun, Maestro, Uniswap Frontend×2, SCP)
├─ 1 个 代币合约(Tether_USD 本身)
└─ 3 个 值得看
```

**78% 和套利无关。** 而且排第一的 Banana Gun(占全网优先费 13.9%)之所以第一,**是因为它有最多散户用户 —— 费是用户付的**,和套利能力毫无关系。

> **可迁移的一条:榜单的排序依据决定了它能回答什么问题。**
> 「付费最多」≠「最会赚钱」。用之前先问一句:这个排序是按什么排的?

## 三、行为分类器:先判断类型,再算利润

对一个三明治机器人算「套利利润」是没有意义的。所以先分类。

**关键发现:只用事件的 `topic0` 就够分类**,不需要 ABI、不需要解码参数、不需要 trace:

| 要判断的 | 靠什么 |
|---|---|
| 用了哪些 DEX | `Swap` 事件的 topic0 |
| 有没有闪电贷 | Aave/Balancer/Morpho 的 `FlashLoan` topic0 |
| 是不是清算 | `LiquidationCall` topic0 |
| 是不是三明治 | **同一区块内该合约出现 ≥2 次** |
| 成功率 | receipt 的 `status` |

成本:每笔一次 `eth_getTransactionReceipt`。

**验证有效**:分类器把 `jaredfromsubway` 判成三明治 —— 那正是它的公开身份;把 `Tether_USD` 判成非交易类 —— 它确实是代币合约。

### 分类器写错的三个地方(都是静默错误)

**① 事件签名字典错了三处**

```
我原来写的                          实际是
0xefefaba5… = Balancer FlashLoan    Aave V3 FlashLoan
0x2170c741… = curve_swap            Balancer Swap
0x2b3d9c1b9e2b1a0e0e3a… = bal_swap   ← 这个哈希是我编的
```

最后一个:那串 `1a0e0e3a0d5f6a7b8c9d0e1f2a3b4c5d6e7f8091a2b3c4d5e6f7` 规律递增,一眼就是假的。**这是本项目里第三次凭记忆写地址/哈希。**

现在全部改成 `Web3.keccak(text=签名)` 现算。

**② `FlashLoan` 同名不同签名**

Aave V2 / Aave V3 / Balancer / UniV3 四个版本参数不同,`topic0` 完全不同。**只记一个会漏掉四分之三。**

**③ 判断顺序错了 —— 最要命的一个**

第一版把「没有 swap 就是非交易类」排在最前面,结果一个**做了 7 次闪电贷**的地址被判成「非交易类」。

而它恰恰是整批里最值得看的那个。

> **「没有 swap」≠「没做交易」。** 它换币走的是 Bebop(RFQ),不发 AMM 的 `Swap` 事件。

修法两层:
- 用 **aToken 的 mint/burn/transfer** 当"借贷协议侧动作"的证据 —— 清算时抵押物易手一定留痕
- 算**未识别事件占比**,超过 50% 就警告「分类可能不准」,不硬下结论

**这三个 bug 是同一类:沉默地给出一个错误分类。** 和之前踩的伪零、天文数字价格、100% 成功率同族 —— **这个项目里最危险的 bug 从来不是崩溃,是看起来正常的错误输出。**

## 四、锁定目标:`0xf0570ec4…` 闪电贷清算机器人

分类结果:**13 次闪贷 + 8 次清算,成功率 100%**。

### 画像(40 笔样本,2026-08-08 用 trace 重跑)

```
活动    1,456 笔总交易   成功 199/200 (99.5%)   ≈1.24 笔/天
毛机会  合计 +1306.07 WETH   中位 +2.682   均值 +32.652
        为正 38/40   最大 +468.21
        **均值/中位 = 12.2×** → 右偏极严重,机会大小几乎全在尾部
集中度  top1 17.7%  top3 48.2%  top10 88.6%   基尼 0.728(按竞价口径)

毛机会去哪了(这一块是修正后新增的,原版整个是错的):
        毛机会合计     1306.0671 WETH
        付给区块构建者   656.2177 WETH  (50.2%)  38/40 笔非零
        payout→Wintermute 649.8466 WETH  (49.8%)
        合约自留           0.0028 WETH
        gas(EOA 支付)     0.0933 ETH
```

> **注意口径:「毛机会」不是利润,「合约自留 0」也不等于没赚。**
> 这是个转发型合约,利润转给了收款地址。上面 payout 那一行是**按日志位置**
> 认出来的(解包之后那笔),不是按地址求和 —— 两者差 40 倍,见第十三节。
>
> 若只算竞价(旧口径)是「合计 656.22 / 中位 2.658 / 均值 16.406」。
> 计入 payout 后均值/中位从 6.2× 拉到 **12.2×** —— **利润比竞价更集中在尾部**,
> 这正是第十三节那条留存率斜率的统计投影。

### 和 Solana 那个原子套利机器人对比 —— 两种完全不同的形态

| | 清算(ETH) | 原子套利(SOL) |
|---|---|---|
| 成功率 | **99.5%** | **5.8%** |
| 频率 | ~1.24 笔/天 | ~81 笔/小时 |
| 中位单笔毛机会 | 2.68 WETH (~$5,100) | 0.008 SOL (~$1.3) |
| 为速度付费 | **50.2%** | **46%** |
| top3 集中度 | 48% | 58% |

**三个根本差异:**

1. **成功率 99.5% vs 5.8%** —— 清算目标是**确定的**(某仓位健康度跌破 1),抢到就成;原子套利抢的是同一个价差,94% 落空。
2. ~~几乎不为速度付费,说明清算赛道竞争强度远低于原子套利~~ —— **反了,但没反那么多。** 实测清算为速度付出 **50.2%**,和原子套利的 46% 基本同档。**清算的排序竞争不比原子套利轻松。** 原来那个 ≈0% 是脚本口径 bug 骗出来的。
   更要紧的是这个 50.2% 是**平均值,而它掩盖了真相**:小清算 98% 被竞掉,大清算只花 37.5%。见第十三节。
3. **单笔机会差 3 个数量级** —— 清算是「低频大机会」,原子套利是「高频小机会」。这一条仍然成立,而且频率差距比原文更悬殊(1.24 笔/**天** vs 81 笔/**小时**,约 1,500 倍)。

## 六、17 个 EOA 是同一个人 —— 四条证据

```
17 个 EOA,每个调用 13~17 次(分布极均匀)
194/200 笔用同一个方法选择器 0xd8f7ffd4
每个 EOA 发出的交易 100% 都是发给这个 bot 的      ← ❌ 错,实测 78.0%
每个 EOA 的 nonce 只有 85~138(一辈子就干这一件事)  ← ❌ 连带作废
每个 EOA 余额都是 0.1~0.6 ETH(只留够 gas)
```

> **2026-08-08 修正:第三、四条是错的,而且错得有后果。**
> 把 17 个 EOA 发出的全部 1,866 笔交易按目标合约分类:
>
> ```
> 0xf0570ec4…00004  1455 笔  78.0%   ← 清算机器人
> 0x03bd055a…00003   295 笔  15.8%   ← 另一台机器人
> 0xf7dc4ab2…0002     62 笔   3.3%
> 0x1b05437f…dead     38 笔   2.0%
> ```
>
> **这是一个共享签名池,同时服务至少 4 台机器人,不是清算机器人的专属钱包。**
> 「一辈子就干这一件事」的说法也随之作废。
>
> 这个错的代价在第十一节会看到:它会让人把**别的机器人**收到的 refund
> 记到清算机器人头上,直接导致对这门生意盈利能力的高估。

**为什么要 17 个而不是 1 个 —— 因为 nonce 串行:**

```
1 个 EOA:  nonce 5 卡住 → 6、7、8 全部堵在后面
17 个 EOA: 互相独立,一个卡住不影响其它 16 个
```

清算是抢时间的生意,机会出现时要能立刻发出去,不能等前一笔确认。

> **这一条可以直接抄。** 如果你用单钱包发交易,连续机会时会自己堵自己。

## 七、反编译源码:证实「没有秘密策略」

用 dedaub 反编译 `0xf0570ec4…`,拿到 362 行重构源码。

### 它支持的范围

```
6 种借贷协议:  lcfg.exchange = 0..5
4 种闪贷源:    AaveV3 / Balancer / Morpho / Silo 回调
变现:          全部走 AGGREGATOR = 0xbBbB…FAD5F(Bebop)
```

> **2026-08-08 修正:原文这里列了 7 个协议名却说"6 种",而且列表不可靠。**
> `lcfg.exchange = 0..5` 确实是 6 个取值,但 [`source.sol`](../../source.sol) 里
> 硬编码的常量只有 **AaveV3 / AaveV2 / Morpho / Balancer / Radiant / Silo**,
> **没有任何 Compound 地址** —— 原文那两条 Compound 是推测,不是从字节码读出来的。
> 已实测的组合只有 PDF 那三个样本:Aave V3(LINK/USDC、DAI/WETH)和 SparkLend(USDT/cbBTC)。

### 核心:它是一个「配置驱动的执行器」

```solidity
function xd8f7ffd4(LenderCfg lcfg, ExecCfg ecfg, uint256 coinbaseTip) {
    lcfg.exchange   = 0..5   → 打哪个借贷协议
    lcfg.flashType  = 0..2   → 从哪借闪电贷
    ecfg.calls[]    = 任意调用 → 变现路径由链下算好传进来
}
```

**合约里一行策略代码都没有。所有智能都在链下** —— 哪个仓位能清、借多少、怎么变现,全是外面算好塞进来的。

**这就是「没有秘密策略」最硬的证据。**

### 三个值得抄的设计

**① 双重权限模型**

```solidity
require(__approvedOperators[tx.origin], "NotOp");   // 谁能触发
_owner                                              // 谁能改配置 / 提款
```

用 `tx.origin` 白名单管操作员 —— 这正好解释了那 17 个 EOA。加签名者只要 owner 调一次加地址,不用改合约。

**② 利润分账 + 直接给区块构建者小费**

```solidity
IWETH(_wETH).withdraw(coinbaseTip);
_sendNativeToCoinbase(coinbaseTip);              // block.coinbase 直接转账
uint256 payout = numsB[0][n] - coinbaseTip;
IERC20(_wETH).transfer(stor_2_0_19, payout);     // 剩下转到收款地址
```

比抬高 gasPrice 精确 —— 你可以精确控制分给构建者多少。

> **2026-08-08 实测:这个"分账"在实盘里是空的。**
> 40 笔样本中 **38 笔 `coinbaseTip` 非零,合约自留合计 0.0028 WETH** ——
> 也就是 `payout` 基本恒为 0,`coinbaseTip` 吃掉全部。这个设计确实灵活,
> 但运营方选择的参数是「全给构建者」。
>
> 另外两处反编译失真,别照抄这段:
> - **`emit Profit(payout)` 在链上不存在。** 我按 `Profit(uint256)` 现算 topic0
>   (`0x357d905f…9bc8`)去 40 笔 receipt 里找,一条都没有 —— 反编译多写了这行。
> - `stor_2_0_19` 是**存储槽 2**,实测值 = Wintermute(见第五节)。
>   槽 1 = WETH,槽 3 = owner `0xbf826103…113f`。这三个是 `eth_getStorageAt` 读出来的,
>   不是反编译推的。

**③ 变现全部走聚合器,合约不实现任何 swap 逻辑**

`_executeAggregatorSwap` 就是拿链下传来的 calldata 去 `AGGREGATOR.call()`。**换聚合器只要改常量。**

### 两处不能照抄

**① `_forceApprove` 的逻辑是反的**

```solidity
if (amount != 0) {
    require(current == 0, "approve from non-zero to non-zero allowance");
}
```

标准 `forceApprove` 是**先清零再设新值**;这里是"非零时要求当前必须为零" —— **等于第二次授权同一个 token 会直接 revert**。

(反编译可能失真,但如果是真的,这是个会咬人的坑。)

**② 没有滑点保护**

`SwapAction` 结构体里有 `minOut` 字段,但 `_executeAggregatorSwap` **根本没用它** —— 只把 calldata 原样转发,依赖聚合器自己的保护和链下算好的参数。

`buyCollateral(asset, 0, ...)` 那里 `minAmount` 直接传 0。

> **你有合约安全背景,这一条应该在你的版本里补上:执行完检查最终余额 ≥ 预期,否则 revert。**

## 八、所以「能不能抄」

**能,而且六条里五条可抄:**

| 环节 | 它的做法 | 可抄性 |
|---|---|---|
| **零本金** | Balancer 闪电贷 | ✅ 完全可抄,Balancer 闪贷免费 |
| **变现不吃滑点** | Bebop RFQ 卖给做市商 | ✅ 可抄,RFQ 是公开服务 |
| **原子回滚** | 借→清算→卖→还打包一笔 | ✅ 可抄,这是合约写法 |
| **多签名者池** | 17 个 EOA 并行发交易 | ✅ 可抄,多开几个钱包 |
| **覆盖面** | 6 种协议 + 4 种闪贷源 | ✅ 可抄,只是工作量 |
| **速度 / 排序** | 把毛机会 **100%** 报给构建者换排序 | 🚨 **这条不是"拼基础设施",是拼你拿不拿得到 refund** |

> **最后一行是修正后变化最大的一格。** 原版写"只有这条要拼基础设施",
> 语气像是"努努力也能补上"。实测不是:这台机器人把**全部**可见毛机会
> 报了出去,它的净收益来自构建者的**事后 refund**。
> 也就是说,它的真实壁垒不在"发现得快",而在**和构建者的结算关系**
> —— 那是一个你抄不到、也测不到的链下变量。

### 两项改造的价值不一样

**闪电贷 —— 改的是「失败成本」**

```
现在:  自有资金垫付 → 抢输了,钱已经花出去,承担价格风险
之后:  整笔原子回滚 → 抢输了,只亏 gas
```

**这不是省钱,是改变了你能承受的失败率。** 回到成本模型 —— 「失败交易成本」那项现在是 `[待定]`,闪电贷把它直接压到接近 gas。

那个 Solana 机器人能承受 **94% 失败率**,靠的就是这个。

**RFQ —— 改的是「成本的确定性」**

```
走 AMM:  变现折价 = 滑点,事前是估计,事后才知道
走 RFQ:  变现折价 = 报价里写死的,签之前就知道
```

**这把成本模型里的「抵押物变现折价」从"待估"变成"已测"** —— 和做延迟风险时的思路一样。

## 十一、把 refund 逼成一个数(2026-08-08 新增)

脚本:[`refund_probe.py`](../../refund_probe.py)　数据:[`data/refund_f0570ec4.json`](../../data/refund_f0570ec4.json)

修正之后,这门生意剩下的唯一未知数就是:**报出去的钱,构建者退回来多少?**

PDF 的结论是「链上不可观测」。**这个结论下早了。** 它只查了 `0x8d64` 一个 EOA 的普通入账。但 refund 是**链上 ETH 转账**,而且这台机器人有 17 个签名者 —— 钱可能打给任何一个。

### 识别规则:付款人 == 该区块的出块人

不要去维护「已知构建者地址表」,那种表一定过期。用结构性特征:

> **一笔 builder refund,它的 `from` 就是包含它的那个区块的 fee recipient。**

构建者在自己出的块里给搜索者打钱 —— 这个签名几乎不可能伪造。实测很干净:17 个 EOA 的 **73 笔** ETH 入账里,只有 **18 笔**满足,剩下的都是自有资金调拨、gas 供给。(那笔 0.1 ETH 的入账就因为出块人不匹配被正确排除。)

### 结果:refund 确实存在过,但已经停了 551 天

```
refund 合计 6.374503 ETH / 18 笔
  0x95222290…afe5   6.004783 ETH
  0x4838b106…5f97   0.369721 ETH   ← 当前出块量第一的构建者
时间跨度  2025-02-03 01:56 ~ 02:33   ——  **37 分钟之内,全部**

对照:最近 40 笔(2026-06-05 ~ 07-14)
  竞价支出  656.2177 ETH
  同期 refund      0 ETH
```

### 而且这 6.37 ETH 根本不是清算机器人挣的

这是本次最容易踩的坑。refund 那天前后 3 天,17 个 EOA 一共发了 118 笔交易:

```
0x03bd055a…0003   116 笔   ← 另一台机器人
0xf0570ec4…00004    2 笔   ← 清算机器人
```

同窗口清算机器人的竞价支出只有 **0.107915 ETH**。如果按第六节那个"EOA 专属于清算机器人"的错误前提去算,会得出 `6.374503 / 0.107915 = **5907%** 的 refund 率` —— 一个荒谬到必须停下来的数。

**这个荒谬值本身就是那个错误前提的报警器。** 真相是:refund 属于 `0x03bd055a` 那台机器人,和清算业务无关。

### 所以成本模型这一格填什么

```
构建者 refund(清算业务)= 0        ← 有实测支撑,不是保守假设
```

三情景法里,**保守场景就是实测场景**。中性和乐观场景在这台机器人身上**找不到任何链上锚点**。

> ⚠️ **必须同时写清楚这个测量的边界:**
> 它只能证明「**这 17 个地址**没收到 refund」。它证明不了 refund 没有打给
> 一个与机器人无链上关联的地址,更证明不了没走链下结算。
> **报告时写「未发现」,不要写「不存在」。**

### 那它靠什么活着

> **⚠️ 以下这一小节的推理已被第十三节推翻,保留是为了留下推理轨迹。**
> 错因:当时把 payout 整个剔出了分母,以为竞价占毛机会 100%。
> 实测 payout 占 **49.8%** —— 它赚钱,而且赚得不少。
> 但下面那个"利润在 Wintermute 那一端"的方向**猜对了**,只是证据用错了。

清算机器人的收款地址是 Wintermute(第五节),竞价 100% 给构建者、refund 为 0、gas 自付。
纯从链上看,**这台机器人本身不产生利润**。最自洽的解释是:

> 它不是一门独立生意,而是 Wintermute 的一条**订单流管道** ——
> 清算的价值在 RFQ 报价那一端被做市商吃掉了,链上剩下的 surplus 就用来买排序。

如果这个解释成立,那么「抄它的实现蓝图」和「抄它的商业模式」是两回事:
**前者可抄,后者需要你本身就是做市商。**

## 十二、去查那台「拿到过 refund」的机器人(2026-08-08)

第十一节留了个口子:refund 属于 `0x03bd055a…0003`。那就去查它 —— **它是唯一有 refund 实测样本的对象。**

### 先修正一个措辞:这不是「另一台」,是「上一代」

把 17 个共享 EOA 打过的 4 个合约按活跃期排开:

```
0xf7dc4ab2…0002   2024-11-01 ~ 2024-12-13    42 天      66 笔
0x03bd055a…00003  2024-12-13 ~ 2025-02-03    52 天     299 笔   ← 前一代结束当天接棒
0xf0570ec4…00004  2025-01-30 ~ 2026-07-14   530 天   1,455 笔   ← 重叠 4 天后接棒
0x1b05437f…dead   2024-08-28 ~ 2026-07-07   678 天      41 笔   (低频,另一条线)
```

**同一运营方的三代清算机器人,前后接棒。** 所以这是一个**纵向**样本 —— 能看同一门生意随时间怎么变,比横向比两个陌生地址有价值得多。

### 差点又下错结论:一笔异常撑起来的「盈利」

第二代跑出来的画像一开始很漂亮:

```
合约自留 22.9641 WETH   为速度付费 92.6%   40/40 为正   基尼 0.648
```

看着像"上一代是能留下利润的"。**但拆开看,22.9641 WETH 全部来自单独一笔**
(`0x808bdcb7…9bcd`,2025-02-03 01:56),其余 39 笔的自留都是 ~0.00008 的尘埃。

**剔掉那一笔,第二代同样是 ~100% 竞价。** 「92.6%」是被一个异常值拉出来的。

> 这是第 14 条沉淀的第二次应验:**漂亮的中间结果和荒谬的中间结果一样需要拆开看。**
> 只不过荒谬值会主动报警,漂亮值不会 —— 所以它更危险。

### 真正的答案:refund 只补回 1.1%

第二代全生命周期用 trace 逐笔实测:

```
竞价支出   585.3210 ETH / 299 笔   (2024-12-13 ~ 2025-02-03)
refund      6.374503 ETH /  18 笔   (2025-02-03,37 分钟内)
────────────────────────────────────────────
refund / 竞价 = **1.1%**(全生命周期)
                **1.8%**(refund 当天那个窗口)
```

**这就是「中性场景」唯一的实测锚点。** 三情景法现在可以填实数了:

| 场景 | refund/竞价 | 依据 |
|---|---|---|
| 保守 | **0%** | 第三代 551 天实测 |
| 中性 | **1.1%** | 第二代全生命周期实测 |
| 乐观 | ≤1.8% | 第二代最好的那个窗口 |

原来那个"乐观 = 接近边际贡献上限"的设想,**在实测里根本不存在**。

### 结论:refund 补不回来(**但这不等于不赚钱** —— 见第十三节)

```
毛机会 100 
  → 竞价给构建者  −100
  → refund 回来   +1.1
  → gas           −(自付)
────────────────────
净                 ≈ −gas
```

**两代机器人、829 笔交易、1,241 ETH 竞价,换回 6.37 ETH。** refund 这条路确实补不回来。

> **但由此推出的「这门生意在链上不产生利润」是错的,已在第十三节撤回。**
>
> 当时的推理是:「竞价 100% + refund 0 = 不赚钱,所以利润一定在链下」。
> 前提错了(竞价其实只占 50.2%),结论碰巧指对了方向(利润确实归 Wintermute),
> **但那是链上的 payout,不是链下的 RFQ 定价。**
>
> 这是本次最值得记的一次:**一个错误前提 + 一个正确直觉 = 一个看起来很有洞察力的错误结论。**
> 它比纯粹的错更难自查,因为方向对了会让人停止怀疑。
>
> refund = 0 这个结论本身不受影响,它是独立测出来的。
> 变的只是它的含义:**refund 不重要,因为利润根本不走 refund 这条路。**

## 十三、拆那笔异常交易,结果推翻了第十一、十二节的结论

第十二节末尾留了个尾巴:第二代有一笔 `0x808bdcb7…9bcd` 自留了 22.96 WETH。拆开它,发现的东西比预期大得多。

### 先说那笔异常本身:是链下参数算错了

```
WETH 进  810.535519  ← Aave 清算拿到的抵押品(还了 1,904,277.96 USDC 债务)
WETH 进    7.800386  ← Wintermute RFQ 找零
WETH 出  787.571951  → Wintermute(卖抵押品)
WETH 出    0.589793  → Wintermute(payout)
withdraw   7.210593  → 全额给出块人 0x4838b106
─────────────────────────────────────────
合约净留  22.963568 WETH
```

合约的分账公式是 `payout = numsB[0][n] − coinbaseTip`,实测 `7.800386 − 7.210593 = 0.589793` ✅ 严丝合缝。

**问题出在链下传进来的 `numsB[0][n]` 只等于「RFQ 找回的 WETH」,没算「没卖掉的抵押品」。** 它手里有 810.54 WETH,只卖了 787.57,差的 22.96 就地搁浅 —— 分账公式根本不知道这笔钱存在。

后来怎么处理的?**4.3 小时后(块 21764125)手工扫走 23.000000 WETH**,转到 `0xb0bb27d8…7072`(既不是 Wintermute 也不是 owner)。**是事后人工兜底,不是自动流程。**

> **可抄的一条:分账不要用链下传进来的数,要用 `balanceOf(address(this))` 现读。**
> 这台机器人恰恰在你打算抄的那个位置埋了雷 —— 而且它自己踩了。

### 但真正重要的是:这笔拆解暴露了我的口径又错了

拆日志时看到这个顺序:

```
[124] WETH OUT  787.571951 → Wintermute      ← 卖出腿
[129] WETH.Withdrawal 7.210593                ← 解包点(给构建者)
[130] WETH OUT    0.589793 → Wintermute  ★    ← payout,在解包**之后**
```

**payout 和卖出腿都转给同一个地址,只能靠日志位置区分。** 我此前试过两种口径,都错:

|---|---|---|

| 取净额 | 被换币方向带偏 | 抵押品是 WETH 时符号整个翻 |
| **「解包之后」那笔** | **正确** | 对应合约的固定出账顺序 |

我当时选了"把 payout 整个剔出分母",于是得出 **「毛机会 100% 给构建者、这门生意不赚钱」** —— **那个结论是错的。**

### 改对之后:这门生意是赚钱的

### 而这才是真正可用的发现:留存率随规模单调上升

**结论:竞价存在一个近似的地板,它不随机会大小等比例放大。**

- 小清算:毛机会 2.72 WETH,**98% 被竞掉**,做一单等于白做;
- 大清算:毛机会 468 WETH 那笔,竞价只花 116,**留下 352**。

**38 笔里的 4 笔大单,贡献了 96.8% 的利润。** 第四节那个「基尼 0.728、top3 占 48%」现在有了机制解释:不是运气,是**只有大单才越得过竞价地板**。

### 对你的决策意味着什么

前面写的「这条路不赚钱」要撤回。修正后的判断是:

> **这条路赚钱,但只在大清算上赚钱,而大清算的入场券是资本和 RFQ 报价。**

```

100+ WETH 毛机会         → 留存 62.5%                      ← 生意在这里

要吃到 100+ WETH 档的机会,得能在一笔里吞下 15,131 WETH 的抵押品并原子变现 —— 那需要做市商级别的 RFQ 额度。**这重新解释了为什么收款地址是 Wintermute:不是"它顺手赚一笔",是它的报价能力本身就是入场券。**

## 十四、「用闪电贷不就覆盖成本了吗」—— 把成本逐项摊开

脚本:[`bid_floor.py`](../../bid_floor.py)　数据:[`data/bid_floor_f0570ec4.json`](../../data/bid_floor_f0570ec4.json)

这是第十三节之后最自然的一个问题,也是这门生意最大的直觉陷阱。

### 实测:闪贷费 0.00%,gas 0.01%,竞价 50.2%

38 笔按毛机会分档,每一项占毛机会的比例:

```

  5~20     6    58.79 │  0.00%   0.03%   97.4%    2.6%

────────────────────────────────────────────────────────
  合计    38  1306.07 │  0.00%   0.01%   50.2%   49.8%
```

闪贷来源:**Balancer 21 笔(fee 0)、Aave V3 17 笔(0.05%,收在借出的稳定币上)**。
换算到 WETH 口径,两位小数都进不去。

**所以「闪电贷 + gas」不到 1%。答案是:它已经在用了,而且已经把能覆盖的全覆盖了 —— 那根本不是主要成本。**

### 反直觉的一层:高竞价恰恰是闪电贷造成的

闪电贷把**入场资本门槛降到 0**;清算机会又是公开的、确定性的(健康度跌破 1,规则对所有人一样)。于是:

> 所有人都能执行同一笔清算 → 唯一差别只剩谁出价高 →
> 公开拍卖把价值拍到接近 100% 归拍卖人(区块构建者)。

**闪电贷消除的是「失败成本」和「资本成本」,不是「竞争成本」。**
它甚至反向加剧竞争:你能零成本参与,别人也能。
**投入被商品化之后,租金流向唯一稀缺的要素 —— 这里稀缺的是区块排序权。**

这也修正了第八节「闪电贷改的是失败成本」那段的语气:那句话本身对,但它当时被当成了利好。实测下来,闪电贷是**入场必备、但不产生任何优势**的东西 —— 因为所有对手都有。

### 竞价不是「地板」,是「比例」—— 这个区别决定打法

原本的猜想是固定地板(小单被地板吃掉、大单摊薄)。**实测不是。**

```
毛机会 0.0776 → 竞价 99.6%      毛机会  2.71 → 竞价 98.8%
毛机会 0.3552 → 竞价 99.5%      毛机会 14.29 → 竞价 97.8%
毛机会 1.4000 → 竞价 99.8%      毛机会 42.58 → 竞价 93.6%
        <20 WETH 的 29 笔:竞价/毛机会 **中位 98.8%**
```

从 0.08 到 84 WETH,**竞价比例基本是常数 ~98%,与规模无关**。
固定地板的形状应该是"小单比例高、绝对值相近" —— 不是这个样子。

真正的断点在 100 WETH 附近,而且很陡:

```
 84.76 → 87.3%
105.82 → 84.1%
137.02 → 44.5%   ← 悬崖
294.86 → 37.6%
468.21 → 24.8%
        ≥100 WETH 的 4 笔:竞价/毛机会 **中位 41.1%**
```

**这不是"大单摊薄了固定成本",是"大单没人跟你抢"。**
竞价掉下来只能因为能执行该规模的对手变少了。而闪电贷对大单同样免费 ——
所以变少的不是**入场**能力,是**出场**能力:原子变现 15,131 WETH 抵押品,
需要做市商肯给这个量的 RFQ 报价。

> **一句话:闪电贷解决入场,不解决出场。而竞争发生在出场能力上。**

### 门槛的具体数字

按 $1,911/ETH(第五节推算):

```
中位那笔  毛机会 2.68 WETH ($5,120) × 留存 1.8% ≈ 0.048 WETH ≈ **$92/笔**
频率 1.24 笔/天                                            ≈ **$114/天**
```

**做中位清算不是生意。** 而 38 笔里那 4 笔大单贡献 628.9 WETH payout(约 **$120 万**),
窗口 39 天。**整门生意就是那 4 笔。**

换算成仓位规模:观测到的「毛机会 / 抵押品」比例在 **3.1%**(WETH 抵押,已扣 Aave 协议清算费)
到 **7.6%**(cbBTC)之间。要够到 100 WETH 毛机会档,得在**单笔**里吃下约
**$250 万 ~ $620 万**的抵押品并原子变现。

这就是第十三节「大额原子变现能力抄不了」那一行的具体数值。

### 所以真正该问的问题变了

不是「怎么把成本降下来」(成本已经是 0),而是:

> **凭什么这笔机会只有你能执行?**

实测只有两个答案能让竞价掉下来:
1. **规模** —— 大到别人的 RFQ 额度接不住(这台机器人走的路,需要做市商关系);
2. **私有订单流** —— 机会压根不公开(不在本次样本里,是另一条线)。

「更快发现」不在列表里 —— 因为 38 笔里 29 笔都被竞到 98%,
说明发现从来不是瓶颈,**大家都发现得了。**

## 十五、去找私有订单流:横扫全市场清算人

脚本:[`liquidator_scan.py`](../../liquidator_scan.py)　数据:[`data/liquidator_scan_30d.json`](../../data/liquidator_scan_30d.json)、[`data/liq_morpho_big.json`](../../data/liq_morpho_big.json)

第十四节留下的问题:能让竞价掉下来的只有**规模**和**私有订单流**两条路。
规模那条已经量清楚了(要做市商级 RFQ 额度)。私有订单流没法从单个地址看出来,
只能横向比:**把所有清算人摆一起,找出系统性不给构建者付钱的,再看他们凭什么。**

窗口:2026-07-09 ~ 08-08(30 天),协议:Aave V2/V3、Spark、Morpho Blue、

**① 给构建者的钱有两条通道,都要算。**

0xf0570ec4 走前者,大多数清算人走后者。只算一条会把另一种打法误判成"不付钱"。

**② 规模必须一起量,否则「竞价为 0」是废信息。**

第一版只按竞价排序,立刻筛出一个"114 笔清算、每笔只付 0.000001 ETH"的地址,

0xfc45f8e3 ( 49笔)  还债 $0.74 / $0.80
```

**全是几美元的尘埃单。没人跟他们抢,因为那里没有钱。**

### 结论:私有订单流在这个样本里不存在,而且「零竞价」有统一解释

30 天、717 笔、36 个清算合约,竞价 ≈ 0 的情形只有四类,**没有一类是免费午餐**:

| 零竞价的场景 | 为什么没人抢 | 你能赚到吗 |
|---|---|---|
| 尘埃单($1 级) | 没有钱 | ❌ |
| Euler v2 荷兰拍 | 竞争在**折扣空间**,价值退回借款人 | ❌ 折扣被压掉 |
| Morpho 长尾抵押品 | **没有原子出口**,要接非流动库存 | ⚠️ 要自有资金 + 承担价格风险 |
| Compound III `absorb` | 那步本来就不产生利润(利润在后续 `buyCollateral`) | ❌ |

> **一条贯穿全部数据的规律:**
> **凡是存在可原子变现出口的地方,竞价就会把价值吃掉;
> 凡是竞价为 0 的地方,要么没有价值,要么没有出口。**
>
> 这和第十四节从单个机器人得出的结论完全一致 ——
> **闪电贷解决入场,竞争发生在出场能力上** —— 现在它在全市场尺度上也成立。

### 所以这条线到此为止

两条候选路,实测结果:

1. **规模** —— 真实存在,但入场券是单笔 $250 万~$620 万的原子变现能力(第十四节)
2. **私有订单流** —— **在 30 天全市场数据里没有出现**

第三条路在数据里浮现了,但它不是"套利":**接非流动抵押品**。
那是一门**信贷/库存生意**,需要自有资金、承担价格风险、按天而不是按区块结算 ——
和"链上套利"是两个行当。要不要进,是另一个决定。

> ⚠️ **边界:** 30 天、单链、5 类协议、平静行情。
> 「没找到」不等于「不存在」—— 尤其私有订单流的定义就是**链上看不见**,
> 本方法只能证明「这些清算人没有在链上表现出私有优势」。

## 沉淀

1. **归因拆分需要分布,不是单笔。** 运气/基础设施/策略,三者的签名都是统计性的。
2. **榜单的排序依据决定了它能回答什么。** 「付费最多」≠「最会赚钱」——那份榜单 78% 和套利无关。
3. **「没有 X 事件」≠「没做 X」。** 可能只是走了你字典没覆盖的场所。工具要能承认自己看不见的东西。
4. **签名、地址、哈希一律现算,不凭记忆写。** 本项目第三次犯。
5. **清算没有秘密策略** —— 反编译源码里一行策略都没有,全在链下配置。**edge 在执行不在发现。**
6. **协议方自己提议关停,是最强的退出信号。**
7. **「失败成本≈0」是一种能力,不是一个数字。** 它决定你敢不敢试错 —— 那个 Solana 机器人靠它承受 94% 失败率。

### 2026-08-08 新增的四条(都是这次修正换来的)

8. **「没有事件」比「事件不认识」更危险。** 沉淀 3 说的是"走了字典没覆盖的场所",
   这次更狠:`block.coinbase.call{value:}("")` 和 `WETH9.withdraw()` 的那笔流出
   **根本不产生任何日志**。只要你的工具建立在"扫日志"之上,它就有一整类
   看不见的资金流 —— **想量原生 ETH 的去向,只能上 trace,没有别的路。**
9. **两个盲点可以合谋,把错误伪装成一个漂亮的数。** 单独漏掉 `Withdrawal`
   或单独漏掉 coinbase 转账,结果都会明显不对;两个一起漏,残差恰好等于竞价,
   于是脚本输出了一个"看起来完全合理的利润分布"(中位 2.658、基尼 0.728),
   还能通过所有 sanity check。**这是本项目至今最隐蔽的一个静默错误。**
10. **别人的报告和你的结论冲突时,先假设错的是自己。** 那份 PDF 只用一笔交易
    就得到了正确结论,而我有 40 笔样本却得到了反的 —— 差别不在数据量,
    在于它老老实实看了资金去向,而我信了一个没验证过的口径。
11. **「自留 0」不等于「没赚钱」,也不等于「赚了」。** 链上能确认的只有
    "全额报给了构建者";refund 要单独去测。**遇到测不到的变量,就把它显式列成
    未知并做情景分析,不要用一个默认值把它糊过去** —— 无论默认成 0 还是默认成满额。
12. **「不可观测」往往只是「没查够」。** PDF 查了 1 个 EOA 就判定 refund
    链上测不到;查全 17 个就查到了 18 笔。**下这种判定之前,先问一句
    「我把可能的接收方都枚举了吗」。**
13. **用结构性特征识别,别用地址名单。** builder refund 的判据是
    「付款人 == 该块出块人」—— 自证、不过期、不需要维护任何白名单。
    凡是要靠"已知地址表"的识别逻辑,都会在你不知道的时候悄悄失效。
14. **荒谬的中间结果是免费的报警器,别急着把它调顺。**
    `refund/竞价 = 5907%` 这个数本身没用,但它逼我回头查了 EOA 的归属,
    才发现「17 个 EOA 专属于清算机器人」是错的。
    **如果当时随手把分母换个口径让它"看起来合理",就会得出完全相反的结论。**
15. **漂亮的中间结果比荒谬的更危险 —— 因为它不报警。**
    第二代跑出「自留 22.96 WETH、为速度付费 92.6%」,看着就像"上一代能赚钱",
    差点写进结论。拆开发现 22.96 全来自**单独一笔**,其余 39 笔是尘埃。
    **合计数必须看分布,均值必须看有没有被一个点撑着。**
16. **纵向比自己,胜过横向比陌生人。** 找到三代同一运营方的机器人接棒关系之后,
    「这门生意随时间怎么变」才第一次可测。**判断一个赛道时,先找同一个玩家的历史,
    再找不同玩家的横切面。**
17. **要下「不可行」的结论,得把最有利的样本也测了。**
    第三代 refund = 0 只能说明第三代不行;找到唯一有 refund 的第二代、
    实测 refund/竞价 = **1.1%** 之后,「refund 补不回来」才算有了证据,
    而不只是一个没查到的空白。

### 二次修正换来的四条(第十三节)

18. **同一个量,换个口径能差 40 倍 —— 所以口径要有物理依据,不能挑"看着合理"的那个。**
    「转给收款地址的 WETH」按地址求和是 27,466,取净额是另一个数,按
    「解包之后」认是 649.85。**最后那个之所以对,是因为它对应合约里一行确定的执行顺序**,
    不是因为它的数看着舒服。**没有机制依据的口径,选出来的都是你想要的答案。**
19. **错误前提 + 正确直觉 = 最难自查的错误结论。**
    我从「竞价 100%」推出「利润在链下的 RFQ 定价里」—— 前提错了,方向却对了
    (利润确实归 Wintermute)。方向对会让人**停止怀疑**,比纯粹的错更难发现。
    **验证结论时要单独验前提,不能因为结论看着对就放过。**
20. **平均值会掩盖分段规律。** 「为速度付费 50.2%」这个数本身没什么用;
    拆成规模分档才看到 1.8% → 62.5% 的斜率,而**生意全在那个斜率里**。
    **看到一个说不清所以然的比例,先按规模、时间、类型拆开看有没有斜率。**
21. **「成本」和「竞争代价」是两回事,别用降成本的思路解竞争问题。**
    闪电贷把资本成本降到 0,实测闪贷费 + gas < 1% —— 然后 98% 的价值
    被竞价拿走。**投入被商品化之后,租金流向唯一稀缺的要素。**
    问「怎么更便宜」之前,先问「凭什么这笔只有我能做」。
22. **区分「固定地板」和「恒定比例」,两者的打法完全相反。**
    地板 → 做大单摊薄它;恒定比例 → 做大单没用,得改变竞争结构。
    实测竞价在 0.08~84 WETH 区间是恒定 ~98%,**只有跨过 100 WETH 才掉**,
    而那是因为对手接不住,不是因为摊薄。
23. **筛选指标必须和「值不值得」一起看,否则筛出来的全是垃圾。**
    只按「竞价低」排序,排在最前的是清 $1.08 仓位的尘埃机器人。
    **任何"成本低/竞争小"的筛选,都要先乘上规模,再看排名。**
24. **命名里常常写着答案。** 那 21 笔"零竞价大额清算"的抵押品叫
    `ILLIQUID_PERPD` —— 名字直接说了它为什么没人抢。
    **看到反常样本,先把涉及的合约 `symbol()` / `name()` 读出来**,
    比任何推理都快。
25. **"没找到"要写清楚方法的盲区。** 私有订单流的定义就是链上不可见,
    所以本方法**先天**证明不了它不存在。**结论要写「这些清算人没有表现出
    私有优势」,不能写「私有订单流不存在」。**
26. **去拆那笔"待解释的异常",往往不是收尾,是开头。**
    第十二节把那笔 22.96 WETH 当尾巴留着,以为拆开只是补个注脚;
    实际它同时给出了「分账要现读余额」的可抄教训、暴露了 payout 的口径错误、
    并直接推翻了两节的结论。**清单上那条"不影响结论"的疑点,值得优先拆。**
