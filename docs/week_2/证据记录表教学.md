# Week 2 教学:证据记录表 —— 把采样变成判断

> 脚本:[`make_evidence.py`](../../make_evidence.py)　|　产物:[`evidence.csv`](../../evidence.csv)　|　数据源:`watch/*.jsonl`

共学文档说这张表是「把运气变成策略的地方」。听起来像记账,其实不是。
**它真正干的事是换一个统计口径:**

```
watch/*.jsonl   一行 = 一次报价       → 采样
evidence.csv    一行 = 一条路径的判断  → 观察
```

从上面到下面,不是格式转换,是**从"我看到了什么"升级成"我判断是什么"**。
这一节就讲这中间要想清楚的四件事。

---

## 1. 三类列,必须分清谁能填

拿到这张表,第一件事不是填,是**给每一列归类**:

| 类别 | 列 | 谁来填 |
|---|---|---|
| **A. 探针知道的** | 时间、链、资产、类型、规模、路径、观测次数、真实成本、延迟 | 脚本自动 |
| **B. 只有人能填的** | 屏幕价差、成败原因 | **必须人工** |
| **C. 要有历史才能填** | 可复现? | 攒够样本再填 |

`make_evidence.py` **只填 A**。B、C 留空。

这不是偷懒,是设计。**脚本不该替你猜判断** —— 一旦它猜了,你就再也分不清
表里哪些是事实、哪些是推测。而这张表存在的全部意义,就是让你在三周后
还能相信里面的数字。

> 顺带一提:我给表加了一列文档 schema 里没有的 **「观测次数」**。
> 因为「真实成本 25.02 bps」这句话,在观测 1 次和观测 100 次时的含金量完全不同。
> 不写观测次数,读表的人无从判断该信几分。

---

## 2. 真实成本填的是分布,不是单点

这是整张表最容易做错的地方。

一次报价给你一个数,很容易就直接抄进表里。但 Week 2 的教训是:
**一个数字是采样,一个分布才是观察。**

所以脚本填的是**中位数 + 区间**:

```
25.02              ← 3 次观测完全一致
36.11 [29.41~43.43] ← 波动很大,中位 36,但你要知道它能跑到 43
```

代码里对应这几行:

```python
bps = sorted(o["bps"] for o in obs)
med = statistics.median(bps)
cost = f"{med:.2f}" if lo == hi else f"{med:.2f} [{lo:.2f}~{hi:.2f}]"
```

**为什么用中位数不用平均数**:成本分布是偏的 —— 偶尔一次路由降级会跑出
153 bps 这种极端值,平均数会被它拖歪,中位数不会。

「路径」列同理,填的是**路由分布**而不是某一次的路由:

```
eco×5                      ← 五次都走 eco,很稳
stargateV2 → across×3, stargateV2 → near×1   ← 有一次换了路由,要留意
```

## 3. 「屏幕价差」这一列为什么必须人工

脚本有 `--fetch-screen`,能抓两条链上同一个 token 的标价之差。
但它抓完会**明确标注 `(标价)`** —— 因为:

> **标价 ≠ 可成交价差。**

LI.FI 的 `priceUSD` 是聚合的参考价,不是你真能吃到的挂单。
真正的「屏幕价差」应该来自你实际观察到的、有深度支撑的可成交价。

所以这个开关是给你**起个头**用的,不是替你观测。表里那个 `(标价)` 标记
就是在提醒未来的你:这个数字比其他列软。

### 实测到的东西比预想的更有意思

抓两次,结果是:

```
2026-08-03 03:18(Hermes 记录):  +9.70 bps   ← BAS 的 USDC 比 ARB 贵
2026-08-03 04:0x(本次抓取):     -1.86 bps   ← 反过来了,BAS 更便宜
```

**它在正负之间摆动。** 而真实成本那一列纹丝不动:

```
25.23 / 25.23 / 25.23 / 25.23 / 25.23    极差 0.00 bps
```

一个在抖,一个是石头。这个对比本身就是结论,下一节说。

## 4. 「可复现?」问的不是成本稳不稳

这是最容易搞混的一点,单独拎出来。

看到成本极差 0.00 bps,很容易就想填「可复现」。**但那是两回事:**

| | 问的是什么 |
|---|---|
| 成本稳定 | **门槛**这个数字稳不稳 |
| 可复现 | **机会**(净收益 > 0)能不能重复出现 |

成本稳定只是**必要条件**,不是答案。成本再稳,如果净收益永远是负的,
那不叫"可复现的机会",叫——

> **可复现地不成立。**

而这同样是有价值的结论。共学文档反复说的「不成立本身就是成果」,
在表格里就长这个样子。

所以脚本的建议逻辑是这样写的:

```
观测 < 3 次           → 「可复现」先别填,样本不够
观测 ≥ 3 且缺屏幕价差 → 净收益未知,还判不了
观测 ≥ 3 且净收益为负 → 可考虑填「可复现地不成立」
```

注意它只是**打印建议**,不写进表。填不填是你的判断。

## 5. 一个必须做对的工程细节:重新生成不能洗掉判断

这张表会被反复重新生成(每次监控攒了新数据都要更新)。
如果每次生成都是覆盖写,**你手填的判断第二次就全没了。**

所以 `make_evidence.py` 做了两件事:

**① 人工列合并回来**

```python
MANUAL_COLS = ["屏幕价差bps", "成败原因", "可复现"]
row.update(manual.get(mkey, {}))     # 手填的盖回自动生成的
```

**② 孤儿行原样保留**

有些行**根本不来自监控** —— 比如 Hermes 那条「口径校准」记录,
`watch/*.jsonl` 里没有对应的桶。这类行必须留着:

```python
orphans = [r for k, r in existing_raw.items() if k not in touched]
```

> 这个坑是真踩到的。第一版写完 dry-run 一看,**Hermes 记的那条口径校准
> 会被静默删掉**。跑之前先 `--dry-run` 看一眼,是这类"会改动已有数据"的脚本
> 应有的礼貌。

**③ 顺手修的一个 key 不一致**

`cost_probe.py` 之前写 CSV 时用了千分位(`"1,000 USDC"`),
而 `watch_probe.py` 写的是 `1000 USDC` —— 同一条记录会裂成两行。
两头都修了:探针改成不带千分位,合并时再做一次归一化兜底。

> **可迁移的一条**:任何要被程序当 key 用的字段,**不要为了好看做格式化**。
> 好看是展示层的事,key 要的是稳定。

## 6. 打样:一条填满的行

这是当前 `evidence.csv` 里的样板行,你照着这个格式填其他的:

```
时间       : 2026-08-03T01:55:37+00:00 ~ 2026-08-03T03:15:06+00:00
链         : ARB→BAS
资产       : USDC→USDC
类型       : 跨链
规模       : 10000 USDC
路径       : eco×3
观测次数    : 3
屏幕价差bps : -1.86 ~ +9.70(标价,两次观测)
真实成本bps : 25.02
净收益bps   : -15.3 ~ -27.1(始终为负)
延迟秒      : 7
成败原因    : 25bps 是 LI.FI 固定费率(非市场撮合,不随规模/时段变);而两链 USDC
             标价差实测在 -1.86 ~ +9.70 bps 间摆动且跨零。门槛是价差波动幅度的
             2-3 倍,净收益结构性为负 —— 不是"今天没机会",是"这条路没有机会"
可复现      : 可复现地不成立(5次观测,成本极差0.00bps;标价差虽波动但从未接近25bps)
```

### 「成败原因」怎么写:写机制,不写结果

这一列最能看出一个人有没有真的想明白。对照着看:

| ✗ 写结果(没信息量) | ✓ 写机制(可迁移) |
|---|---|
| 「没赚到钱」 | 「25bps 是固定费率,不随市场变;而价差在 ±10bps 内摆动,量级差 2-3 倍」 |
| 「成本太高」 | 「门槛的地板是比例费,规模再大也摊不薄」 |
| 「这次没成」 | 「门槛只有 20bps,但 1080 秒延迟内价差早消失了」 |

判断标准很简单:**你写的这句话,能不能拿去推断另一条路径?**
能 → 是机制。不能 → 只是结果。

上面样板行那句「不是'今天没机会',是'这条路没有机会'」,
就是把一次观测提升成了结构性判断 —— **这才是这张表的产出。**

## 怎么用

```bash
# 1. 先攒数据(没有历史就没有判断)
python3 watch_probe.py --from-chain ARB --to-chain BAS --token USDC \
    --amounts 1000,10000 --interval 1800

# 2. 汇总成表(--dry-run 先看一眼,别直接覆盖)
python3 make_evidence.py --dry-run
python3 make_evidence.py --fetch-screen

# 3. 打开 evidence.csv,手填 屏幕价差 / 成败原因 / 可复现
# 4. 以后再跑 make_evidence.py,自动列刷新,你填的判断留着
```

## 沉淀下来的四条

1. **给每一列归类:脚本能填的、只有人能填的、要有历史才能填的。**
   脚本越界去猜判断,整张表就不可信了。
2. **成本填分布不填单点。** 用中位数不用平均数 —— 极端值会把平均数拖歪。
3. **「可复现」问的是机会能不能重复,不是成本稳不稳。**
   「可复现地不成立」是一个完整且有价值的结论。
4. **会改动已有数据的脚本,先写 `--dry-run`。** 这次就是靠它发现
   Hermes 那条记录会被静默删掉。
