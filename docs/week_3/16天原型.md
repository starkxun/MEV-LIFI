## 已知的近似(P1 要消除)

**`getUserAccountData` 只给聚合值,不告诉你抵押物具体是什么币。**

所以推算新健康度用的是一阶近似:

```
HF_new ≈ HF_now × (P_new / P_now)
```

**只在「抵押物全是随该喂价波动的资产、债务是稳定币」时成立。**

真实仓位可能:
- 混着稳定币抵押物 → 价格跌时 HF 降得没那么快
- 借的也是波动资产 → 分子分母同向变动,HF 几乎不动

**所以 P0 的预测偏激进,会高估"将被清算"的数量。**

这个近似在 P0 阶段可以接受 —— **P0 的目的是证明"能提前看见",不是精确定价。**
P1 用 `eth_call` 逐个模拟 `liquidationCall` 才能消除它。

# SVR:被推翻的前提

## 一句话

> **我盯错了喂价。** Aave 在 Arbitrum 上早就不读公开的 Chainlink ETH/USD 代理了,
> 它读的是一个专门用来**把清算利润拍卖回收给协议**的喂价。

## 什么是 SVR

SVR = **S**mart **V**alue **R**ecapture,Chainlink + Aave 的联合机制。
翻译成人话:

**以前**:预言机把新价格广播到公开内存池 → 所有 searcher 同时看见 → 谁快谁抢到清算。
利润归 searcher,协议一分钱拿不到。

**SVR 之后**:预言机把**同一份价格报告**同时走两条路发出去 ——

```
        ┌──→ 公开聚合器   (走公开内存池,谁都能看,和以前一样)
Data DON┤
        └──→ SVR 聚合器   (走私有通道,先不公开)
                              ↓
                         searcher 竞价:
                    「让我跟在这次价格更新后面清算,
                      我愿意把利润的 XX% 交出来」
                              ↓
                    出价最高的赢 → 他的清算和价格更新
                       打包进同一个区块
```

Aave 的合约读的是 **SVR 聚合器**。所以"价格变了导致仓位可清算"这件事,
在公开世界看见之前,拍卖赢家已经在同一个区块里把它做完了。

如果私有通道失败或超时,SVR 喂价会**回落到公开价格**(有个可配置的延迟)——
这就是漏给普通 searcher 的那部分。

## 官方公布的数字

来自 [Aave 治理提案 ARFC-SVR-Expansion](https://governance.aave.com/t/arfc-svr-expansion-next-phase-of-multi-network-expansion/25332):

| 市场 | 上线时间 | **回收率** |
|---|---|---|
| Ethereum Core V3 | 2025-03 | 51.5%(近 365 天) |
| **Base V3** | **2026-03** | **89.3%** |
| **Arbitrum V3** | **2026-03** | **89.2%** |

**为什么 L2 的回收率(89%)远高于以太坊主网(51.5%)?**
提案自己给了解释:以太坊有完整的 MEV 供应链(builder、validator 层层抽成),
价值在中途就被别人截走了;**Base / Arbitrum 是中心化排序器,中间环节少,
所以能收得更干净。**

> 这一条对我们特别刺眼:**恰恰是"排序器中心化、没有公开内存池"这个我原本
> 以为对小 searcher 有利的特征(不用拼 builder 关系),让 SVR 能吃得最干净。**

其他数字:
- 累计 SVR 清算量 ~$887.6M,总收入 ~$21.3M,Aave DAO 分 65% = ~$13.9M
- 参与 SVR 拍卖的独立地址:**从最初 93 个涨到 245 个**

### 清算发生在什么时候

```

  -10块 ×3   -9 ×2   -8 ×6   -4 ×1   -3 ×1   +2 ×1

26 个区块的窗口撞上的概率约 7.2%。**实测 36.8% 是随机的 5 倍**,是真关联。

## 一个反直觉的出路:不打 SVR,加入 SVR

SVR 拍卖是**公开竞价**,不是邀请制。参与地址从 93 个涨到了 **245 个**。

对"小而中立的 searcher"来说,这个方向的性质完全不同:

```
抢公开清算          SVR 拍卖竞价
拼延迟,赢家通吃  →  拼出价,按利润分成
输了亏 gas        →  没中标不花钱
需要基础设施       →  需要的是估值准确
```

**拍卖把"谁跑得快"换成了"谁算得准"** —— 而算得准恰好是我们这四周一直在练的。

# 调查:怎么成为 SVR 拍卖参与方

## 先说方法:链上找入口,文档补手续

不是先去翻文档。**先在链上找到"已经在做这件事的人从哪个门进去的"**,
再拿这个门去文档里对号入座。这样不会被文档的措辞带偏,也不会漏掉文档没写的东西。

上一节筛出了 13 笔"喂价更新后 3~10 块内"的疑似拍卖赢家。看它们的 `tx.to`:

0x9f83664976adc0abe9c375151b0e5b36ee7703d7   ×3
0x4ef12ab6d0d59a840369886ccb1d01f4ab4e6587   ×1
```

问那个合约它叫什么:

```
name()          → "Atlas ETH"
VERIFICATION()  → 0xac116abb948e26b023c9c4815ab001845fbf54ff
SIMULATOR()     → 0x57fa2abf1dc109c5f7ea2fb6a72358d2c624971d

**Atlas** —— 正是 Chainlink 文档里说 Base / Arbitrum / BNB 上 SVR 所用的拍卖系统

| **准入** | **无需申请、无白名单、无 KYC**。原文:*"Onboarding and access to the high-reputation set is **permissionless** and does not require communication with Chainlink Labs."* |
| **押金** | Base / Arbitrum **0.1 ETH**(≈ $192),BNB Chain 1 BNB,调 `depositAndBond` |
| **锁定期** | `ESCROW_DURATION()` = **128 区块**。链上实测,Arbitrum 上 ≈ **32 秒** |
| **要写的合约** | 实现一个回调 `atlasSolverCall(...)`,官方 SDK 提供 `SolverBase` 基类 |
| **接收行情** | WebSocket `wss://svr-bid-endpoint.chain.link/ws/solver`,订阅 `solver_subscribe(["userOperations"])` |
| **出价** | JSON-RPC `solver_submitSolverOperation`,EIP-712 签名 |
| **排名** | 两档信誉位(高信誉有保留位、低信誉走开放位),但**"Final winner ordering is determined by bid competitiveness, not reputation."** |

### 三条最要命的信息

**① 推送里直接带新价格。**
通知内容包含 *"hint data (aggregator address, **median price**)"* ——
**Chainlink 直接把新价格推给你**。

> 这一条直接注销了我们前四周所有关于"预言机时差"的工作方向。
> 不用抢先看见价格,**人家发给你**。信息竞速这一层没了。

**② 排名看出价,不看速度。**
在这个赛道里"跑得快"不再是护城河 —— 变成了**估值准不准 + 敢出多高**。

**③ 押金只有 0.1 ETH,锁 32 秒。**
资金门槛 ≈ $192,而且几乎不锁死。**这不是"要有钱才能玩"的生意。**

> ⚠️ **没能在链上核实押金**:试了 `balanceOf` / `balanceOfBonded` /
> `balanceOfUnbonding` 三个方法查现有 solver 的余额,全返回 0。
> 要么方法名不对,要么押金记在别的地址下。**0.1 ETH 目前只有文档一个来源,未经独立验证。**

# 把 Atlas 拆到底:三个问题的答案

## 怎么拆的

Atlas 最近 90k 块只发两种事件。暴力匹配候选签名:

```

0x1c8af922…  ×66  → MetacallResult(address,address,bool,uint256,uint256)
```

`SolverTxResult` 里就有 `bidAmount` —— **中标价直接写在链上**。
三个 indexed 字段分别是 `solverTo`(solver 合约)、`solverFrom`(solver 身份 EOA)、
`dAppControl`(业务线)。

## 答案一:中标高度垄断

扫 7 天,1931 条 `SolverTxResult`,全部 `executed=true, success=true`。

> **顺带答了一个问题:落败的出价根本不上链。**
> 只有赢家会留下记录 —— 所以"没中标不花钱"是真的。

```
中标 solver 数:3
  0x83eb6513…  1633 笔  (84.6%)
  0xb4a3c10c…   295 笔  (15.3%)
  0x35666ffa…     3 笔  ( 0.2%)

**这就是我上一节判断错的地方。** 我看到 10 个 EOA 就以为有 10 个参与者,
其实那些是 bundler。真正的竞标者只有 3 个。

而且 —— **那 3 笔真正的 Aave 清算,全被占 0.2% 的那个小 solver 拿走了。**
占 84.6% 的大户赢的是别的东西(1931 笔里只有 3 笔是 Aave 清算)。

**实测 92.3%,比官方口径的 89.2% 还狠。**

## 答案三:押金门槛属实(而且更低)

上一节查押金全返回 0,**是因为我查错了地址** —— 查的是 bundler EOA 和
执行环境合约。真正的 solver 身份是 `solverFrom`:

```
0x83eb6513…  balanceOfBonded = 0.2617 ETH  ($503)
0xb4a3c10c…  balanceOfBonded = 0.0893 ETH  ($172)   ← 低于文档说的 0.1

**0.1 ETH 的说法基本属实**,而且有一个只押了 0.0893 —— 说明是推荐值不是硬下限。
**全网所有 solver 的押金加起来只有 $26,228。**

# 新市场上线初期,回收率真的低吗?—— 实测

## 这个假说从哪来

有人(codex)提出:**新 Atlas 市场刚启动时 searcher 少、竞价逻辑未校准,
回收率会先低后高。所以 alpha 不是"比 245 个成熟 searcher 更聪明",
而是"新市场开放第一天就能报价"。**

我把两份 Aave 官方文档全文读了 + 7 种模式程序化检索,**这句话不在里面**。
文档说的反而是相反机制:*"liquidation sizes across the recommended deployments
are relatively **modest**, suggesting **stronger competition**… and consequently
**higher** expected recapture rates."*

**但这不需要文档背书 —— Base/Arbitrum 就是 2026-03 上线的,五个月前发生过一次。**
扫 Atlas 160 天的 `SolverTxResult`,和清算按交易哈希对齐,直接测。

**我当时的反驳是"老手会直接平移,你第一天到场只是持平"。实测没有发生。**

第 3 个月  34 个

第二名 `0xb4a3c10c…` 到**第 57.6 天**才第一次中标。竞争是慢慢来的。

# P2 前置阅读:There Will Be Spam(MPI-SWS)

> [`论文/There Will Be Spam Characterizing State-Invariant.pdf`](../../论文/There%20Will%20Be%20Spam%20Characterizing%20State-Invariant.pdf)

## 它定义了什么

**state-invariant transaction(状态不变交易)**:把它从区块里删掉,
除了手续费之外**链上状态完全不变**的交易。所有 revert 的合约调用都算,
但也包括那些"成功了却什么也没改"的探测交易。

作者的判定方法不靠猜,用 `trace_replay_block_transactions` 拿每笔的 `stateDiff` 来算。

规模:**14 亿笔**。占以太坊交易的 2.6%,但占 **Optimism 的 24%、Base 的 37%**。
其中 Optimism 57%、Base 68% 来自投机型 MEV。

## 为什么这篇对 P2 是必读的

**因为它算了我一直没算的那笔账:空转成本要摊进利润里。**

我之前测出"失败一次 $0.0084,年空转 ~$850",但没做的是
**把这笔钱从收入里扣掉,再看还剩几个 bot 是赚的**。这篇论文做了(Table 6):

**扣除空转成本前 → 后,盈利 bot 的比例:**

| bot 类型 | Ethereum | Optimism | Base |
|---|---|---|---|
| 投机型**套利** | 84.1% → 82.1% | 56.5% → **13.1%** | 83.5% → **23.4%** |
| 投机型**清算** | 26.2% → 23.8% | 65.6% → **61.7%** | 74.5% → **71.1%** |

**这张表是我目前看到的、对"清算 vs 套利"最直接的一次对照实验。**

- **L2 上的投机型套利,扣掉空转成本后整体转负**(Optimism −31.26,Base −28.07),
  盈利 bot 从 56.5% 崩到 13.1%。
- **投机型清算几乎没掉**(65.6%→61.7%),而且**总利润仍为正**(OP +106.29,Base +390.00)。

原因论文也给了:**清算机会稀缺,所以不需要疯狂空转**;
而套利机会密集,投机型套利 bot 在 Optimism 有 82% 的交易是重复 calldata 的盲打。

> **这条独立支持了我们"选清算不选原子套利"的判断** ——
> 而且是从一个我们完全没测过的维度(空转成本占比)得出的。

另一个细节:以太坊上投机型清算只有 26.2% 盈利,L2 上却有 65~75%。
**投机式打法是 L2 特有的**,主网上因为有公开内存池 + 高 gas,盲打不划算。

## 对 P2 的三条直接影响

1. **失败交易概率不能只算"一次多少钱",要算"占收入多少"** ——
   成本模型里那一栏要改成比值。
2. **必须做 revert 保护**(论文里反复出现"因滑点保护 revert")——
   这正好是反编译那个 bot 时发现它**缺失**的东西。
3. **P2 的成功判据要写成:扣掉全部空转成本后仍为正**,而不是"抢到过几笔"。
