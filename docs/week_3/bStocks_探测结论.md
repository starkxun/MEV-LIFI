## 1. Gate 0:接口是真的,但门有两道

### 1.1 第一道门:出口 IP

```
出口 IP 在美国(San Jose)     → /fapi/* 和 /sapi/v1/equity/* 全部 451
                                "Service unavailable from a restricted location"
出口 IP 在新加坡              → /fapi/* 全通
```

**美国是无条件封禁,和 bStocks 的地区资格是两回事。** 这一条 15 分钟就能测完,
但它能一票否决整个项目。

### 1.2 第二道门:API key

```
[400] /sapi/v1/equity/market/exchangeInfo       -2014 API-key format invalid
[400] /sapi/v1/equity/market/tokenized-assets   -2014
[400] /sapi/v1/equity/market/quote?symbol=NVDA  -2014
```

带一个**格式合法但不存在**的 key 再打,错误码变成 `-2008 Invalid Api-Key ID` ——
**说明这几个接口只校验 `X-MBX-APIKEY` 头,不需要 HMAC 签名。**
所以一个**纯只读 key** 就够,不必开任何交易权限。

> **可迁移的一条:用假 key 探错误码的变化,能在没有真 key 的情况下
> 判断接口的鉴权级别。** `-2014`(格式错) → `-2008`(ID 不存在) 这个跃迁
> 说明服务端已经进到"查这个 key 存不存在"那一步,即 MARKET_DATA 级。

### 1.3 意外:bStock 根本不需要 equity 接口

```
/api/v3/exchangeInfo  →  NVDABUSDT / QQQBUSDT / SPYBUSDT ... 共 14 个
```

**bStock 就在普通现货上,行情完全公开。**
所以 H1(bStock↔Perp)和 H3(CEX↔DEX)**用公开数据就能测完**,
只有 H2(Direct Stock)那条腿被 key 卡住。

### 1.4 盘子比原文档以为的大得多

`/fapi/v1/exchangeInfo` 858 个 symbol,其中 **157 个 `TRADIFI_PERPETUAL`**:

```
EQUITY      133   美股
HK_EQUITY    11   腾讯/美团/快手/泡泡玛特/CSOP 杠杆 ETF  ← 原文档不知道存在
KR_EQUITY     3   三星/SK海力士/现代               ← 原文档不知道存在
COMMODITY     8   XAU/XAG/XPT/XPD/CL/BZ/NATGAS/COPPER
PREMARKET     2   OPENAIUSDT / ANTHROPICUSDT (Pre-IPO)
```

`/fapi/v1/tradingSchedule` 覆盖 4 个市场,当时 `EQUITY=OVERNIGHT`、`HK/KR=REGULAR`。

三层 universe 的实际规模:

```
Direct Stock   7,924 个   ← 绝大多数没有 bStock 也没有永续
bStock            67 个   ← 其中只有 14 个上了现货交易对
TradFi Perp      157 个
```

**三条腿的交集其实很小**,原文档设想的"动态取交集"是对的,
但没料到分母差两个数量级。

### 4.3 multiplier 不全是 1(这条差点造成假 alpha)

## 6. 两个操作层面的教训

### 6.1 时钟

签名接口全部 `-1021 Timestamp for this request was 1000ms ahead`。

```
本机时钟比服务器快 4,807 ~ 5,348 ms
```

必须用 `/api/v3/time` 算偏移再签名,**不能用本地时钟**。
原文档 §37 说的就是这个,但它把这条写成"建议开 NTP" —— 实际是**硬性前置条件**。

### 6.2 REST 轮询会被 IP ban,而且封禁会续期

```
第一次撞  418  banned until  ...159879   (剩 6.7 分钟)
又撞了一次     banned until  ...914580   (剩 50.5 分钟)
```

**每撞一次 418,封禁时间往后续。** 所以限流必须**立刻放弃**,不能退避重试 ——
退避重试只会让封禁越来越长。

币安在错误信息里直接写了:*"Please use the websocket for live updates to avoid bans."*
**原文档 §7.1「行情禁止使用 REST 轮询作为主数据源」现在有实证了。**

代码里的处理:

```python
except urllib.error.HTTPError as e:
    if e.code in (418, 429):
        raise RuntimeError(last)   # 限流绝不重试
    ...
time.sleep(min(1.0 * 2 ** i, 8))   # 只对连接层错误退避
```

## 8. H4:maker = 0 —— 补贴是真的,池子太小

脚本:[`markout_probe.py`](../../markout_probe.py)(纯公开成交数据,未下任何单)

### 8.1 机制转换

前三条假设全是"**穿两边盘口**"的算法,所以被约 20bp 的往返成本压死。
bStock maker 免费意味着**挂单一侧零成本**,那条路变成:

```
在 bStock 挂被动双边报价
用 TradFi Perp 对冲库存
```

**这是做市,不是套利。** 风险从"抢不抢得到"换成了**逆向选择 + 库存**。

**这是一次真实的机制转换,和 SVR 那次同类** —— 不是同一件事的变体,
是"你要做的根本不是原来那件事"。

### 8.2 第一版 markout 测量失败了

想法是对的:逆向选择可以从逐笔成交直接量出来,不用下单 ——
对每笔成交假设 maker 是自己,看 N 秒后浮亏多少。

`aggTrades` 的 `m` 字段 = "买方是否为 maker":

```
m=True   maker 买入,  PnL = 未来价 - 成交价
m=False  maker 卖出,  PnL = 成交价 - 未来价
```

跑出来八个标的**全是正的**(NVDAB +0.7bp @30s)。**正 markout 意味着做市商
在价差之外还系统性赚钱 —— 这不合常理,所以先怀疑测量。**

查成交稀疏度:

```
sym      笔/分钟   平均间隔   t+N±2s 窗口内真有成交的概率
NVDAB      3.66     16.4s              22%
QQQB       3.45     17.4s              21%
AAPLB      1.14     52.9s               7%
COINB      1.25     47.8s               8%
```

**七到九成的情况窗口是空的**,代码回落到"取 t+N 之后第一笔"。
于是 @1s / @5s / @30s **测的是同一个东西** —— 下一笔成交。

而且这会造出**假的正 markout**:taker 砸在买价上(maker 买入),
下一笔往往回到卖价,`未来价 > 成交价` → 算成赚。
**那不是 alpha,是 bid-ask bounce。**

> **可迁移的一条:结果方向和常理相反时,先查测量,别先信结论。**
> 这次救回来的判据很硬 —— **做市商不可能在价差之外还系统性赚钱**。
> 如果只看数字本身,八个全绿看起来非常"干净"。
> (同样的病在 P0 出现过:[subgraph 那 15 个整整齐齐的 1.0000](16天原型.md#坑-1现成的-aave-风险-subgraph-数据是坏的)。)

要修得用 WebSocket 录一段真实盘口再对 mid 算。**但没修** —— 因为下面这个数
不依赖 markout,而且已经足够定案。

### 8.3 不依赖 markout 的那个数:天花板

```
sym       $/小时流量   半价差bp   100%吃满$/时   扣永续对冲5bp后
NVDAB        58,072      0.68         3.97          -25.06
QQQB         76,062      0.07         0.53          -37.50
SPYB         46,673      0.06         0.30          -23.04
TSLAB        12,267      2.11         2.59           -3.54
MSTRB        21,205      2.06         4.36           -6.24
CRCLB        43,588      0.75         3.25          -18.54
AAPLB         8,796      1.94         1.71           -2.69
COINB         4,037      5.35         2.16          +0.14
─────────────────────────────────────────────────────────────
合计                                 18.87         -116.48
```

**"100% 吃满" = 假设这些标的每一笔成交的对手方都是你。**
这在现实中不可能 —— 而即使这样,**整个盘子只有 $18.87/小时**。

**而对冲腿每成交一笔就要付一次。** 永续 taker 5bp,对上捕获的 0.06–5.35bp ——
**八个标的里七个,对冲成本高于捕获的价差。**
唯一为正的 COINB 是 $0.14/小时。

按 maker 对冲(永续 maker ~2bp)也救不回来:只有 COINB / TSLAB 勉强转正,
而 COINB 一小时才 $4,037 的流量。

### 8.4 放大到全天,方向不变

本节样本落在 OVERNIGHT。用 24h 成交额外推(14 个 bStock 对合计约
**$22M/天 ≈ $920k/小时**):

```
100% 吃满毛收入   $920k × ~1bp  ≈   $92 / 小时
对冲成本         $920k × 5bp   ≈  $460 / 小时
```

**量级差 5 倍,方向不变。**

### 8.5 裁决

**maker=0 这个补贴是真的,但它补贴的池子太小。**
币安免 bStock 的 maker 费,**恰恰因为这些交易对没什么量** ——
补贴是拿来引流的,不是留给你的利润。

现实估计:排在零费队列的队尾,拿到 10% 流量算走运,
`$22M/天 × 10% × 1bp ≈ $220/天` 毛收入,还没扣对冲、没扣逆向选择。
