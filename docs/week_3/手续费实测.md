# 手续费实测:我们一直用的 8 bps 是错的

> 2026-08-15　|　先从 10 笔真实账单反推,再去两个所的官方费率页对账
> **这是四周来第一次把「成本」这一项从假设变成实测。**

---

## ⚡ 最重要的一条(后补)

去官方费率页核对后,发现了一个账单里看不到的格子:

```
币安 TradFi 合约   挂单方 0.0000%   ← 活动期
Bybit TradFi       挂单实测   0     ← 账单
                              ↓
        TradFi 双边挂单往返 = (0 + 0) × 2 = 【0.00 bps】
```

**「8 bps 成本地板」在「代币化股票 + 双边挂单」这一档根本不存在。**

之前被成本否掉的方向,凡是标的属于 TradFi 的,都要重算。
代价是挂单可能挂不上 → 单腿风险,**零手续费不等于零成本**。
另外这是**活动期**费率,会过期,要定期重查。

## 一、先看结论

单腿单边(bps):

| | Bybit maker | Bybit taker | 币安 maker | 币安 taker |
|---|---|---|---|---|
| **代币化股票** | **0.00** | 2.75 | **0.00** | 4.00 |
| **加密** | 2.00 | 5.50 | 2.00 | 5.00 |

往返 = 两条腿 × (开仓 + 平仓) = 4 笔:

| | 双边吃单 | 混合(Bybit挂+币安吃) | 双边挂单 |
|---|---|---|---|
| **代币化股票** | 13.50 bps | 8.00 bps | **0.00 bps** ★ |
| **加密** | **21.00 bps** | 14.00 bps | 8.00 bps |

以前一律按 **8.0 bps** 算 —— 加密双边吃单低估 **163%**,
而 TradFi 双边挂单则是**高估到无穷**(实际是 0)。

**三件以前不知道的事:**

```
① 同一个交易所,代币化股票和加密的费率【不一样】,最多差 2 倍
② 我们脚本和文档里一律按 8 bps 算 —— 加密方向全部偏乐观
③ TradFi 双边挂单 = 0 —— 成本地板在这一档不存在
```

同时官方表**纠正了我一个假设值**:

```

```

> ### 🔑 账单和费率表是两种不同的证据,不能互相替代
>
> ```
> 账单    →  你【实际付了】多少,含账户等级/活动/折扣的真实结果
> 费率表  →  规则是什么,【包括你还没交易过的格子】
> ```
>
> 账单验证「这张表对我成立」,费率表补上账单的空白。
> **只有账单会有盲区,只有费率表不知道是否真的适用于你。**

## 三、★ 挂单零手续费

```
Bybit  SNDK  限价单  $0.00000000 / $16.44 = 0.00 bps
```

不是四舍五入,账单上就是 `0 USDT`。

币安 TradFi 官方表同样是挂单 **0.0000%**。于是有两档:

```
混合   Bybit挂 0.00 + 币安吃 4.00, × 2  =  8.00 bps   ✅ 两腿均有账单
双边挂 Bybit挂 0.00 + 币安挂 0.00, × 2  =  0.00 bps   📖 币安那格只有官方表
```

**代价是挂单可能挂不上 → 单腿风险。** 这是一个可以量化的权衡:

```
双边吃单 → 混合    省 5.5  bps × $16.45 = $0.0090   一条腿承担挂单风险
双边吃单 → 双边挂  省 13.5 bps × $16.45 = $0.0222   两条腿都承担
```

注意第二档**省下的正好等于全部手续费** —— 成本项归零后,
这笔交易的盈亏就只剩「资金费 − 基差变化」,没有任何固定损耗。

taoli 面板上那个「限价」勾选框就是干这个的,**下次值得试**,但要盯着成交。

## 四、这个错误的性质

和前面几次不同:

```
14 天窗口年化       →  取样窗口太短        (取样错误)
42 天分布定阈值     →  取样窗口太长        (取样错误)
11 分钟外推日噪音   →  样本量太小          (取样错误)
两半比值筛稳定性    →  筛选目标不一致      (目标错误)
8 bps 往返手续费    →  **从来没测过**      ← 这次
```

前四次都是「测了,但测错了」。**这次是「压根没测,直接抄了个公示费率,然后当成事实用了四周」。**

> ### 🔑 「假设」和「实测」放在同一个字典里,一个月后就分不出来了

`FEES = {"Binance": {"maker": 2.0, "taker": 5.0}}` —— 这行代码没有任何地方
告诉你 5.0 是抄来的。它长得和实测值一模一样。

**所以新的 `lib/fees.py` 把出处和数值分开存,四档可信度:**

```python
FEES    = {...}       # 数值
SOURCES = {           # 每个格子的出处
    ("Binance","tradfi","taker"): ("bill+table", "0.0400% / SNDK×2 SOXL×1"),
    ("Binance","tradfi","maker"): ("table",      "TradFi 挂单方 0.0000% ⏳活动期"),
    ("Bybit",  "tradfi","maker"): ("bill",       "SNDK 限价单账单 = 0 USDT"),
    ...
}

  ✅✅ 账单 + 官方表     最高
  ✅   只有账单          事实,但可能有盲区
  📖   只有官方费率表    规则,但不确定是否适用于你
  ⚠️   都没有,猜的      ← 出现这个就别拿去做决策
```

每次打印都带标记:

```
tradfi 双边吃单  (币安 4.00✅✅ + Bybit 2.75✅) × 2 = 13.50 bps  ✅ 两腿均有真实账单
tradfi 双边挂单  (币安 0.00📖  + Bybit 0.00✅) × 2 =  0.00 bps  📖 含仅凭官方表的格子
```

**📖 的那一行你会先去补一笔账单再用。**

## 五、怎么自动判别资产类别

不硬编码币种清单(会过期)。**问交易所**:

币安 `exchangeInfo` 的 `underlyingSubType` 带 `TradFi` 标记 ——

```
SNDKUSDT      EQUITY       ['TradFi']      ← 代币化美股
SKHYNIXUSDT   KR_EQUITY    ['TradFi']      ← 代币化韩股
HK0700USDT    HK_EQUITY    ['TradFi']      ← 代币化港股(腾讯)
XAUUSDT       COMMODITY    ['TradFi']      ← 代币化黄金
OPENAIUSDT    PREMARKET    ['Pre-IPO','TradFi']  ← 未上市公司
HYPEUSDT      COIN         ['DeFi']        ← 加密
```

816 个合约里 **162 个是 TradFi**,占 20%。这个比例本身就说明:
**不分类是不行的。**

判据一行:

```python
cls = "tradfi" if "TradFi" in (s.get("underlyingSubType") or []) else "crypto"
```

拿不到分类时**回退到 crypto** —— 因为 crypto 的费率更高,
未知时按贵的算只会高估成本,不会让你误以为便宜。

## 八、还没测的

按「有待定项就不出总数」的规矩,**明确列出来**:

```
📖 币安 maker(crypto 2.0 / tradfi 0.0)  —— 有官方表,无账单
📖 Bybit maker(crypto 2.0)              —— 同上
⚠️ Backpack 全部                         —— funding_probe 里那组,抄的且未核对
⚠️ 滑点                                  —— 市价成交价 vs 下单瞬间盘口
⚠️ 限价单的**未成交率**                   —— 决定「省 13.5 bps」值不值
```

**现在没有 ⚠️ 的费率格子了 —— 每格要么有账单,要么有官方表。**
但 📖 的格子仍然不该拿去做 GO/NO-GO:表是规则,账单才是事实,
账户等级/活动资格/地区限制都可能让实际收费和表不一致。

补测很便宜:**各挂一笔最小额限价单,看账单**,每格约 $0.01。
**最该先补的是币安 TradFi 挂单那格** —— 如果 0% 属实,
整条 TradFi carry 路线的成本模型会完全改写。

### 比费率更难测的那个

```
⚠️ 限价单挂不上的概率
```

零手续费的代价是单腿风险。这个数**没有任何公开来源**,只能自己试:
挂 N 次,记录多少次在可接受时间内成交、多少次要撤单改吃单。
在拿到这个数之前,「双边挂单 0 bps」只是一个上界,不是可执行的成本。
