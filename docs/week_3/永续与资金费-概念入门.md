## 第 1 课:永续合约是什么

### 先说传统期货

传统期货有**交割日**:「三个月后按今天约定的价格买 1 吨铜」。
到期那天必须结算,所以期货价格到期时必然收敛到现货价格。

### 永续合约把交割日去掉了

**永续 = perpetual = 永远不到期的合约。** 你可以一直持有。

但这带来一个问题:

> **没有交割日,凭什么保证永续的价格贴着现货走?**

传统期货靠"到期必须结算"这个硬约束。永续没有这个约束,
理论上永续价格可以永远偏离现货 —— 那这个合约就没意义了。

**解决办法就是资金费。**

---

## 第 2 课:资金费 —— 一笔多空之间的转账

### 机制

```
永续价格 > 现货价格   →  多头太多,把价格推高了
                      →  罚多头:多头付钱给空头
                      →  资金费为【正】

永续价格 < 现货价格   →  空头太多
                      →  罚空头:空头付钱给多头
                      →  资金费为【负】
```

**关键:这笔钱是多空之间转的,交易所只是搬运工,不是手续费。**

这就形成一个负反馈:永续涨太高 → 做多要持续付钱 → 多头减少 → 价格回落。

### 读你屏幕上的资金费

```
A: Bybit    8H  +0.0273%
B: 币安     4H  +0.0148%
```

拆开是:

| 字段 | 含义 |
|---|---|
| `8H` / `4H` | **结算间隔** —— 每 8 小时 / 每 4 小时收一次 |
| `+0.0273%` | **这一次**要收的费率,按持仓名义价值算 |
| `4h 23m` | 距离下次结算还有多久 |

正号 = 多头付给空头。所以**你做空就是收钱的那方。**

### ⚠️ 第一个坑:间隔不同,不能直接比大小

```
Bybit  +0.0273%  看起来比币安大一倍
币安   +0.0148%
```

**但 Bybit 是 8 小时收一次,币安是 4 小时收一次。** 必须先换算成年化:

```
Bybit:  0.0273% × (8760 ÷ 8  = 1095 次/年)  =  +29.89% / 年
币安:   0.0148% × (8760 ÷ 4  = 2190 次/年)  =  +32.41% / 年
                                                ────────
                                                币安反而更高
```

> ### 🔑 记住这条
> **看到资金费,先问间隔是多少。** 不年化就比大小,会得到相反的结论。
> 这是你屏幕上就能踩到的坑。

## 第 3 课:同一个币,为什么各所费率不一样

资金费由**各个交易所自己的多空失衡**决定,不是全市场统一的。

```
币安的 SKHYNIX 多头特别多   →  币安的资金费高
Bybit 的 SKHYNIX 相对平衡   →  Bybit 的资金费低
```

**所以同一时刻,同一个币,不同所的资金费可以差很多。**

你之前查到的历史数据:

```
SKHYNIX   币安 +59.58%    Bybit +37.44%     (公共窗口均值)
```

这个差就是可以做文章的地方 —— 下一课讲怎么做。

## 第 4 课:对冲 —— 让价格涨跌与你无关

### 问题

如果你只在币安做空 SKHYNIX 收资金费,那么 SKHYNIX 一涨你就亏。
**资金费那点钱,一个涨停就吃光了。**

### 解法:两条腿方向相反

```
币安    做空 1 个 SKHYNIX      SKHYNIX 涨 $10  →  亏 $10
Bybit   做多 1 个 SKHYNIX      SKHYNIX 涨 $10  →  赚 $10
        ──────────────────────────────────────────────
        价格涨跌            →  净盈亏 ≈ 0
```

**价格波动被抵消掉了,剩下的只有资金费。** 这就叫 **delta 中性**
(delta = 价格变动的敞口,中性 = 敞口为零)。

### 这就是 A 腿 / B 腿

taoli.tools 屏幕上的 `A:` 和 `B:` 就是这两条腿:

```
A: SKHYNIX/USDT  Bybit 永续
B: SKHYNIX/USDT  币安  永续
```

**一个做多、一个做空,数量相同。**

### 为什么两条腿都用永续,不用现货

```
方案一:现货买入 + 永续做空
        手续费 = 现货 8 bps + 永续 2 bps,开平共 4 笔 = 20 bps

方案二:永续做多 + 永续做空(跨所)
        手续费 = 永续 2 bps × 4 笔 = 8 bps       ← 便宜一半以上
```

而且方案二不用真的持有那个币,**省掉了托管和提币的麻烦**。

代价:方案二有**两个**交易所的爆仓风险(第 8 课讲)。

## 第 5 课:两种完全不同的玩法,别搞混

这是最容易混淆的地方,而且**决定了你该怎么设置那个 0.15%**。

### 玩法一:价差套利

赌的是**两个所的价格会收敛**。

```
此刻   Bybit $1,083.89    币安 $1,083.30      差 0.05%
       → 在贵的所做空、便宜的所做多

之后   两边价格靠拢       差 0.00%
       → 平掉,赚那 0.05%
```

- 持有时间:**几分钟到几小时**
- 收益来源:**价差收敛**
- 用 `循环` 模式,阈值设 0.15%(价差够大才进)

### 玩法二:资金费 carry

赌的是**资金费会持续付给你**。

```
开仓后什么都不做,每 4 小时 / 8 小时收一笔钱,持有几天到几周。
```

- 持有时间:**几天到几周**
- 收益来源:**资金费**
- 用 `单次` 模式,进去之后就放着

### 你要做的是玩法二

所以:

```
❌ 阈值设 0.15% 等价差张开      ← 那是玩法一
✅ 只要开仓成本不太高就进,然后拿住
```

> ### 🔑 一句话区分
> **价差套利赚的是"价格回来";carry 赚的是"时间过去"。**

## 第 6 课:读懂 `-A+B` 和 `+A-B`

屏幕右下角这两行是**开仓的两个方向,以及各自此刻的价格成本**。

```
-A+B: +0.05%     ← 做空 A(Bybit)、做多 B(币安)
+A-B: -0.06%     ← 做多 A(Bybit)、做空 B(币安)
```

`-A` 表示 A 腿做空,`+B` 表示 B 腿做多。

### 怎么算出来的

```
A(Bybit)   买一 $1,083.89   卖一 $1,083.9
B(币安)    买一 $1,083.3    卖一 $1,083.31

做空 A:以 A 的买一成交  =  卖出得 $1,083.89
做多 B:以 B 的卖一成交  =  买入付 $1,083.31
                            ─────────────
                            净赚 $0.58  =  +0.054%   ✓ 对上 +0.05%
```

反方向:

```
做多 A:付 A 的卖一 $1,083.9
做空 B:得 B 的买一 $1,083.3
                    ────────
                    净亏 $0.6  =  −0.055%   ✓ 对上 −0.06%
```

### ⚠️ 第二个坑:价格方向和资金费方向可能打架

```
价格便宜的方向:  -A+B  →  做空 Bybit、做多币安    (开仓白赚 5 bps)
资金费给钱方向:  +A-B  →  做空币安、做多 Bybit    (币安年化 +32.41% 更高)
                  ^^^^
                  但这个方向开仓要倒亏 6 bps
```

**两者不一致。** 你要按资金费方向开,就得接受 6 bps 的开仓成本。

## 第 7 课:钱的单位 —— bps、maker、taker

### bps(基点)

```
1 bps = 0.01% = 万分之一
100 bps = 1%
```

为什么用 bps:因为这行的成本都很小,用百分比要写一堆小数点。
「手续费 0.02%」不如「2 bps」好念。

### maker vs taker

```
taker(吃单)  你的单立刻和别人的挂单成交  →  手续费【贵】
maker(挂单)  你的单挂在盘口等别人来吃    →  手续费【便宜】,有时是负的
```

交易所鼓励你挂单(提供流动性),所以 maker 便宜。

Backpack 的例子:

```
永续 maker  2 bps        永续 taker  5 bps      → 差 2.5 倍
```

**但挂单可能不成交** —— 这就引出下一课的单腿问题。

### 屏幕上的 `限价` 和 `VA / VB`

```
□限价          勾上 = 用限价单(挂单),不勾 = 市价单(吃单)
VA / VB        限价单挂在买一卖一之外多少 %
```

挂得越远,成交概率越低,但价格越好。**这是取舍。**

## 第 8 课:风险词汇

### 杠杆(你屏幕上的 `20x`)

```
20x 杠杆 = 你出 $100 保证金,可以开 $2,000 的仓位
```

**对 carry 来说,高杠杆没有任何好处,只有坏处。**

原因:两条腿是对冲的,价格涨跌本来不影响你。**但如果一条腿被爆仓了,
对冲就断了,你瞬间变成裸单边。** 杠杆越高,越容易在插针时被爆掉。

> **建议降到 2~3x。** 你屏幕上的 `20x` 是危险的默认值。

### 保证金 / 爆仓

```
保证金率 = 账户权益 ÷ 仓位价值

跌到交易所规定的维持线以下  →  强制平仓(爆仓)
```

### ADL(自动减仓)

极端行情下,如果爆仓单来不及在市场上平掉,交易所会**强制减掉盈利方的仓位**
来配平。你可能明明没爆仓,仓位也被砍掉一部分。

**对 carry 的杀伤:一边被 ADL,对冲就断了。**

### 单腿(single-leg)

```
你想同时开两条腿,但:
  A 腿成交了,B 腿因为网络/滑点/挂单没成交
  → 此刻你只有单边敞口,价格一动就是真金白银的盈亏
```

**这是这套玩法最主要的亏损来源**,taoli.tools 存在的意义就是把这个窗口压小。

屏幕上的 `同时下单`(Parallel)就是为此 —— 两条腿同时发,而不是一前一后。

## 第 10 课:现在回头看你那一屏

把前面全部串起来:

```
A: Bybit  8H +0.0273%  →  年化 +29.89%
B: 币安   4H +0.0148%  →  年化 +32.41%

要收资金费 → 做空币安、做多 Bybit → 对应 +A-B 那一行
                                    开仓价格成本 −0.06%

净资金费收益 = 32.41% − 29.89% = +2.52% / 年
```

**而历史公共窗口算出来是 +22.13%/年。现在只有 2.52%。**

成本:

```
开仓价差   6 bps
手续费     8 bps(全 maker,四笔)
           ──────
           14 bps

回本天数 = 14 ÷ (2.52% ÷ 365 × 10000) ≈ 20 天
```

### 所以结论是

**此刻不值得进。** 不是因为策略不行,是因为**当前的费率差只有历史平均的 1/9**。

**该做的是:等一个费率差回到历史水平附近的时刻再进。**

## 第 11 课:代币化股票永续 —— 一个普通币没有的坑

SKHYNIX = **SK 海力士**,一支韩国股票。它在币安/Bybit 上是**代币化股票永续**。

两个所都在页面顶部挂了警告,很容易划过去:

> **币安**:「基础资产在其**主要市场的非交易时段**内,资金费率的波动可能会较大」
> **Bybit**:「During **weekends**, some symbols may be subject to position risk control,
> and **only reduce-only orders are allowed**」

币安的标的名旁边还有个「**非交易时段**」标签。

### 两条后果

```
① 标的休市时,资金费可能剧烈波动 —— 高费率可能只是休市假象
② 周末可能只允许减仓 —— 一条腿被限制、另一条没有,你想调都调不了
```

**第 ② 条对对冲是致命的**:carry 的前提是两条腿能同步进出。
一边被锁成只减仓,你就失去了平衡仓位的能力。

### 所以要专门查:收益是不是集中在休市时段

```bash
python3 funding_probe.py hours SKHYNIX --venue Binance
```

实测输出:

```
按 UTC 小时(该槽单独年化,假设每日发生一次):
   0:00    71 期    -5.97%   ███
   4:00    29 期   +29.89%   ███████████████████
   8:00    71 期   +52.85%   ██████████████████████████████████
  12:00    28 期    +0.32%   █
  16:00    71 期    -0.43%   █
  20:00    29 期    -1.04%   █

工作日  215 期   年化  +77.02%
周末     84 期   年化   +6.92%
周末 / 工作日 = 0.09 倍   ✅ 收益主要来自工作日(标的开市)
```

**读法:**

- **收益高度集中在 UTC 08:00 那一个结算点**(+52.85%),
  其余几个槽接近零甚至为负
- **周末只有工作日的 9%** —— 这是**好消息**:
  收益来自标的开市的正常交易日,不是来自流动性最差、限制最多的周末

> ### 🔑 如果比值反过来(周末 > 工作日)
> 那就要非常小心:**你的收益来自一个你可能没法自由进出的时段。**
> Bybit 明写周末可能只允许减仓 —— 收益全在周末 = 收益全在你手被绑住的时候。

## 第 12 课:我在写这个工具时犯的一个错(值得学)

`hours` 第一版跑出来是这样的:

```
UTC  8:00   +317.10%     ← 高得离谱
工作日     +111.77%
```

数字大得可疑。回头看**期数**才发现问题:

```
UTC  0:00   71 期
UTC  4:00   29 期    ← 只有 71 的 40%
UTC  8:00   71 期
UTC 12:00   28 期
UTC 16:00   71 期
UTC 20:00   29 期
```

**0/8/16 点各 71 期,4/12/20 点只有 29 期** ——
说明这个合约**中途从 8H 结算改成了 4H**:早期只有 0/8/16 三个槽,
后期才多出 4/12/20。

而我的代码算年化用的是:

```python
年化 = 均值 × (8760 / 中位间隔)
```

中位间隔算出来是 4h(因为后期 4H 的点更多),
**于是早期那 127 个 8H 的点被整整放大了一倍。**

### 修法:换成不依赖间隔的算法

```python
年化 = 窗口内费率总和 ÷ 窗口天数 × 365
```

**直接加总实际收到的钱,除以实际经过的时间。**
这个算法对间隔变化、缺失结算、不规则结算全都免疫。

修完:

```
UTC 8:00   +317.10%  →  +52.85%
工作日     +111.77%  →  +77.02%
```

**形状完全没变**(8:00 仍然是主要来源、周末仍然只有 9%),
说明结论是对的,错的只是倍数。

> ### 🔑 可迁移的一条
> **看到「期数」列不整齐,先问为什么。**
> 这一次它暴露的是「合约中途改了结算间隔」——
> 而这个事实会让任何「乘以固定次数」的年化算法出错。
>
> 更一般的:**任何「× 一年多少次」的换算,都要先确认那个次数在整段历史里没变过。**

## 第 13 课:怀疑一个数字的时候,怎么设计验证

**这一课不讲永续,讲方法。** 它比 SKHYNIX 这个标的本身有用得多。

前面第 11 课查出「收益高度集中在 UTC 08:00 一个结算点」。
下面是从那个发现出发的完整推理链 —— **每一步都是「提出一个能被证伪的怀疑,然后去测」**。

### 链条

```
① 观察   资金费 80% 来自 UTC 08:00 这一个结算点
              ↓
② 怀疑   会不会是标的休市造成的假象?
         (币安页面自己警告过:非交易时段费率波动可能较大)
              ↓
③ 障碍   我不知道 SKHYNIX 跟的是哪个市场的交易时段
         韩国交易所?某个 ADR?**猜错整个分析作废**
              ↓
④ 绕开   不猜 —— 标的开市时,永续成交量必然放大
         **成交量的形状就是开市时间**
              ↓
⑤ 测量   python3 funding_probe.py session SKHYNIX
              ↓
⑥ 结果   UTC  0~5 点   成交额 1~1.6 亿   ← 开市(韩国)
         UTC 13~14 点  成交额 ~1 亿      ← 开市(美股)
         UTC  8 点     成交额 5,569 万   ← **休市**
         → 怀疑成立:高费率确实出现在休市时段
              ↓
⑦ 新怀疑 休市时标的价格冻住,两个所的永续可能各自漂
         那我收到的资金费,会不会只是在**补偿基差**?
              ↓
⑧ 测量   拉两所 1000 小时 K 线,按时段统计基差
              ↓
⑨ 结果   开市  基差均值 -5.9 bps   标准差 11.7
         休市  基差均值 -2.1 bps   标准差 10.1
         两者只差 3.8 bps,休市期波动反而更小
         → **怀疑被排除,那笔钱是真给你的**
```

### 这套路里可复用的四点

**① 观察到反常,先明确写出「反常在哪」。**
不是"这个数看着怪",而是"80% 的收益集中在一个不该有收益的时点"。
**说得越具体,越容易设计验证。**

**② 遇到「我不知道 X」时,不要猜 X,要绕开 X。**
我不知道韩股几点开盘 —— 但我不需要知道。
**成交量能替我回答这个问题,而且比查日历更可靠**(它反映的是实际交易行为,
不是名义时间表)。

> 这和我们查 SVR 时那条一样:**问协议本身,不问文档。**
> 这次是:**问市场本身,不问日历。**

**③ 一个怀疑被证实之后,要立刻问「那又怎样」。**
第 ⑥ 步证实了"高费率在休市时段"—— 但这本身不构成结论。
**必须再往下问一步:这对我的钱意味着什么?**
答案是第 ⑦ 步那个新怀疑:它可能在补偿基差。

**④ 排除一个怀疑,和证实一个怀疑,同样有价值。**
第 ⑨ 步排除了"补偿基差"这个可能 —— 于是前面那个看起来很吓人的
「收益在休市时段」的发现,**杀伤力被大幅削弱了**。

如果没有第 ⑧ 步这次测量,我大概率会因为第 ⑥ 步的发现而否掉这个标的。
**那就是一次错误的否定。**

### 一个反面对照

回想一下这个项目里的失败:

```
14 天窗口 → 年化 → 得出「市场一年值 $18,682」
                  → 实际是 $721,542,低估 39 倍
```

那次为什么错?**因为我观察到一个数,直接用了,没有对它提出任何怀疑。**

> ### 🔑 一句话
> **数字本身不可信,可信的是「这个数字扛住了几次针对性的攻击」。**
> 每一次「我怀疑它是因为 X」并去测掉 X,这个数字就更硬一分。
