## 二、五个报错,五条知识

按发生顺序。**每一条都是文档里没写的。**

### 报错 1:`价格已过时`

```
2026-08-12 16:57:12 [+A-B] A: 价格已过时
```

触发条件满足了,但 Bybit 的报价超过时效,**工具主动放弃下单**。

> **这是好事,不是故障。** 调研文档里那条「报价超过 3 秒触发失败」就是这个机制 ——
> 它宁可不成交,也不在报价过期的情况下单边下。
>
> **报错比成交更让人放心。**

### 报错 2:`A 的持仓价值即将大于最大持仓价值限制: +$1`

风控参数把自己拦住了。当时的设置:

```
数量 0.01  |  A最小持仓 0.01  |  A最大持仓 0.01
                                   ^^^^^^^^^^^^
                                   上限 = 要开的量 → 一开就顶格
```

**上限必须严格大于下单量。** 而且这几个字段在面板折叠状态下看不见,
要点 `⊞` 展开;任务运行中参数是锁死的,得先点「停止」。

正确设置:

```
数量 0.01  |  最小持仓 0  |  最大持仓 0.05  |  最小价值 0  |  最大价值 100
```

### 报错 3:`110126 You must sign the required agreement before trading this contract`

**Bybit 的代币化股票(TradFi Perpetual)要单独签一份协议**,普通币不用。

API 签不了,必须去网页手工下一笔单,弹出协议后勾选同意。

> 这和[概念入门第 11 课](永续与资金费-概念入门.md)那条警告是同一件事的两面:
> **代币化股票有一整套普通币没有的规则** —— 交易时段、周末只减仓、单独协议。
> 选标的时这些都要算进去。

### 报错 4:`-2015 Invalid API-key, IP, or permissions for action`(币安)

**能读余额,不能下单。**

币安 API key 的权限是分开的:

```
☑ 启用读取           ← 有,所以余额读得到
☐ 启用合约           ← 没有,所以下不了单
```

> **「余额读得到」不等于「能交易」。** 这两件事走的是不同的权限位。
>
> 另外:如果这个 key 是在开通合约账户**之前**创建的,
> 「启用合约」可能勾不上 —— 得重新建一个 key。

### 报错 5:配置性单腿(最严重的一条)

修好 Bybit 协议之后再点「单次」:

```
taoli 日志:
  +A Bybit 永续 $1,080.32     ← ✅ 成交
  -B 币安  永续 $1,079.5      ← ❌ 没成交
```

**币安的权限问题当时还没修好,所以 A 成交、B 被拒。**

## 三、核心发现:双腿同时下 ≠ 原子性

这是今天最重要的一条,值得单独一节。

```
taoli.tools 做的:  把两条腿的下单请求【同时发出去】
它没做的:          任何一条失败时,把另一条【撤回来】
```

**A 成交了就是成交了,不管 B 有没有失败。**

### 和链上原子套利的对照

我们在 [原子套利.md](../week_2/原子套利.md) 里研究过 Solana 上的原子套利:

| | 链上原子套利 | 跨所对冲 |
|---|---|---|
| 机制 | 两条腿打包进**同一笔交易** | 两个请求同时发出 |
| 失败 | **整笔回滚**,只损失 gas | **一条成、一条败** |
| 结果 | 要么全成,要么什么都没发生 | **裸单边敞口** |

> ### 🔑 「同时」和「原子」是两个概念
> **同时** = 把时间差压到最小(taoli 做到了)
> **原子** = 要么全成要么全不成(**跨所做不到,物理上就不可能**)
>
> 两个交易所是两个独立系统,没有共同的事务边界。
> **这不是工具的缺陷,是跨所对冲的固有属性。**

### 两类单腿,严重程度完全不同

```
市场型单腿   滑点/报价过期/深度不够  →  概率性,可以靠参数压低
配置型单腿   一条腿根本不能交易      →  **必然发生,每次都单腿**
```

**我们今天遇到的是第二种**,而它本来是完全可以避免的 ——
只要在挂双边之前,先确认两条腿都真的能下出一笔单。

## 四、补上一个流程:单边验证

**这一步我们跳过了,代价是两次裸腿。现在把它固化成必做项。**

```
每次配置一个新交易对之后,挂双边之前:

  1. 按住 Shift 单边下单 → 只在 A 腿下 0.01
     成功 → 立刻平掉
     失败 → 记下报错,修好再来

  2. 同样在 B 腿单边下 0.01 → 平掉

  3. 两边都验证过,才允许点「单次」挂双边
```

**判据不是「余额读得到」,是「能下出一笔单并平掉」。**

> 这条和我们查 SVR 时那条是同一个道理:
> **问系统本身,不问它的表象。**
> 余额显示正常是表象,能不能成交才是事实。

## 六、我在这一天里犯的两个判断错误

### 错误 1:用 42 天的分布定当下的阈值

我算「阈值 0 有 38% 触发率」,用的是 **42 天**的基差分布
(均值 -3.4,标准差 10.7)。

但当时的实际区间是:

```
窗口        均值    标准差   ≥0 占比
最近 6h     -8.5     1.4       0%     ← 几乎钉死
最近 24h    -6.1     2.6       0%
最近 7 天   -5.9     4.5       8%
全部 42 天  -3.4    10.7      38%     ← 我用的这个
```

**标准差从 10.7 缩到 1.4,分布完全变了。** 按 42 天算出的阈值,
在当下的区间里触发率只有 8% —— 基本等不到。

> ### 🔑 和之前那次 39 倍的错误是同一类,但方向相反
> 上次是**窗口太短**(14 天年化,低估 39 倍)。
> 这次是**窗口太长**(42 天定阈值,而市场已经换档)。
>
> **不存在"正确的窗口长度",只存在"和你要回答的问题匹配的窗口"。**
> 问"这门生意一年值多少" → 要长窗口。
> 问"现在该不该进" → 要短窗口,而且要检查区间有没有变。

### 错误 2:让"等一个好入场点"压过了"机会正在消失"

我建议等基差转正,能省约 8 bps。但同时:

```
carry 24 分钟跌三分之一
8 bps 在 +40% 的 carry 下只值 0.74 天
```

**省 0.74 天的钱,去赌一个 8% 概率的入场点,而标的的收益在小时级衰减。**
这笔账当时应该更早算出来。

> **优化入场成本,前提是那个机会还在。**

# Day 2(08-13):第一次成功

## 一、先说改了什么

Day 1 两次单腿都不是市场原因,是**币安 API 下不了单**。真正的病根是:

```
VPS 的出口 IP 在频繁变化(实测三次请求三个不同 IP)
→ 币安 API key 的 IP 白名单挡住了下单请求
→ 但【读余额】那条路是通的,所以界面上一切正常
```

**换成固定 IP 的主机之后,一次就通了。**

> ### 🔑 这个坑值得单独记
> 症状是「余额读得到、下单报 -2015」,很容易误判成权限没开。
> 实际是 **IP 白名单 + 出口 IP 漂移**。
>
> 判别方法:**用同一把 key 分别打现货和合约的认证端点**。
> 都失败 → IP 问题;现货通、合约不通 → 权限问题。

昨天 +47.9% 的机会完全消失。

对 22 个流动性达标的币做**币安 vs Bybit 历史稳定性**筛选:

```
判据:不反号 + 两半 ≤1.8 倍 + 净 ≥3%
结果:22 个里只过了 2 个

## 三、又一个参数坑:持仓上下限是有符号的

```
[-A+B] A: A 的持仓即将小于最小持仓限制: 0
```

`-A+B` 是**做空 A 腿**,Bybit 持仓会变成 **-0.04**。
而 `A最小持仓 = 0` —— 负数低于下限,被拦。

Day 1 做的是 `+A-B`(做多 A),持仓 0 → +0.04,所以 `最小持仓 0` 没问题。
**方向反了,这个参数也得跟着反:**

```
A最小持仓   0  →  -0.05      ← 允许做空
A最小价值   0  →  -100
```

还有一个纯前端的坑:改完 `最小持仓 = -0.05` 之后,`最大持仓` 输入框
报「有效值是 -0.05 和 0.95」—— 那是 HTML `number` 输入的 `step` 校验
(step=1,起点 -0.05)。填 `0.95` 即可,它只是个护栏,不影响实际下单量。

## 五、★ 最重要的发现:基差噪音 ≈ 0.7 天的资金费

开仓几分钟后,两条腿**同时**浮亏:

```
Bybit 空  143.50 → 标记 143.59    -$0.0036
币安  多  143.47 → 标记 143.4594  -$0.0004
                                  ─────────
                                  -$0.0040
```

对冲没失效 —— **是【基差】动了:**

```
开仓时  两所标记价差 +0.030
几分钟后             +0.131      扩大 7 bps
```

**你做空这个价差,它扩大你就亏。**
价格本身的涨跌被对冲掉了,**但两个所之间的价差没有被对冲**。

> ⚠️ **修正(08-13)**:原文写的是「这是唯一的真实风险来源」,不准确。
> 准确的说法是:
>
> **在两条腿都已成功建立、且不考虑执行和交易所事件的前提下,
> 短期价格盈亏的主要剩余风险是跨所基差变化。**
>
> 完整的风险清单还包括:两腿非原子成交 / 单腿、API 与网络故障、
> maker 未成交被迫 taker、流动性枯竭、资金费突然反号、
> 两边结算时点不一致、交易所规则变更、ADL 与强平规则差异、
> 代币化股票的特殊规则、标的公司行为(corporate action)。

### 量化一下

开仓后 11 分钟的连续记录(25 个采样点):

```
基差区间   -5.5 ~ +1.6 bps    宽度 7.1 bps
在 $5.74 名义上 = $0.00405

一天资金费收入 = $0.00599
              ─────────────
基差一次日内波动 ≈ **0.7 天**的资金费
```

> ### 🔑 这条改变了对这个策略的理解
> **短期完全被基差主导,资金费只有长期持有才会浮现。**
>
> 今天开仓、明天看盈亏,结果基本是随机的 ——
> 因为一次普通的基差波动就能吃掉一天的收益。
>
> **所以之前算的「回本 0.5 天」是误导性的** ——
> 那只算了手续费,**没算基差波动**。
> 真正的「多久能确定盈利」,要长得多。

### 对策略设计的直接影响

```
❌ 不能做短线进出 —— 每次进出都暴露在基差波动里,而收益按天计
✅ 要么持有足够久(周级),让基差波动被平均掉
✅ 要么只在基差【极端偏离】时进场,让均值回归成为额外收益
```

第二条正是 `carry_watch.py` 里那个 z 值判据在做的事 ——
只是 Day 1 我把它的阈值定错了(用 42 天分布定当下阈值)。

## 八、盈亏到底怎么算(公式推导)

### 单条腿

```
盈亏 = 数量 × 方向 × (标记价 − 开仓价)
       方向:多头 = +1,空头 = −1
```

**注意用的是「标记价」,不是最新成交价。** 两个所的标记价不同,
所以两条腿的数字不会完全对称。

代实盘的数:

```
Bybit 空   0.04 × (−1) × (143.71 − 143.50) = −$0.0084
币安  多   0.04 × (+1) × (143.685 − 143.47) = +$0.0086
                                              ─────────
                                              +$0.0002
```

### 两条腿相加,化简之后

```
空腿 = qty × (空开仓价 − 空标记价)
多腿 = qty × (多标记价 − 多开仓价)
相加 = qty × [(空开 − 多开) − (空标 − 多标)]
     = qty × (开仓时价差 − 当前价差)
```

> ### 🔑 **整个仓位的盈亏,只由基差变化决定,与价格本身完全无关。**
>
> ```
> 净盈亏 = 数量 × (开仓价差 − 当前价差)
>        = 0.04 × (0.030 − 0.0246)
>        = +$0.0002    ✓ 和分别算的结果一致
> ```
>
> SOXL 涨到 200 还是跌到 100,你都不赚不亏。
> **你赌的不是价格,是「两个所之间的差不要变太多」。**
>
> 这就是 delta 中性在数学上的样子。

### 加上资金费,完整的账

```
总收益 = 数量 × (开仓价差 − 当前价差)      ← 基差,来回随机波动
       + Σ 每次结算的资金费                ← 单向累积,这才是收入
       − 手续费                            ← 一次性
```

**三项里只有第二项是「收入」,另外两项一个是噪音、一个是成本。**

实盘验证(08-13):

```
基差盈亏    +$0.0002 ~ +$0.0034   (来回晃)
资金费      +$0.0013              (16:00 那次结算,钱包 15.0000 → 15.0004)
手续费      −$0.0016              (开仓)
```

## 九、~~这门生意能不能做~~ ⛔ 本节结论已撤回

> ## ⛔ 2026-08-13 撤回声明
>
> **下面整节的结论建立在两个错误的模型上,不能用于决定资金投入。**
> 原文保留,因为「用错模型得出看似合理的结论」本身是值得记录的一次失败。
>
> ### 错误 1:把资金费当成连续累计
>
> 原文用 `carry / 365 / 24 / 60 × 窗口分钟数` 估算能收多少 bps。
> **这假设资金费按分钟连续累积 —— 错的。**
>
> 永续资金费按**结算时点离散发生**(4H 或 8H 一次):
>
> ```
> 高 carry 持续 5 小时,但没跨过结算点  →  实收 0
> 只持续 10 分钟,但跨过结算点          →  实收【完整一期】
> ```
>
> 代 SKHYNIX 验算:47.9% 年化、8H 结算 → 每期 **4.37 bps**。
> 原文算的是 1.91 bps。**没跨结算是 0,跨了是 4.37 —— 两个方向都错。**
>
> **所以「高 carry 只持续小时级,收不回手续费」这个结论不成立** ——
> 它取决于窗口有没有跨过结算点,而原文根本没检查这件事。
>
> ### 错误 2:基差噪音从 11 分钟外推到「7 bps/天」
>
> 原文用 SOXL **11 分钟、25 个采样**的极差(7.1 bps)当作日噪音,
> 再套 `噪音 = 7 × √T` 的随机游走模型。
>
> **11 分钟的极差不是日标准差。** 而且随机游走假设没有验证过 ——
> 基差也可能是均值回归的,那样长期噪音反而收敛。
>
> 这正是本项目记录过三次的取样错误(14 天低估 39 倍、4 天高估 9.3 倍、
> 42 天分布定错阈值),**这是第四次**。
>
> ### 因此以下数字全部作废
>
> ```
> ❌ 「20% 年化是门槛」
> ❌ 「3% 要 72.5 天」「5% 要 26.1 天」
> ❌ 「SKHYNIX 只能收 1.91 bps」「SOXL 只能收 0.43 bps」
> ❌ 「基差噪音 = 7 bps × √T」
> ```
>
> ### 正确的做法(已实现在 `carry_watch.py --scan`)
>
> ```
> 统计对象从「窗口时长」改成【真实结算事件】
>   · 从 nextFundingTime 的跳变检测结算
>   · 用【结算前】最后一个快照的费率,不是结算后的新预测
>   · 数窗口跨过几次结算,而不是持续了几分钟
> 基差噪音改成按 1h / 8h / 1d / 3d 多个 horizon 实测分布
> ```
>
> **这一节要等 2~4 周 settlement-centric 数据回来才能重写。**

### 判据

```
往返手续费      8 bps(全 maker,4 笔)

```

**两天里遇到的两次高 carry 机会,都在 1~4 小时内归零。**

> **不是"能不能赚",是"能赚的窗口活不到你收回手续费"。**
>
> 而且它不是执行问题,是**费率结构**决定的:
> 8 bps 的往返成本,要求 carry × 持续时间 > 8 bps。
> 我们观察到的机会,这个乘积都不够。
