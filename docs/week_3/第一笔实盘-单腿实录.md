## 二、五个报错,五条知识

按发生顺序。**每一条都是文档里没写的。**

### 报错 1:`价格已过时`

```
2026-08-12 16:57:12 [+A-B] A: 价格已过时
```

触发条件满足了,但 Bybit 的报价超过时效,**工具主动放弃下单**。

> **这是好事,不是故障。** 调研文档里那条「报价超过 3 秒触发失败」就是这个机制 ——
> 它宁可不成交,也不在报价过期的情况下单边下。
>
> **报错比成交更让人放心。**

### 报错 2:`A 的持仓价值即将大于最大持仓价值限制: +$1`

风控参数把自己拦住了。当时的设置:

```
数量 0.01  |  A最小持仓 0.01  |  A最大持仓 0.01
                                   ^^^^^^^^^^^^
                                   上限 = 要开的量 → 一开就顶格
```

**上限必须严格大于下单量。** 而且这几个字段在面板折叠状态下看不见,
要点 `⊞` 展开;任务运行中参数是锁死的,得先点「停止」。

正确设置:

```
数量 0.01  |  最小持仓 0  |  最大持仓 0.05  |  最小价值 0  |  最大价值 100
```

### 报错 3:`110126 You must sign the required agreement before trading this contract`

**Bybit 的代币化股票(TradFi Perpetual)要单独签一份协议**,普通币不用。

API 签不了,必须去网页手工下一笔单,弹出协议后勾选同意。

> 这和[概念入门第 11 课](永续与资金费-概念入门.md)那条警告是同一件事的两面:
> **代币化股票有一整套普通币没有的规则** —— 交易时段、周末只减仓、单独协议。
> 选标的时这些都要算进去。

### 报错 4:`-2015 Invalid API-key, IP, or permissions for action`(币安)

**能读余额,不能下单。**

币安 API key 的权限是分开的:

```
☑ 启用读取           ← 有,所以余额读得到
☐ 启用合约           ← 没有,所以下不了单
```

> **「余额读得到」不等于「能交易」。** 这两件事走的是不同的权限位。
>
> 另外:如果这个 key 是在开通合约账户**之前**创建的,
> 「启用合约」可能勾不上 —— 得重新建一个 key。

### 报错 5:配置性单腿(最严重的一条)

修好 Bybit 协议之后再点「单次」:

```
taoli 日志:
  +A Bybit 永续 $1,080.32     ← ✅ 成交
  -B 币安  永续 $1,079.5      ← ❌ 没成交
```

**币安的权限问题当时还没修好,所以 A 成交、B 被拒。**

## 三、核心发现:双腿同时下 ≠ 原子性

这是今天最重要的一条,值得单独一节。

```
taoli.tools 做的:  把两条腿的下单请求【同时发出去】
它没做的:          任何一条失败时,把另一条【撤回来】
```

**A 成交了就是成交了,不管 B 有没有失败。**

### 和链上原子套利的对照

我们在 [原子套利.md](../week_2/原子套利.md) 里研究过 Solana 上的原子套利:

| | 链上原子套利 | 跨所对冲 |
|---|---|---|
| 机制 | 两条腿打包进**同一笔交易** | 两个请求同时发出 |
| 失败 | **整笔回滚**,只损失 gas | **一条成、一条败** |
| 结果 | 要么全成,要么什么都没发生 | **裸单边敞口** |

> ### 🔑 「同时」和「原子」是两个概念
> **同时** = 把时间差压到最小(taoli 做到了)
> **原子** = 要么全成要么全不成(**跨所做不到,物理上就不可能**)
>
> 两个交易所是两个独立系统,没有共同的事务边界。
> **这不是工具的缺陷,是跨所对冲的固有属性。**

### 两类单腿,严重程度完全不同

```
市场型单腿   滑点/报价过期/深度不够  →  概率性,可以靠参数压低
配置型单腿   一条腿根本不能交易      →  **必然发生,每次都单腿**
```

**我们今天遇到的是第二种**,而它本来是完全可以避免的 ——
只要在挂双边之前,先确认两条腿都真的能下出一笔单。

## 四、补上一个流程:单边验证

**这一步我们跳过了,代价是两次裸腿。现在把它固化成必做项。**

```
每次配置一个新交易对之后,挂双边之前:

  1. 按住 Shift 单边下单 → 只在 A 腿下 0.01
     成功 → 立刻平掉
     失败 → 记下报错,修好再来

  2. 同样在 B 腿单边下 0.01 → 平掉

  3. 两边都验证过,才允许点「单次」挂双边
```

**判据不是「余额读得到」,是「能下出一笔单并平掉」。**

> 这条和我们查 SVR 时那条是同一个道理:
> **问系统本身,不问它的表象。**
> 余额显示正常是表象,能不能成交才是事实。

## 六、我在这一天里犯的两个判断错误

### 错误 1:用 42 天的分布定当下的阈值

我算「阈值 0 有 38% 触发率」,用的是 **42 天**的基差分布
(均值 -3.4,标准差 10.7)。

但当时的实际区间是:

```
窗口        均值    标准差   ≥0 占比
最近 6h     -8.5     1.4       0%     ← 几乎钉死
最近 24h    -6.1     2.6       0%
最近 7 天   -5.9     4.5       8%
全部 42 天  -3.4    10.7      38%     ← 我用的这个
```

**标准差从 10.7 缩到 1.4,分布完全变了。** 按 42 天算出的阈值,
在当下的区间里触发率只有 8% —— 基本等不到。

> ### 🔑 和之前那次 39 倍的错误是同一类,但方向相反
> 上次是**窗口太短**(14 天年化,低估 39 倍)。
> 这次是**窗口太长**(42 天定阈值,而市场已经换档)。
>
> **不存在"正确的窗口长度",只存在"和你要回答的问题匹配的窗口"。**
> 问"这门生意一年值多少" → 要长窗口。
> 问"现在该不该进" → 要短窗口,而且要检查区间有没有变。

### 错误 2:让"等一个好入场点"压过了"机会正在消失"

我建议等基差转正,能省约 8 bps。但同时:

```
carry 24 分钟跌三分之一
8 bps 在 +40% 的 carry 下只值 0.74 天
```

**省 0.74 天的钱,去赌一个 8% 概率的入场点,而标的的收益在小时级衰减。**
这笔账当时应该更早算出来。

> **优化入场成本,前提是那个机会还在。**
