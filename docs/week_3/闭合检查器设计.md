# 闭合检查器:设计文档

> 2026-08-11　|　接替「16 天原型」之后的主线
> **规格不是凭空设计的,是从这四周四次失败倒推出来的。**

---

## 一、为什么不叫「异常扫描器」

最初的想法是:每天自动扫新池、新市场、新永续、新金库,
把**经济关系明显不闭合**的扔给 Hermes 深挖。

方向对,但**过滤器抓不到东西**。理由很硬 ——

### 我们证伪过的每一个方向,表面上看都是闭合的

| 方向 | 扫描器会看到什么 | 真实失败点 | 需要专门测什么 |
|---|---|---|---|
| 跨链稳定币套利 | 两条链有价差 | **LI.FI 25 bps 服务费地板** | 142 次报价实测 |
| 收费站 LP | 手续费率很高 | **手续费只覆盖 15.6% 的损失** | 回测无常损失 |
| 清算 | 奖励 5%,闪电贷零成本 | **SVR 回收 89%** | 问协议它读哪个喂价 |
| DOS 新池 | 建池价 0.10,现价 1.45 | **流动性区间在别处,0.10 不可成交** | 解 `ModifyLiquidity` |

**没有一个是"新对象自己看起来不对"。**

异常从来不在新对象身上,而在**新对象与某个已存在的东西之间的关系**里
—— 而那个"东西"扫描器事先不知道去哪找。

DOS 那个尤其典型:扫描器看到「新池子,`sqrtPriceX96` 解出初始价 0.10」,
完全正常。要发现「0.10 根本不可成交」,得去解流动性区间 ——
**而你只有在已经怀疑它的时候,才会想到去解。**

> ### 结论
> **「看起来异常」不是一个可执行的判据。**
> 换成一个可执行的:**「我能不能写出完整的往返闭环,并且每条腿都有价」。**

## 二、四问过滤器

对每个新对象,强制回答四个问题。**顺序不能变,前一问不过就不问下一问。**

```
① 起点资产 == 终点资产 吗?
      不是  →  这不是套利,是投机。出局。

② 另一条腿在哪?现在能报出价吗?
      报不出  →  出局(而不是"假设它值多少")。

③ 每条腿的成本都有实测值吗?
      有任何一项"待定"  →  **不出总数**,进待测队列。

④ 谁已经在做?份额多集中?
      Top3 > 80%  →  出局。
```

四问全过,才轮到 Hermes。

### 每一问都是一次失败换来的

**① 起点 == 终点** —— 来自铁律 1(token 口径闭环)。

DOS 池子死在这里:没有第二个场子,「在 0.05 买入」的终点是**持有 DOS**,
不是回到 USDT。**那不是套利,是拿套利当名义的投机。**
收费站 LP 也死在这里。

**② 另一条腿能报价** —— 来自跨链套利。

价差看得见,但真去 LI.FI 报价才发现有 25 bps 的服务费地板。
**「理论上应该能」和「现在报个价试试」是两件事。**

**③ 有"待定"就不出总数** —— 来自成本模型。

当时我们定的规矩:**主项没测出来,就拒绝打印合计。**
一个带着"待定"的总数会被当成结论用 —— 我自己就干过
(明知 14 天样本不可靠,还是把 $1,439 写进了结论表)。

> **加免责声明不等于没犯错。免责声明只是让错误更刺眼。**

**④ 集中度** —— 来自 SVR / Atlas 和多链清算人调查。

```
Atlas solver         7 天 3 个中标者,Top1 84.6%
Avalanche 清算人     14 天 4 个,Top3 95%
Optimism 清算人      14 天 8 个,Top3 79%
Arbitrum 清算人      14 天 11 个,Top3 66%
```

**开放但已被占满的市场,和封闭的市场,结果一样。**

## 三、两条硬约束

### 约束 1:范围先砍到一个

「新池 + 新 market + 代币化资产 + 永续 + 借贷 + 金库 × 多链」
是六个方向的集成工作量。**先只做一个我们已经有工具的。**

首选 **PancakeSwap Infinity 建池(BSC)** —— 查 DOS 那天已经跑通全链路:

```
Initialize 事件      → 池子 ID、币对、hook、手续费、sqrtPriceX96 初始价
ModifyLiquidity 事件 → 流动性实际覆盖的价格区间   ← 关键,别人漏的就是这个
Swap 事件            → 首笔成交价、价格轨迹、谁在交易
```

跑通一个再复制到下一个对象类型。

### 约束 2:第一版的任务是产出基准率,不是找钱

这是今天栽两次换来的:

```
「任意喂价更新」命中率 36.8%  →  基准率接近 100%,指标无信息量
14 天窗口年化           →  比 160 天真实值低估 39 倍
```

所以第一版只回答三个数:

```
一天冒出多少个新对象?
其中多少个四问全过?
全过的那些,多久被别人吃掉?被谁吃?
```

**这三个数决定整件事值不值得继续。**
如果两周里零个通过闭合检查 —— 那结论和清算线一样硬,
但只花了两周,而不是四周。

## 四、输出格式

不是"发现 N 个异常",而是**一本可复核的台账**。每个对象一行:

```
对象      pancake-infinity:0x2e9c6c…
时间      2026-08-09 08:10:50 UTC
币对      USDT / DOS
① 闭环    ❌  DOS 无第二场子(V2/V3 池均不存在,已用 CREATE2 验证)
② 报价    ——  (①未过,不再问)
③ 成本    ——
④ 集中度  ——
判定      出局:不闭合
```

**"出局"必须带可打印的理由。** 不是"感觉不行"。

对通过 ① ② 但 ③ 有待定项的,进待测队列并明确写出**缺哪个数、怎么测**:

```
③ 成本    ⚠️ 待定:变现滑点未知
          测法:用 5 档 size 打 /quote,拟合冲击曲线(复用 cost_probe.py)
```

## 五、和 Hermes 的分工

```
扫描器  →  机械过滤,只输出「四问全过」的候选  ← 便宜,可全量跑
Hermes  →  只看候选,做需要判断力的深挖        ← 贵,必须省着用
```

**过滤必须狠在 Hermes 之前。** BSC 一天新池数以千计,绝大多数是垃圾;
把"看起来异常"的直接喂给 Hermes,等于花钱买噪音。

---

## 六、一句必须说清楚的话

**这个扫描器大概率还是会输出一长串"不闭合"。**

差别在**成本**:

```
以前   一个方向  ≈  一周人工
以后   几十个    ≈  一天自动,人只看通过的
```

**证伪不会变少,只会变便宜。**

如果接受这个交换,这条路值得做;如果期待的是"扫出一个能直接赚钱的机会",
那按前四周的经验,大概率会失望。

## 八、四条不会过期的方法

比任何一个具体结论都值钱,写在这里当扫描器的验收标准:

1. **问协议本身,不问文档** —— 协议随时换源,文档滞后
2. **分清系统里的角色** —— 别把 bundler 数当参与者数
3. **解码要有外部可验证量** —— 用币价校验解码,而不是"看起来合理"
4. **偏态分布下,取样窗口必须覆盖极端事件** —— 否则测的是"平时",
   而平时恰恰不是这门生意

## 补:第 ⑤ 问 —— 筛选目标必须和使用目标一致

> 2026-08-14 新增。这一条是把自己的筛选器证伪之后加的。

### 事情经过

给资金费 carry 写了个 `pair-screen`,判据是:

```
不反号 + 两半比值 ≤ 1.8 倍 + |净年化| ≥ 3%
```

「两半比值」= 把历史劈成近一半 / 远一半,分别算年化,看两者差几倍。
**比值小 = 这个价差很稳定。** 听起来很合理。

24 个币筛出 3 个,然后拿去看实时:

```
SNDK   历史 +5.26%  →  当前 +0.86%
SOXL   历史 -4.59%  →  当前  0.00%
AKE    历史 -6.27%  →  当前 +5.47%
```

**三个里两个当前机会是零。** 于是去查被淘汰的那批:

```
                  通过组      淘汰组
当前 |净| 中位     0.86%      15.47%
当前 |净| 最大     5.47%     354.90%
                            ─────────
             淘汰组是通过组的 18 倍
```

### 为什么必然如此

```
「两半比值 ≤ 1.8」  =  这个价差【一直没怎么变】
一直没变的价差      =  一直是那个小数
                    →  现在也小,以后大概率也小

而机会恰恰来自【变了】
```

SKHY 历史 -3.00%,当前 **-51.81%**;COTI 历史 +3.95%,当前 **-354.9%**。
**这些全被"不稳定"淘汰掉了。**

> ### 🔑 我在用「不会出现机会」当筛选条件

### 和前面几次错误的区别

```
14 天窗口年化       →  取样窗口太短
42 天分布定阈值     →  取样窗口太长
11 分钟外推日噪音   →  样本量太小
两半比值筛稳定性    →  **筛选目标和使用目标不一致**   ← 这次
```

前三次是**取样错误**,数据本身没问题,是我取错了范围。
**这次是目标错误** —— 数据和统计都对,但我筛的东西(历史稳定)
和我要用的东西(现在有机会)**不但不同,而且负相关**。

**这类错误更隐蔽:因为筛选器工作得很好,只是在做一件没用的事。**

### 所以四问要变五问

```
① 起点资产 == 终点资产?
② 另一条腿在哪?能报价吗?
③ 每条腿的成本都有实测值吗?
④ 谁已经在做?份额多集中?
⑤ ★ 我这个筛选条件,和我要用它做的决定,是同一件事吗?
```

**第 ⑤ 问的检验方法:把被筛掉的那批也算一遍指标,和通过的比。**

如果淘汰组在你真正关心的维度上明显更好,**筛选器就是反的**。

这个自检已经写进 `funding_probe.py pair-screen` —— 每次跑都会自动打印:

```
=== ⚠️ 筛选器自检:稳定性筛选是不是把机会筛掉了 ===
  通过的 3 个   当前 |净| 中位  0.59%   最大  5.47%
  淘汰的 17 个  当前 |净| 中位  5.66%   最大 84.48%
  🔴 **淘汰组的当前机会是通过组的 10 倍**
```

> **可迁移的一条:任何筛选器都要跑一次「淘汰组对照」。**
> 只看通过的那批,永远发现不了自己在反向选择。

### 那正确的判据是什么

不是「历史稳定」,而是:

```
① 现在够大                       ← carry_watch 实时能看
② 大到能撑过至少 1~2 次结算       ← **只有 settlement 数据能回答**
```

**第 ② 条正是那个 2~4 周扫描要测的东西。**
在数据出来之前,**我们没有可靠的选币判据** —— 这是当前的诚实状态。
