# 第一部分:技术知识点

## 一、链上:清算与 MEV

### 1.1 Aave V3 的关键接口

```
getUserAccountData(address)     总抵押/总负债/可借/清算阈值/LTV/健康度
getUserConfiguration(address)   位图!每个储备 2 bit:是否抵押、是否借入
getUserEMode(address)           用户的 eMode 类别
getEModeCategoryData(uint8)     ⚠️ 返回【动态结构体】,ABI 解码有 0x20 偏移
```

**选择器:**
```
liquidationCall(address,address,address,uint256,bool)  = 0x00a718a9
```

**自定义错误:**
```
HealthFactorNotBelowThreshold()  = 0x930bb771
MustNotLeaveDust()
```

### 1.2 eMode 会让健康度算错 16%

不处理 eMode,自己算的 HF 会比链上低 16.61%。因为 eMode 类别下
同类资产(如全是稳定币)的清算阈值更宽松。

**教训:任何自己复算的协议状态,都要和链上返回值对账。对不上就是漏了配置。**

### 1.3 用 eth_call 探测,比扫字节码可靠

我们在 Pool 实现的字节码里**没扫到** `liquidationCall` 的选择器,
差点得出"这个函数不存在"的结论。但用 `eth_call` 打过去:

```
返回空 revert          → 函数确实不存在
返回 4 字节自定义错误   → 函数存在,只是业务上拒绝了你
```

拿到 `0x930bb771`(HealthFactorNotBelowThreshold)就证明函数在。

> **教训:问系统本身,不问它的表象。字节码扫描是表象,eth_call 是问本人。**

### 1.4 P1 模拟:用没钱的地址去试探

```python
# Aave 的健康度检查发生在【代币转账之前】,所以用一个没钱的地址模拟,
# revert 的位置就能区分:
#   revert HealthFactorNotBelowThreshold  → Aave 拒绝,仓位健康
#   revert 在 ERC20 转账处                → **Aave 的检查全过了**
```

**零成本判断"这笔清算现在能不能做"。**

### 1.5 Chainlink SVR(Smart Value Recapture)

这是清算线的死因。

```
传统:  预言机更新 → searcher 抢跑清算 → 利润归 searcher
SVR:   双聚合器架构,OEV 先进入拍卖,回收给协议
```

实测(Arbitrum):**回收率 89.2%**,留给 solver 的残值池约 $253k/年,
且 **Top1 solver 占 84.6%**。

### 1.6 Atlas(FastLane,已被 Chainlink 收购)

```
入场:  permissionless,0.1 ETH 保证金(约 $192)
```

### 1.8 AnswerUpdated 事件的解析陷阱


**`current` 和 `roundId` 都是 indexed**,所以 data 段里**只有 `updatedAt`**,

## 二、永续合约与资金费

### 2.1 资金费是【离散事件】,不是连续利息

这是最贵的一课。

```
❌ 错:carry / 365 / 24 / 60 × 持有分钟数
✅ 对:只在结算时点划转。没跨过结算,一分钱不动
```

**实例:** 某时段年化 +40% 持续 5 小时但未跨结算 → 收益 **0**,不是 2.28 bps。

### 2.2 年化必须按各所自己的结算间隔归一化

```
A 所 8H  单期 +0.0273%  →  ×3×365 = 29.89%
B 所 4H  单期 +0.0148%  →  ×6×365 = 32.41%   ← 单期只有一半,年化反而更高
```

**单期费率之间不可直接比较。**

更稳的写法(不依赖间隔):

```python
def annualise(pts):
    """把窗口内收到的费率直接加总,除以窗口天数,再乘 365。"""
    days = (pts[-1][0] - pts[0][0]) / 86400000
    return sum(r for _, r in pts) / days * 365 * 100
```

### 2.3 资金费的方向

```
费率为正  →  多头付、空头收
费率为负  →  空头付、多头收
```

### 2.4 永续用资金费替代交割来实现收敛

永续没有到期日,但资金费让偏离变得昂贵,把价格拉回指数。
**这就是期货的 convergence 机制在永续上的等价物。**

可实测:跨所基差呈均值回归,半衰期约 7~22 小时。

### 2.5 对冲组合的盈亏,只由基差决定

```
空 S 所 q 手 @ P_S⁰,多 L 所 q 手 @ P_L⁰

PnL = q(P_S⁰ − P_Sᵗ) + q(P_Lᵗ − P_L⁰)
    = q[(P_S⁰ − P_L⁰) − (P_Sᵗ − P_Lᵗ)]
    = q × (开仓基差 − 当前基差)                    ∎
```

**价格水平项被完全消去。标的从 56 涨到 200,盈亏不变。**

真实账单验证(HYPE 误平那次):

```
公式:0.09 × (+0.004 − +0.084) = -0.0072
两腿实际合计                    -0.0072    ✅ 分毫不差
```

### 2.6 标记价格 vs 最新成交价

强平判定用**标记价格**(指数价格 + 溢价指数合成),不是最新成交价。
目的是防止单所插针触发连环清算。

### 2.7 资金费上限,以及它造成的结构

```
币安 ±2.000%   Bybit ±2.500%   MEXC ±3.000%   Bitget ±1.875%
```

**各所上限不同 → 极端行情下一边触顶一边没触顶 → 结构性价差。**

COTI 实例:Bybit 打到 -2.0000%,币安最差才 -0.599%,
空币安 + 多 Bybit,45 小时净 **+276.5 bps**。

**但必须是【单边触顶】。** ACE 实测两边同时触顶 → 净差归零,
而且失衡从资金费通道**转移到价格通道**:基差爆到 -259.8 bps(-9σ)。

> **上限锁住一个通道,压力会从另一个通道冒出来。**

### 3.3 盘口价差是和手续费同量级的成本

```
开仓 = (空腿买一 − 多腿卖一) / mid       ← 可成交的入场价差
关仓 = 同方向平仓时的价差
开仓 − 关仓 = 【往返盘口成本】= 两所买卖价差之和
```

CAP 验证:
```
币安价差 1.55 + Bybit价差 7.75 = 9.30 bps
QQQ.BOT 给的 开仓−关仓 = 6.1 bps       ✅ 同量级
```

实测六个币的往返盘口成本:**6~18 bps** —— 和手续费一样重。

**你一单就把买一吃光。** 而且深度是秒级变化的。

### 3.6 非原子性 = 单腿风险

"同时下单"≠ 原子。两个独立撮合引擎之间没有共同事务边界。

**实际踩过两次:**

第 ② 种更危险:界面上看着"两条腿都有"。


## 四、统计与计量

### 4.1 均值回归 vs 随机游走 —— 两个模型给出相反策略

实测 HYPE 基差:

```
持有      实测     随机游走预测    OU 上界(√2·σ∞)
   8h     2.27         2.27           3.10
  24h     2.64         3.93           3.10
  72h     2.94         6.81           3.10
 168h     3.07        10.40           3.10
                    高估 3.4 倍      差 1%
```

**OU 模型的预测和实测差 1%,随机游走差 3.4 倍。**

```
随机游走  →  持有越久风险越大  →  应该快进快出
均值回归  →  风险有上界        →  【应该拿住】
```

**误用随机游走会导致过度交易,把本来就薄的 carry 全交给手续费。**

### 4.2 Ornstein-Uhlenbeck 过程

```
Var(B_{t+T} − B_t) = 2·σ∞²·(1 − e^(−θT))
半衰期 = ln2 / θ
T → ∞ 时标准差上界 = √2 · σ∞
```

反解半衰期:HYPE 得 7.2h(T=8) / 12.8h(T=24) / 21.6h(T=72)。

**半衰期随观测尺度单调上升 → 单因子 OU 不够,存在多时间尺度。**
快分量是盘口噪音,慢分量是相对定价漂移。
**用短窗口反解会低估长期风险。**

### 4.3 信噪比的增长阶数

```
OU  信噪比 ∝ T / 常数     →  【线性】增长
RW  信噪比 ∝ T / √T = √T  →  【平方根】增长
```

实例(HYPE,carry +8.5%,σ∞ 2.19 bps,半衰期 12h):

```
 T      收益      噪音     比值
1 天    2.33      2.68     0.87    ← 噪音主导
3 天    6.99      3.07     2.27
7 天   16.30      3.10     5.26    ← 收益主导
```

**噪音 3 天后饱和,收益继续线性累积。**

### 4.4 厚尾:均值和中位数差 21 倍

```
清算奖励      中位 $0.03    均值 $81.18      差 2700 倍
45h 持有收益  中位 +0.37    均值 +7.64 bps   差 21 倍
              最大 +276.5(COTI)→ 占合计的 98%
```

**总额 = 笔数 × 均值,这是恒等式。** 用中位数估总额永远是错的。
但用均值描述"典型情况"也是错的。**先想清楚你要回答哪个问题。**

### 4.5 取样窗口:短了、长了都会错

```
14 天窗口年化清算规模   → $18,682   实际 $721,542   低估 39 倍
4 天窗口看资金费        → BILL +126%  344 天真值 +13.57%   3/5 符号反了
1 天窗口               → VELVET +28%  33 天真值 -10.6%    符号反了
42 天分布定阈值         → 实际触发率 8%,预期 38%(近期 std 1.4 vs 42天 10.7)
11 分钟外推日噪音       → 样本量根本不够
```

**没有"正确的窗口长度",只有"和问题匹配的窗口长度"。**

### 4.6 基准率

```
"清算前 12 区块内有任意喂价更新" 命中率 36.8%
→ 听起来很高,但【随机情况下的基准率接近 100%】
→ 36.8% 实际上【低于随机】
```

**任何命中率,先算基准率再说。**

### 4.7 t 检验:长期收益和 0 有没有区别

```
t = 均值 / 标准误 = 均值 / (标准差 / √n)
```

比"标准差是均值的 N 倍"讲究得多 —— 那个判据**没考虑样本量,
样本越多越容易报警,方向是反的**。

实测:
```
币        样本天   长期净%   ±SE    t
VELVET    33.3    -10.6    2.7   -4.0   🔴 显著为负
HYPE      16.7     -1.0    1.2   -0.8   ⚪ 和 0 无区别
SNDK      66.7     +5.1    2.7   +1.9   ⚪ 和 0 无区别
```

### 4.8 自相关会让 t 值虚高

t 检验假设各期独立,而资金费是自相关的。

```
n_eff = n × (1 − ρ₁) / (1 + ρ₁)
```

实测修正:
```
币        n     ρ₁    n_eff   t朴素   t修正
ZEST     200   0.21   132     6.5     5.3   ✅
MAGMA    200   0.41    84     6.1     3.9   ✅
BLUAI    200   0.64    44     3.5     1.6   🔴 净值最高那个,修正后不显著
```

**高 carry 和高自相关是一起来的,这不是巧合。**

### 4.9 历史必须按【你要开的方向】读

净值是有向的。无方向的 t 会把"反着做能赚"误报成"能赚"。

```
hist_in_your_direction = 历史均值 × sign(当前净值)
```

### 4.10 「多数期数为负」不能单独当红旗

COTI 实测:

```
61% 的结算期亏钱,但总额 +276.5 bps
  赢的 11 次  平均 +42.1
  输的 17 次  平均 -11.0     赢面是输面的 3.8 倍
```

**正偏态分布本来就长这样。多数期数亏钱是赢家的常态,不是缺陷。**

只有当**均值也立不住**时,高负比才是坏消息。

## 方法一:五问闭合检查器

对每个新想法,强制按顺序回答。**前一问不过就不问下一问。**

```
① 起点资产 == 终点资产吗?
      不是  →  这不是套利,是投机。出局。

② 另一条腿在哪?现在能报出价吗?
      报不出  →  出局(而不是"假设它值多少")。

③ 每条腿的成本都有实测值吗?
      有任何一项"待定"  →  【不出总数】,进待测队列。

④ 谁已经在做?份额多集中?
      Top3 > 80%  →  出局。

⑤ 我这个筛选条件,和我要用它做的决定,是同一件事吗?
```

**每一问都是一次失败换来的:**

- ① 来自 DOS 池:没有第二个场子,"在 0.05 买进"的终点是持有那个币
- ② 来自跨链套利:价差看得见,真去报价才发现 25 bps 服务费地板
- ③ 来自成本模型:带"待定"的总数会被当结论用 —— 我自己干过
- ④ 来自 SVR/Atlas:开放但已被占满的市场,和封闭市场结果一样
- ⑤ 来自我们自己的筛选器(见方法四)

## 方法四:筛选目标必须和使用目标一致

这是四周里最隐蔽的一个错误。

我给资金费 carry 写了个筛选器:

```
判据:不反号 + 两半比值 ≤ 1.8 倍 + |净年化| ≥ 3%
```

「两半比值小 = 这个价差很稳定」,听起来完全合理。24 个币筛出 3 个。

然后我去看**被淘汰的那批**:

```
                通过组      淘汰组
当前 |净| 中位   0.86%      15.47%      ← 淘汰组是通过组的 18 倍
```

**为什么必然如此:**

```
「两半比值 ≤ 1.8」= 这个价差【一直没怎么变】
一直没变的价差    = 一直是那个小数 → 现在也小,以后也小
而机会恰恰来自【变了】
```

> ### 🔑 我在用「不会出现机会」当筛选条件

**和前面几次错误的区别:**

```
14 天窗口年化      →  取样窗口太短    (取样错误,数据取错了)
42 天分布定阈值    →  取样窗口太长    (取样错误)
11 分钟外推        →  样本量太小      (取样错误)
两半比值筛稳定性   →  【目标错误】—— 数据和统计全对,筛的东西不对
```

**目标错误更隐蔽:筛选器工作得很好,只是在做一件没用的事。**

### 检验方法

**把被筛掉的那批也算一遍指标,和通过的比。**
如果淘汰组在你真正关心的维度上明显更好,**筛选器就是反的**。

**任何筛选器都要跑一次「淘汰组对照」。只看通过的那批,永远发现不了自己在反向选择。**

## 方法五:分清「假设」和「实测」,并且让它们长得不一样

```python
FEES = {"Binance": {"maker": 2.0, "taker": 5.0}}
```

**这行代码没有任何地方告诉你 5.0 是抄来的。它长得和实测值一模一样。**

一个月后你会忘记,然后拿它做决策。我们就是这么把一个照抄的
8 bps 用了四周,实际是 21 bps(加密)。

**改法:出处和数值分开存,四档可信度:**

```
✅✅ 账单 + 官方表     最高
✅   只有账单          事实,但可能有盲区
📖   只有官方费率表    规则,但不确定是否适用于你
⚠️   都没有,猜的      ← 出现这个就别拿去做决策
```

每次打印都带标记,`📖` 那行你就会先去补一笔账单再用。

### 推论:两种证据不能互相替代

```
账单实测   →  你【实际付了】多少,含账户等级/活动/折扣的真实结果
官方费率表  →  规则是什么,【包括你还没交易过的格子】
```

**只有账单会有盲区,只有费率表不知道是否真的适用于你。**

## 方法七:绕开你不知道的量,而不是去猜它

两个实例:

```
不知道 SKHYNIX 跟哪个市场的交易时段
  → 不去查日历,用【成交量的形状】定位开市时间

没有 BNB IDO 日历
  → 不需要。逻辑是:
     如果 IDO 造出了可交易异常 → 数据里必然存在异常时段
     如果数据里【任何时候】都没有异常 → IDO 没造出异常
  → 只要证明"异常从未发生过",不用知道事件何时发生
```

## 方法九:偏态分布下,取样窗口必须覆盖极端事件

否则你测的是"平时",**而平时恰恰不是这门生意**。

```
45 小时 × 37 个币,合计 +282.5 bps
去掉 COTI 一个币                  合计 +6.0 bps
                                  ↑ 一个币占 98%
```

**这门生意不是稳定收租,是等一个 COTI。**
而如果你的取样窗口刚好没盖到那次 COTI,你会得出"完全没机会"的结论。

# 第五部分:九个方向的最终账

```
❌ 判据当场砍掉   新币上线 / 费率变动 / 刷积分 / 砸盘拉盘
❌ 实测证伪       跨所永续 carry / 现货+永续 / 资金费逃票 / IDO 事件
⚠️ 闭环成立但拥挤  DEX-CEX 搬砖(唯一没实测的)
```

加上前期的:跨链稳定币套利、收费站 LP、清算、DOS 新池 —— **共 12 个方向**。

### 四次实测证伪,四个不同的死因

```
跨所永续    机会存在但【小到和噪音一个量级】,深度只有 $114 且秒级变化
现货+永续   好做的方向【被市场自己套没了】—— 正费率易套所以被套平,
            剩下的负费率要借币,而借币成本和资金费是同一失衡的两面
逃票        【结构不适用】—— 对冲仓两条腿一起逃等于白逃
IDO 事件    【异常压根不存在】—— 168 天零一次
```

**没有一个死于"竞争太激烈"。**
前期在清算线上撞的是竞争(SVR 回收 89.2%,Top1 占 84.6%);
后期撞的是**经济学本身**:能做的都被做掉了,剩下的都有做不了的理由。

### 真正的约束不是想法,是位置

```
本金  万级以上才够穿过深度和固定成本   ← 实际 $30
执行  程序化下单、低延迟              ← 实际网页手动点
信息  别人看不到的数据或通路           ← 实际全公开
```

**每次失败都是「机制对,位置不对」。而位置只有这三种改法。**
