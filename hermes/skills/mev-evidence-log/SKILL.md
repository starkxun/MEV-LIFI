# 证据记录表

把每个候选机会记一行。这张表是**把运气变成策略**的地方 ——
没有它,你只会记住赚钱的那几次,忘掉亏钱的那些。

文件:`~/MEV-LIFI/evidence.csv`

## Schema

| 字段 | 说明 | 谁来填 |
|---|---|---|
| 时间 | 发现时的区块高度 / 时间戳 | 探针自动 |
| 链 | 源链 → 目标链(或单链) | 探针自动 |
| 资产 | 涉及的 token | 探针自动 |
| 类型 | DEX间 / 三角 / 稳定币 / 清算 / 跨链 | 探针自动 |
| 规模 | 测试的本金规模 | 探针自动 |
| 路径 | 用了哪个桥 / DEX | 探针自动 |
| 屏幕价差 | 表面看到的价差(bps) | **人工观测填** |
| 真实成本 | token 口径总成本(bps) | 探针自动 |
| 净收益 | 屏幕价差 − 真实成本,**可能为负** | 算出来填 |
| 延迟 | 执行需要多久 | 探针自动 |
| 成败原因 | 为什么成 / 为什么没成 | **人工判断填** |
| 可复现? | 稳定机会还是一次性噪声 | **要有历史才能填** |

## 自动写入

```bash
python3 cost_probe.py --from-chain ARB --to-chain BAS --token USDC \
    --amounts 1000,10000 --csv evidence.csv
```

探针只填它**知道**的字段。「屏幕价差」「净收益」「成败原因」「可复现」四列
故意留空 —— 那些需要判断,不该由脚本猜。

## 填空时的纪律

**屏幕价差**:必须是独立观测到的、可成交的价差,不是 CoinGecko 之类的
聚合标价。填之前问一句:这个价差我真的能吃到吗?深度够吗?

**净收益**:直接减。**为负就如实记为负** —— 负结论是成果不是失败。
共学的核心结论之一就是"稳定币跨链搬砖不成立",那是靠一堆负数堆出来的。

**可复现?**:没有历史数据**不要填**。先跑
`python3 watch_probe.py ... --history` 看这条路的分布,
一次观测永远回答不了这个问题。

**成败原因**:写机制,不写结果。
- ✗ "没赚到钱"
- ✓ "25bps 桥费是固定费率,稳定币间不可能有 25bps 的可成交价差"
- ✓ "门槛只有 20bps,但 1080 秒延迟内价差早消失了"

## 汇报纪律

- 用户问"有什么机会"时,先读 `evidence.csv`,基于**已记录的证据**回答,
  不要凭印象。
- 统计时把负净收益的行也算进去。只看赚钱的行就是幸存者偏差。
- 一行证据 ≠ 一个策略。同一条路径要有多次观测、且结论一致,才谈得上 edge。
